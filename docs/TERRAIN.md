# 지형 · 지표 시스템 (Phase 12)

"보기 좋은 울퉁불퉁한 바닥"이 아니라 **시뮬레이션이 읽는 지형 데이터**입니다. 바람(이번 Phase), 지진·홍수·폭우(향후)가 같은 데이터를 씁니다.

## 1. 표현 방식: 정규 높이 그리드 (heightfield)

| 후보 | 판단 |
|---|---|
| **정규 높이 그리드 (선택)** | Rapier `heightfield` 충돌체가 같은 그리드를 그대로 받음 → 시각 메시 = 충돌체 = 샘플러 높이. O(1) 조회, 브러시 편집이 배열 쓰기, 홍수 계산(셀 단위 물 흐름)에 바로 재사용 가능 |
| 높이맵 텍스처 | GPU 표시에는 좋지만 시뮬레이션 코어가 텍스처/Three.js를 읽게 됨 (코어–렌더링 결합 금지 위반) |
| 복셀 / 블록 | 동굴·절벽은 표현되지만 경사면 물리와 바람 프로파일에 불필요하게 복잡, 저장 크기 큼 |
| 비정규 메시(TIN) | 해상도 효율은 좋지만 조회·편집·물리·홍수 모두 공간 인덱스가 필요 (과설계) |

- 200 m 월드 위 **1 m 간격, 201×201 정점**. 건물 기초(7–14 m)와 차량 크기의 경사를 표현할 수 있고, 메시 8만 삼각형·충돌체 생성 1.4 ms로 가볍습니다.
- 각 셀은 **(x1,z0)–(x0,z1) 대각선**으로 두 삼각형으로 나눕니다. Rapier heightfield의 분할과 같습니다(실측 후 맞춤). 그래서 샘플러 높이와 Rapier 표면의 차이가 1 mm 미만입니다(테스트 600점, float32 정밀도 수준).
- 높이는 **1 cm 단위로 양자화**(편집할 때마다)하므로 저장 → 불러오기 결과가 비트 단위로 같습니다.

## 2. 구조

```

terrain/
  TerrainData.ts        생성·양자화·사각형 패치(실행 취소 단위)
  TerrainSampler.ts     sampleHeight / sampleNormal / sampleSlope / sampleGroundType / sampleGround /
                        sampleWaterDepth / heightAboveGround / raycast  (할당 없음, 평지는 분기 1개)
  TerrainEditor.ts      브러시: raise · lower · flatten · smooth · paint (코사인 감쇠)
  TerrainPresets.ts     TerrainPresetGenerator: flat · gentleHills · valley · coastal (시드 PRNG)
  GroundMaterials.ts    GroundMaterialRegistry: 잔디·흙·모래·아스팔트·콘크리트
  TerrainPhysicsAdapter.ts  TerrainData → 엔진 중립 TerrainColliderDesc
  groundPlacement.ts    카테고리별 지면 배치 규칙 (높이·기울기)
  terrainCodec.ts       압축 저장 형식
  terrainStats.ts       HUD용 비용 카운터
physics/RapierEngine.ts setTerrain(): 평지 = 기존 슬래브, 지형 = heightfield + 바깥 y=0 슬래브 4개
rendering/terrain/      TerrainRenderer: TerrainSurface(메시·스커트·외곽선·셰이더 등고선/격자), TerrainLayer(R3F), 도로 드레이프
```

- 시뮬레이션 코어(`simulation/`, `terrain/`)는 Three.js 메시를 조회하지 않습니다. 렌더러와 물리는 같은 `TerrainData`에서 각각 만들어집니다.
- `EnvironmentState.terrain`이 모든 시스템에 같은 샘플러를 줍니다.

## 3. 데이터 모델

| 필드 | 내용 |
|---|---|
| `nx, nz, cellSize, originX, originZ` | 그리드 정의 (기본 201×201, 1 m, 원점 −100 m) |
| `heights` | 정점별 고도 (m, 1 cm 양자화, −40 … 80 m) |
| `ground` | 정점별 지표 종류 id |
| `settings.preset / seed` | 마지막으로 생성한 프리셋과 시드 |
| `settings.waterLevel` | 정적 기준 수면 (해안 프리셋 = 0 m). `sampleWaterDepth`의 기준 |
| `revision` | 제자리 편집 시 증가 (저장 안 함) |

경사·법선은 저장하지 않고 높이에서 계산합니다. 향후 층(토양 강도, 투수성 지도, 함수율, 지진 증폭계수, 침식)은 `ground` 옆에 정점별 typed array로 추가하고, 코덱에 항목을 하나씩 더합니다.

## 4. 지표 종류 (GroundMaterialRegistry)

| 지표 | 마찰 | 거칠기 | 투수성 |
|---|---|---|---|
| 잔디 (기본) | 0.55 | 0.35 | 0.60 |
| 흙 | 0.60 | 0.30 | 0.45 |
| 모래 | 0.50 | 0.20 | 0.85 |
| 아스팔트 | 0.70 | 0.10 | 0.05 |
| 콘크리트 | 0.65 | 0.08 | 0.02 |

**모든 값은 상대적 거동을 위한 근사 시뮬레이션 파라미터**이며 측정된 물성값이 아닙니다. UI에도 그렇게 표시합니다.
- 이번 Phase에서 물리에 쓰는 값은 마찰뿐입니다. 자유 물체(차량·사람)는 **시뮬레이션 시작 시 놓인 지표의** `마찰 / 잔디 마찰`을 자기 마찰에 곱합니다(잔디 = 정확히 ×1 → 기존 결과 불변). 거칠기·투수성은 향후 바람 거칠기 길이, 강우 침투에 쓸 자리입니다.
- **도로는 별도 인프라 오브젝트로 유지**했습니다. 차선 수·표시·길이 파라미터와 기존 저장 파일이 있고, 피해·선택·인스펙터 흐름이 오브젝트 단위이기 때문입니다. 지형 위에서는 노면과 차선을 지형에 덮어 그립니다(렌더링 전용). 지표를 "아스팔트"로 칠하는 것은 마찰·향후 배수용 지표 속성이고, 도로 오브젝트와 겹쳐도 충돌하지 않습니다.

## 5. 편집기

- 왼쪽 **지형** 탭 = 지형 편집 모드. 도구: 올리기·내리기·평탄화(획 시작점 높이로)·다듬기(3×3 평균, 순서 무관)·지표 칠하기·지점 정보.
- 브러시 크기 1–40 m(`[` `]`, Shift = 5 m), 세기 5–100 %, 코사인 감쇠. 마우스를 누르고 있는 동안 매 프레임 dab(dt 상한 1/20 s).
- **한 획 = 실행 취소 1단계**. 기록에는 획이 건드린 사각형의 전/후 값만 저장합니다. 지면 위에 서 있던 오브젝트는 같은 단계 안에서 새 지면으로 옮겨지고, 실행 취소하면 함께 돌아옵니다. 일부러 띄운 오브젝트는 그대로 둡니다.
- 프리셋 적용과 기준 수면 변경도 실행 취소할 수 있습니다.
- 표시: 지표(지표 색 + 경사 음영), 고도(고도 색 + 1 m/5 m 등고선), 지표 종류(단색 지도). 편집 모드에서는 셰이더로 1 m/10 m 격자를 그립니다.

## 6. 오브젝트 배치 규칙 (`ObjectDefinition.terrainFit`)

| 카테고리 | 기울기 | 기준 높이 |
|---|---|---|
| 건물, 담장, 가로등, 표지판 | 수평 유지 | 바닥 네 모서리·중심 중 **가장 낮은 곳** (뜨는 모서리 없음, 오르막 쪽은 기초처럼 묻힘) |
| 사람 | 수평 유지 | 중심 지면 |
| 나무 | 지면 경사의 30 % | 줄기 위치 지면 |
| 차량 | 네 바퀴 평면에 맞춤 | 네 모서리 평균 |
| 도로 | 수평 (렌더링은 드레이프) | 중심 |

- 기울여도 **진행 방향(yaw)은 정확히 유지**됩니다. 지형을 여러 번 편집해 다시 앉혀도 회전이 누적되지 않습니다.
- 기즈모: 지면에 있던 오브젝트를 수평 이동·회전하면 지면을 따라가고, Y 핸들로는 띄울 수 있습니다. 지면 아래로는 내려가지 않습니다. 평지에서는 기존 동작 그대로입니다.

## 7. 물리

- 평지(모든 높이 0) → 기존과 같은 무한 슬래브를 **같은 순서로** 생성합니다. 그래서 Phase 11 골든 결과가 비트 단위로 그대로입니다.
- 지형 → Rapier `heightfield`(FIX_INTERNAL_EDGES) + 월드 밖 y = 0 슬래브 4개. 렌더링의 가장자리 벽(스커트)과 일치합니다.
- **갱신 전략**: 물리 월드는 시뮬레이션 모드에서만 존재하고, 그동안 지형은 고정입니다. 그래서 충돌체는 로드·초기화할 때 스냅샷에서 한 번 만들고(1.4 ms), 편집 중 dab은 데이터와 렌더 메시만 바꿉니다. `PhysicsEngine.setTerrain()`은 한 번 호출로 충돌체를 교체합니다(향후 침식·산사태용, 테스트 있음).
- **경사면 휴면**: 강체 박스(차체)가 비평면 삼각형 위에 있으면 수 mm 크기의 접촉 진동이 생기고, Rapier 휴면 임계값을 넘어 영원히 깨어 있습니다(언덕 1000개 장면에서 물리 3.0 ms → 무풍 정지 상태). `PoseSyncSystem`은 지형이 있을 때만, 바람 하중이 없고 0.5 s 동안 3 cm 이상 움직이지 않은 몸체를 재웁니다. 상태만 보고 정하므로 결정론적이고, 바람 힘이나 접촉이 생기면 다시 깨어납니다. 적용 후 물리는 3.0 → 0.31 ms였습니다.

## 8. 바람

- `WindField.speedAt`: 높이 프로파일을 **지면 기준 높이** `y − terrainHeight(x,z)`로 계산합니다(언덕 위 10 m와 평지 10 m의 풍속이 같다는 테스트 있음).
- 건물 wake: `WindObstacle.baseY`(건물 바닥 높이)를 기준으로 높이를 잽니다. 언덕 위 건물의 그림자는 그 건물 높이에 생깁니다.
- 건물 외피 요소의 설계 풍속 보정도 지면 기준 높이를 씁니다. 판형 파편 양력, 입자 착지, 화살표·스트릭 시각화도 지면 기준입니다.
- 지형에 의한 가속·차폐는 구현하지 않았고, `TerrainWindModifier`(지점·지면 기준 높이 → 배율) 확장점만 있습니다.

## 9. 저장 형식 (스키마 v2)

```json
"terrain": {
  "kind": "heightfield", "nx": 201, "nz": 201, "cellSize": 1, "originX": -100, "originZ": -100,
  "elevation": { "encoding": "cm-delta-rle", "data": "<base64>" },   // 평지면 null
  "ground":    { "encoding": "u8-rle", "data": "<base64>" },         // 기본 지표뿐이면 null
  "settings":  { "preset": "gentleHills", "seed": 1, "waterLevel": null }
}
```

- 고도: cm 정수 → 행 방향 델타 → zigzag varint + 같은 델타 반복 길이(run-length). 지표: (값, 길이) 반복.
- 크기: 평지 0.17 KB, 계곡 64 KB, 완만한 언덕 81 KB (원시 float32라면 157 KB + 지표 39 KB).
- **기존 프로젝트 이전**: 스키마 v1(`terrain: {kind:'flat'}`) 또는 terrain이 없는 파일 → 0 m 평지로 불러오고, 오브젝트 위치는 그대로입니다. 저장하면 v2로 기록됩니다.
- 자동 저장도 같은 직렬화를 거칩니다(이전에는 `JSON.stringify(doc)` 직접 호출이어서 typed array를 담을 수 없었음).

## 11. 결정론

- 프리셋은 `Rng`(시드 PRNG)만 씁니다. `Math.random`을 호출하면 실패하는 테스트가 있습니다. 같은 프리셋 + 시드 → 같은 높이(비트 단위).
- 같은 지형 + 월드 + 이벤트 + 시드 → 같은 피해 순서와 최종 포즈(Rapier 포함 테스트). 다른 지형 → 다른 결과.
- 평지: Phase 11 골든 3개 시나리오가 **비트 단위로 일치**합니다.

## 12. 향후 재난과의 연결

- **지진 (Phase 13)**: `Earthquake Event → Ground Motion → Terrain/Ground Properties → Object Foundation → Structural Damage`. 지면 성질은 `sampleGround()`(정점별 지표 → 재질)로 이미 조회할 수 있으므로, `GroundMaterial`에 `soilStrength`, `seismicAmplification`을 추가하면 됩니다. 기초 위치는 `groundPlacement`가 정한 바닥 높이·기울기입니다.
- **홍수**: 수원 → 지형 고도 → 저지대 → 확산 → 수심. 홍수 시스템은 `TerrainData.heights`(정규 그리드)를 셀 격자로 그대로 쓰면 되고, `settings.waterLevel`, `sampleWaterDepth()`가 출발점입니다. 수심 층은 정점별 배열로 추가합니다.

## 13. 알려진 제한사항

- 해상도 1 m 고정(문서에는 cellSize가 있지만 UI에서 바꿀 수 없음). 월드 밖은 y = 0 평면이고, 가장자리는 디오라마형 벽입니다.
- 지형에 의한 바람 가속·차폐·배수 없음. 거칠기·투수성은 아직 시뮬레이션에 쓰이지 않습니다.
- 지표 마찰은 시작 위치 기준입니다(미끄러져 다른 지표로 가도 바뀌지 않음). 기준 수면은 정적 표시입니다(부력·흐름 없음).
- 경사면 건물은 수평 상자로, 오르막 쪽이 지면에 묻힙니다(옹벽·기초 모델 없음). 도로 드레이프는 렌더링만 합니다(도로는 충돌체가 없음).
- 강풍 속 언덕 장면은 물리 비용이 평지의 약 3배입니다.
- Rapier 레이 질의는 정점을 정확히 지나는 수직 광선을 놓칠 수 있습니다. 편집기는 자체 `TerrainSampler.raycast`를 쓰므로 영향이 없습니다.
