# Phase 16 — Creative World Builder & Advanced Editing

월드 제작을 Minecraft Creative Mode처럼 빠르게 하되, 결과물은 기존 3D 스타일·물리·재난 시뮬레이션 구조를 그대로 쓰는 것이 목표입니다.
모든 기능은 GUI/마우스로 사용할 수 있고, 자연어 명령은 바뀌지 않았습니다(선택 기능).

## 1. 기존 에디터 분석과 충돌 검토

| 기존 시스템 | 상태 (Phase 15) | Phase 16 처리 |
|---|---|---|
| World Editor (`editor/EditorScene.tsx`) | 오브젝트마다 React 컴포넌트 1개 + 파츠별 메시 → 1000개 ≈ 1,800 draw call, `useFrame` 224개 | **Phase 11 `SimRenderAdapter`를 편집 모드에 재사용**(청크 단위 배치). 선택된 단일 오브젝트와 도로만 React 뷰로 남김 |
| 배치 (`PlaceTool`) | 단일 클릭, 그리드 스냅(자동 0.5/1 m), R 90° | 유지 + 그리드 간격·지형 표면 스냅·겹침/경사 경고 추가 |
| 선택 / 기즈모 | `selectedId` 하나, drei `TransformControls` | `selectedIds` 추가, **`selectedId`는 "주 선택"으로 유지**(인스펙터·포커스·기즈모·시뮬레이션 화면 모두 기존 그대로). 단일 선택 경로 무변경 |
| Undo / Redo (`worldStore`) | 오브젝트 맵 스냅샷(불변) + 지형 패치, 100단계 | 그대로 재사용. 새 `applyEdit()`가 대량 편집을 **한 번의 commit = 한 단계**로 기록 |
| 지형 편집 (`TerrainTool`) | 지형 모드에서 좌클릭 드래그 | 도구 상태 `tool`이 하나뿐이라 지형 도구와 제작 도구가 동시에 입력을 받지 않음(기존 구조 확장) |
| Object Registry / Palette | 8종 정의, 16개 프리셋 | 그대로 재사용. 팔레트는 정의·편집 뷰가 있는 프리셋만 표시(`disabled` 제외) |
| 지형 배치 규칙 (`groundPlacement`) | 종류별 `terrainFit` | 그대로 재사용, `groundPose(…, align?)`에 선택적 기울기 재정의만 추가 |
| Save / Load v5 | zod 검증 + v1–v4 마이그레이션 | **스키마 버전 유지(5)**. 오브젝트에 선택 필드 `group` 추가 |
| 시뮬레이션 격리 | `SimulationController.load()`가 문서를 `structuredClone`, Reset은 스냅샷 재구성, 편집 모드 복귀 = 런타임 폐기 | **중복 시스템을 만들지 않고 그대로 사용**. 시뮬레이션 중 월드 잠금 + 원본 지문 표시 + 테스트로 보장 |
| 실험 비교 (`runComparison`) | 같은 문서 스냅샷으로 헤드리스 실행 | 변경 없음 |
| 단축키 | W/E/R, F, G, Ctrl+Z/Y/D, Delete, Esc, Space, [ ], Shift+P | 충돌 없는 키만 추가 (§10) |

충돌 위험과 해결:
* **Shift+좌드래그**는 OrbitControls에서 카메라 이동(pan)이었습니다 → 선택 도구에서만 영역 선택으로 바꾸고, 카메라 이동은 우클릭 드래그(기존 안내)로 계속 가능합니다.
* **배치 렌더링 교체**는 선택·기즈모가 씬 노드(`entity:<id>`)를 찾던 구조와 충돌합니다 → 선택된 오브젝트는 배치에서 숨기고 React 뷰로 그려 기즈모 경로를 바꾸지 않았습니다.
* **그룹 = 물리 바디 결합?** → 아닙니다. 그룹은 오브젝트의 `group` 문자열일 뿐이며, 런타임 빌더는 이를 읽지 않습니다(각자 독립 바디).

## 2. Creative Build Mode — 도구

뷰포트 왼쪽 위 **제작 도구 막대**(편집 모드에서만 표시, 재난 설정은 하단 패널):

| 도구 | 키 | 동작 |
|---|---|---|
| 선택 | V | 클릭 / Shift+클릭(추가·제외) / Shift+드래그(영역) / Alt+클릭(그룹 안의 하나) |
| 배치 | P | 클릭마다 1개 (기존 동작 + 경고) |
| 브러시 | B | 좌클릭 드래그로 칠하기, 놓으면 한 번에 커밋 |
| 선형 배치 | L | 점 클릭 → 마지막 점 재클릭/Enter로 배치, Backspace 점 삭제 |
| 영역 채우기 | A | 사각형/원 드래그 또는 브러시로 칠한 영역 → 미리보기 → Enter/배치하기 |
| 붙여넣기 | Ctrl+V | 클립보드 고스트가 커서를 따라옴, 클릭마다 복사본, R 90° |
| 이동/회전/크기 | W/E/R | 기존 기즈모. 다중 선택은 그룹 기즈모(이동·Y 회전) |
| 복사/복제/삭제 | Ctrl+C / Ctrl+D / Delete | 다중 선택 지원 |

한 번에 한 도구만 뷰포트 입력을 가집니다(`editorStore.tool`). 도구를 바꾸면 이전 도구의 세션(선 점, 영역)이 끝납니다.
**시뮬레이션 중**: 제작 도구 막대가 사라지고, 팔레트는 "시뮬레이션 중에는 편집할 수 없습니다" 안내, `worldStore.locked = true`라 어떤 경로(단축키·콘솔·명령)로도 오브젝트/지형이 바뀌지 않습니다.

## 3. Object Palette

* 카테고리 필터 칩(전체·★즐겨찾기·건물·자연·차량·사람·인프라·환경), **검색**(한국어·영어 이름·종류 id 모두 검색: "나무", "tree", "conifer")
* **미리보기**: 프리셋마다 실제 파츠 빌더로 렌더한 썸네일(오프스크린 렌더러 1개로 한 번 생성 후 해제 — WebGL 컨텍스트를 상주시키지 않음)
* **최근 사용**(최대 8개), **즐겨찾기**(★) — 브라우저에 저장(사용자별, 월드 파일에는 저장하지 않음)
* 선택한 프리셋 카드: 미리보기, 크기(W×D×H), 배치 방식 전환 버튼(배치/브러시/선형/영역)
* 실제 지원하지 않는 오브젝트는 표시하지 않음: `PLACEABLE = PALETTE.filter(!disabled && hasDefinition && STATIC_VIEWS)`

## 4. 브러시 및 영역 배치

모든 분포는 `editor/build/distribution.ts`의 순수 함수입니다(`Math.random` 없음).

* **브러시** (`BrushScatter`): 경로를 고정 호 길이(반경의 ½)마다 스탬프로 재표본화 → 각 스탬프는 **이전 스탬프가 덮지 않은 원 영역에만** 점을 추가 → 브러시를 천천히 움직여도 밀도가 일정. 하나의 시드 스트림을 스탬프 순서대로 소비하므로 **같은 시드 + 같은 입력 경로 → 같은 점**(포인터 이동마다 증분 계산한 결과 = 경로 전체를 한 번에 계산한 결과, 테스트로 검증).
  옵션: 반경, 밀도(개/100 m²), 최소 간격, 무작위 회전(+회전 스냅), 무작위 크기(0.5–2 범위로 고정), 시드(🎲 새 시드), 지형 정렬(종류별/수직 유지/경사면 따라), 경사 한계, 겹침 방지.
* **영역 채우기**: 사각형·원·브러시로 칠한 영역(원판 합집합). 격자(간격·흔들림) 또는 무작위(밀도·최소 간격). 무작위는 경계 사각형 전체에 밀도대로 투척 후 영역 판정 → 어떤 모양이든 영역 안 밀도가 요청값. 확정 전 **미리보기**(배치될 것 파랑, 경고 주황, 제외 빨강 + "N개 배치 · M개 제외") — 옵션을 바꾸면 즉시 다시 계산.
* **배치 계획** (`placementPlan.ts`): 점마다 독립 시드 스트림(`subSeed(seed, 'obj', index)`)으로 변화(params)·방향·크기·오브젝트 시드 결정 → 기존 `groundPose`로 지형에 앉힘 → 월드 경계·경사 한계·발자국 겹침(기존 오브젝트 + 같은 작업에서 먼저 놓인 것) 검사.
* **충돌 검사** (`footprint.ts`): 방향 있는 직사각형 발자국 SAT 판정 + 격자 공간 색인. 나무는 수관이 맞물릴 수 있게 수관의 45%만, 도로(지면 레이어)는 충돌 없음(위에 올려놓는 대상).

## 5. 선형 배치

`lineLayout(path, {spacing, orient, yaw, offset, bothSides})`: 꺾은선을 따라 `spacing`마다(꼭짓점을 넘어 연속), 끝점은 마지막 점에서 반 간격 이상 남을 때 추가. 방향: 경로 방향(오브젝트 +x가 진행 방향) / 경로에 수직 / 고정(R·T로 회전). 옆으로 띄우기(+ = 진행 방향 오른쪽)와 양쪽 배치(가로등 두 줄).
가로등·담장·나무 줄·차량 행렬에 사용. 도로 네트워크 편집은 Phase 18 범위로 남겼습니다.

## 6. 다중 선택 및 그룹 편집

* `editorStore.selectedIds` + `selectedId`(주 선택 = 마지막 클릭). 단일 선택일 때 화면·인스펙터·기즈모는 Phase 15와 동일.
* Shift+클릭 추가/제외, **Shift+드래그 영역 선택**(화면 사각형 안에 중심이 투영되는 오브젝트), **종류별 전체 선택**(장면 탭의 칩), 전체 선택(Ctrl+A), 선택 해제(Esc / 빈 땅 클릭).
* 시각 표시: 선택된 모든 오브젝트의 경계 상자를 **하나의 선분 지오메트리**로(오브젝트 수와 무관하게 draw call 1).
* **그룹 편집** (`GroupSelection`): 선택된 오브젝트를 피벗(경계 중심) 아래 하나의 배치 그룹으로 그리고, 기즈모가 피벗을 이동/회전 → 놓는 순간 강체 변환을 모든 오브젝트에 적용(상대 위치 유지, 지면에 서 있던 오브젝트는 새 위치의 지형에 다시 앉힘) — **한 번의 Undo 단계**. 드래그 중에는 문서를 바꾸지 않으므로 배치 재구성이 없습니다.
* 인스펙터: 구성(종류별 개수), 그룹/그룹 해제, 정렬(X/Z 최소·가운데·최대), 균등 배분, 90° 회전, 복사·복제·삭제·포커스.
* 그룹 = `WorldObject.group`(문자열). 클릭하면 그룹 전체가 선택되고 Alt+클릭은 하나만. **물리 바디는 합치지 않음**.

## 7. 복사·붙여넣기 / Blueprint 기반

`editor/build/blueprint.ts` — `{ format: 'disaster-sim/blueprint', version: 1, name, size, objects[] }`:
각 오브젝트는 type, name, seed, params(구조·재질·크기), physics, seismic, 앵커(경계 중심) 기준 상대 위치, 지면 위 높이(떠 있던 오브젝트만), 회전, 크기, 지면 여부, 로컬 그룹 키를 가집니다. **id는 저장하지 않으며** 붙여넣을 때마다 새 id와 새 그룹 id를 만듭니다. zod 검증 `parseBlueprint()`(알 수 없는 종류는 제외)까지 있어 Phase 20에서 파일 저장/라이브러리로 확장할 수 있습니다.
붙여넣기는 고스트 미리보기 → 클릭(반복 가능), R/T 회전. Ctrl+D 복제는 +2 m 위치에 즉시 복사(단일 오브젝트는 기존 동작 그대로).

## 9. Undo / Redo

* 새 `worldStore.applyEdit({ add, update, remove })`: 다음 오브젝트 맵을 **완성한 뒤에만** commit → 한 번의 Undo 단계. 생성 도중 예외(알 수 없는 종류 등)가 나면 아무것도 바뀌지 않습니다(테스트: 문서 객체 동일성 + history 길이 불변).
* 한 단계로 되돌려지는 작업: 브러시 획(나무 100개 → Undo 1회), 선형 배치, 영역 채우기, 다중 이동, 그룹 회전, 정렬, 복제, 삭제, 붙여넣기, 그룹/그룹 해제.
* Redo는 저장된 객체 맵을 그대로 복원하므로 동일한 결과(같은 id, 같은 값)입니다.
* 일련번호(serial) 계산을 작업당 1회로 바꿔 대량 추가가 O(n²)가 되지 않게 했습니다.

입력 필드에 입력 중일 때는 모든 단축키가 비활성(기존 규칙).

## 11. 원본 월드와 실험 격리

기존 구조를 조사한 결과 격리는 이미 **스냅샷 방식**이었습니다: `enterSimulation` → `SimulationController.load(doc)`가 `structuredClone`, Reset = 같은 스냅샷 + 같은 이벤트 목록으로 재구성, 편집 모드 복귀 = 런타임 폐기. 중복 시스템을 만들지 않고 다음을 추가했습니다.

1. **시뮬레이션 중 월드 잠금** — `worldStore.locked`: 오브젝트·지형 편집, Undo/Redo, 문서 교체가 거부됩니다(설정·실험 계획 편집은 기존처럼 허용).
2. **원본 지문** — `worldFingerprint(doc)`(저장 시각 제외 전체 내용 해시). 시뮬레이션 모드 배지 "✓ 원본 월드 보존"에 지문과 오브젝트 수 표시.
3. **테스트로 보장**: 지진으로 도시를 무너뜨려도 문서가 바이트 단위로 같고, 이어서 실행한 태풍 결과 = 저장 파일을 다시 불러와 실행한 태풍 결과(해시 동일). Reset 후 모든 엔티티가 초기 자세·정상 상태, 같은 피해 순서를 재현.

예시 흐름(도시 제작 → 저장 → 지진 → 붕괴 → 종료 → 원본 → 태풍)은 그대로 동작합니다. 저장은 시뮬레이션 중에 눌러도 항상 원본(문서)을 저장합니다.

## 12. Save / Load

* **스키마 버전 5 유지**. 오브젝트의 선택 필드 `group`만 추가(잘못된 값은 버림). Phase 15 앱도 이 파일을 읽을 수 있습니다(모르는 필드는 무시 → 그룹만 사라짐).

## 15. 알려진 제한

* 다중 선택은 이동·Y축 회전만(크기 조절은 개별 선택). 그룹 드래그 중 미리보기는 강체로 움직이고, 지형 재착지는 놓을 때 적용됩니다.
* "경사면 따라" 정렬로 놓은 오브젝트도 이후 지형 편집·이동 시에는 종류별 기본 규칙으로 다시 앉혀집니다(정렬 방식을 오브젝트에 저장하지 않음).
* 영역 선택은 오브젝트 중심 투영 기준(경계 상자 일부만 걸친 오브젝트는 제외).
* 붙여넣기 클립보드는 탭 메모리에만 있습니다(새로고침 시 사라짐, 시스템 클립보드 연동 없음). Blueprint 파일 저장·라이브러리는 Phase 20.
* 지형 붓질을 끝낼 때마다 지형 객체가 바뀌어 편집 배치 전체를 다시 만듭니다(2000개 ≈ 8청크 × 17 ms).
* 선택 변경 시 힙이 조금씩 증가(사이클당 ~0.45 MB, Phase 15에도 존재) — 기즈모(drei `TransformControls`) 경로로 추정, 미해결.
* 무작위 크기는 Transform scale(0.5–2)로 적용합니다. 파라미터(층수 등) 자체를 바꾸는 변형은 정의의 `randomizeParams`(자연스러운 변화)만 사용합니다.
* 영역 무작위 채우기·브러시는 결정론적이지만, 입력 경로가 달라지면(같은 선이라도 포인터 샘플링이 다르면) 스탬프 위치가 미세하게 달라질 수 있습니다 — "같은 시드 + 같은 입력 경로"에서만 동일합니다.

## 16. Phase 17 (건물 제작 시스템)과의 연결

* 배치 계획(`planPlacement`)은 `type + params`만 알면 되므로, Phase 17의 건물 구성요소(층·벽·기둥 프리셋)도 같은 브러시/선형/영역/붙여넣기로 배치됩니다.
* `placementCheck`의 gap/bury와 건물 `foundation` 규칙이 Phase 17 기초 모델의 입력 지점입니다(현재는 플린스 표시만).
* Blueprint는 params·seismic(구조·기초)을 그대로 보존하므로, Phase 17에서 만든 건물을 복사·붙여넣기하고 Phase 20에서 라이브러리로 저장할 수 있습니다.
* 그룹은 "여러 파트로 된 건물"을 편집 단위로 묶는 데 그대로 쓸 수 있고, 물리적 결합 여부는 Phase 17에서 별도 모델(접합부)로 결정합니다.
