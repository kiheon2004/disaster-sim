# Phase 20 — World Blueprint, Template Library & Reusable Scenes

월드의 일부(건물·도로·자연환경·지형)를 **설계도(Blueprint)** 로 저장하고, 라이브러리에서 골라, 다른 곳·다른 월드에 미리보기로 놓고, 크기는 그대로 두되 방향·높이·지형 연결·도로 연결 정책을 정해 **한 번의 편집(실행 취소 1단계)** 으로 배치합니다. 월드 전체는 **월드 템플릿**으로 저장해 새 월드의 출발점으로 쓰며, **새 월드 만들기 마법사**가 템플릿·시드·미리보기를 거쳐 바로 빌드 모드로 들어가게 합니다. 모든 기능은 GUI와 마우스로 쓸 수 있고 자연어 명령은 필요 없습니다. 월드 저장 형식은 **스키마 v7 그대로**입니다(지형지물의 선택 필드 `frame` 하나만 추가).

## 1. 기존 Blueprint 구조 분석 (작업 전)

| 시스템 | 직렬화 방식 | 참조 관계 | 설계도와의 관계 |
|---|---|---|---|
| Phase 16 복사/붙여넣기 (`editor/build/blueprint.ts`) | `disaster-sim/blueprint` v1: 오브젝트 배열(앵커 상대 x/z, 지면 위 높이, 회전·크기, params·physics·seismic, 그룹 키) | id 없음, 그룹은 로컬 키 → 붙일 때 새 그룹 id | 클립보드 전용, 지형 없음 |
| Phase 17 모듈형 건물 | 오브젝트 `building` = 불변 설계값(부재·재료·연결·기초·외관·구조 사양). 월드 파일은 2회 이상 쓰인 설계를 `designs` 표에 한 번만 저장 | 부재 id는 건물 내부 로컬 → 복사해도 유효 | v1 클립보드는 설계를 오브젝트마다 인라인 저장(공유 손실) |
| Phase 18 도로 (`roads/blueprintRoads.ts`) | 노드·구간을 **인덱스**로 저장, 고정 높이는 앵커 지면 기준. 붙이기 = 연결(`drawRoad`) / 분리(`insertSubnetwork`) | 오브젝트 `roadLink.segment` → 설계도 구간 **인덱스** | 블록 용도(zone) 미포함, 잘린 끝 정보 없음 |
| Phase 19 자연 지역 (`landscape/region.ts`) | `disaster-sim/nature-region` v1: 사각형 안 지형지물(중심 상대, 로컬 id r<k>) + 조각·칠 격자 | 지형지물 id만 | 기준 높이 없음(호수 수면이 절대값), 회전 불가, 산 거칠기 노이즈가 월드 좌표에 고정(옮기면 모양이 바뀜) |
| 월드 문서 v7 | 지형 레이어(기본·조각·칠·지형지물) → 자연 지형 → 도로 굽기 → 최종 지형 | 오브젝트 id(무작위), 도로 n/s id·지형지물 f id(문서 카운터) | — |
| 실행 취소 | `WorldEdit` = 오브젝트 맵 + 지형 패치 + 레이어 패치 + 도로망(불변) | — | 여러 시스템을 묶어 한 단계로 되돌리는 기반이 이미 있음 |

정리하면 세 개의 “설계도”가 따로 있었고, **(1) 공통 로컬 좌표·기준 높이가 없고 (2) 참조가 인덱스/전역 id로 섞여 있으며 (3) 회전 시 지형(격자·노이즈)이 따라 돌지 않고 (4) 잘린 도로·강 같은 경계 정보와 의존성이 기록되지 않았습니다.** 기존 구현은 버리지 않고: v1·nature-region 파일은 v2로 **이전(migration)** 되고, 도로 붙이기(`pasteRoads`)·자연 지역 직렬화·설계 공유·`WorldEdit` 원자성은 그대로 재사용합니다.

## 2. Unified Blueprint Data Model (`disaster-sim/blueprint` v2)

```
{
  format: 'disaster-sim/blueprint', version: 2, minReaderVersion: 2,
  id: 'bp_…'                                   라이브러리 id (월드 id가 아님)
  meta: { name, description, category, tags[], author?, createdAt, updatedAt }
  origin: { datum, seaLevel }                  원본의 기준 높이(절대), 원본 해수면
  area: [[u,v]…]                               선택 영역(로컬)
  objects:    [{ id:'o<k>', type, name, seed, params?, physics?(사용자 변경분만), seismic?,
                 offset:[u, 지면 위 높이, v], rotation, scale, grounded, base, group?:'g<k>',
                 design?:'d<k>', terrainAlign? }]
  vegetation: [{ id:'v<k>', … }]               나무(같은 형식, 따로 켜고 끔)
  designs:    { 'd<k>': BuildingDesign }        모듈형 건물 설계 표(같은 설계는 한 번)
  roads: { nodes:[{id:'n<k>', x, z, y(기준 높이 상대)|null}],
           segments:[{id:'s<k>', a, b, control, profile, condition?}],
           zones:[{segments:['s<k>'…], zone}] }
  attachments: [{ object:'o<k>', segment:'s<k>', t, lateral, yaw, policy }]
  features:   [Feature (id 'r<k>', 로컬 좌표, 호수 수면 = 기준 높이 상대, frame?)]
  terrain: { grid:{x0,z0,nx,nz,cell}, surface, sculpt, paint, ground, soil, mask } | null
  dependencies: [{ kind, refs:[로컬 id], resolution, value? }]
  preview: { size, bounds, relief, counts, thumbnail }
  (unsupported: 알 수 없는 미래 데이터 — §17)
}
```

- **로컬 좌표**: 원점 = 앵커(선택 영역 중심, 지형 정점에 맞춤), 축 = 원본 월드 축. 배치는 `world = T + R(yaw)·local`, `R(θ)(u,v) = (u·cosθ + v·sinθ, −u·sinθ + v·cosθ)` — Phase 16·18 붙여넣기와 같은 회전이라 오브젝트·도로 노드/제어점·지형지물 점·노이즈 프레임·지형 격자가 함께 돕니다.
- **기준 높이(datum)**: 선택 영역 **경계를 따라 잰 사전-지형지물 지면(기본 + 조각)의 평균**. 중심점이 아니라 경계 평균인 이유: 언덕 꼭대기를 중심으로 잡은 설계도를 “지형 적용”으로 놓으면 언덕이 구덩이가 되는 문제(테스트에서 실제로 확인)가 생기기 때문입니다 — 주변과 만나는 높이가 기준이어야 언덕은 언덕, 골은 골로 남습니다.
- **높이 기준점 정리** (§7과 같음): 오브젝트 = 바로 아래 지면 위 높이(지면에 선 것은 0, `grounded`), 도로 고정 높이·호수 수면·지형 격자(`surface`) = 기준 높이 상대, `base` = 원본에서 기준 높이 상대 원점 높이(강체 배치·미리보기용).
- **물리 값 저장**: 정의/설계에서 나오는 기본값과 다른 값만 저장(사용자가 바꾼 질량·마찰 등). 모듈형 건물은 설계에서 파생되므로 `params`를 저장하지 않습니다.
- **동적 상태 없음**: 수심·유속·손상·시뮬레이션 상태는 형식에 자리가 없습니다(테스트로 확인). 강·호수의 **초기 물 설정**(채움 비율·유입량·채움 여부)은 지형 형상과 따로 켜고 끕니다.

### 기존 Blueprint 호환
| 입력 | 처리 |
|---|---|
| v1 (Phase 16–18 클립보드) | 오브젝트 → o/v 로컬 id, 인라인 설계 → 내용 기준 중복 제거해 `designs` 표, 인덱스 도로 → n/s id, `roadLink.segment` 인덱스 → 부착(attachment). 노드가 없는 구간은 v1처럼 버리되 **보고** |
| nature-region v1 (Phase 19) | 지형지물 → r id, 조각·칠 격자 유지. 원본에 기준 높이·지면 형상이 없으므로 `datum = 0`, `surface = null` → “지형 적용/혼합”은 쓸 수 없고 “기복 더하기”로 배치(경고 `noSurface`) |
| 앱 내 복사/붙여넣기 | 기존 v1 경로 그대로 유지(Ctrl+C/V는 Phase 16–18 동작) |

## 3. 로컬 좌표 및 ID 정책

- 설계도 안의 모든 id는 **로컬**이고 이름공간이 나뉩니다: `o` 오브젝트, `v` 식생, `d` 설계, `n` 도로 노드, `s` 도로 구간, `r` 지형지물, `g` 편집 그룹. 이 값은 월드에 절대 들어가지 않습니다(테스트).
- 배치할 때마다: 오브젝트 id = `createId`(새 무작위), 그룹 = 새 그룹 id, 도로 n/s id·지형지물 f id = **대상 문서의 카운터**. 같은 설계도를 여러 번, 어떤 월드에 붙여도 충돌이 없습니다(두 번 배치 테스트).
- 내부 참조(부착 → 오브젝트·구간, 오브젝트 → 설계, 구간 → 노드, zone → 구간)는 가져올 때 모두 검사하고, 깨진 참조는 **파일 전체를 거부**합니다(§17).
- 배치된 건물은 설계도의 설계 객체를 그대로 공유(불변값) → 같은 설계도를 30번 놓아도 설계는 1개, 월드 파일의 설계 표 항목도 1개.

| 방식 | UI | 동작 |
|---|---|---|
| Rectangle | 설계도 탭 → 설계도 만들기 → 사각형, 뷰포트 드래그 | 영역 안에 원점이 있는 오브젝트 + 영역 기준 도로·지형지물·지형 |
| Polygon | → 다각형, 클릭으로 꼭짓점, 더블클릭/Enter로 닫기, Backspace 마지막 점 삭제 | 단순 다각형만(자기 교차·4 m² 미만 거부). 지형 격자는 다각형 bbox에 **정점 마스크** |
| Selected Objects / Road Network / Natural Region | → 현재 선택 | 편집 모드 선택 오브젝트, 도로 편집 선택 구간(+ 그 도로에 연결된 오브젝트, Phase 18 복사와 같음), 지형 편집 선택 지형지물. 영역은 이들의 경계 + 3 m |

**경계에 걸친 요소 정책** (캡처 화면에서 도로 / 강·지형지물 각각 선택):

| 요소 | 통째로 포함 | 완전히 안쪽만 | 경계에서 자르기 (기본) |
|---|---|---|---|
| 도로 | 구간 전체 포함(설계도가 영역보다 커짐) · `roadPartial kept` | 제외 · `roadPartial dropped` | 복사본 도로망에서 경계 교차점마다 `splitSegment` → 안쪽 조각만, 잘린 끝 = 열린 끝 `roadExternal` |
| 강 | 전체 포함 · `riverPartial kept` | 제외 | 안쪽 구간마다 별도 강, **사행을 점에 구워** 모양 유지(`meander.amplitude = 0`), 유입량은 가장 상류 조각에만, 상류/하류 절단은 `riverInflowOutside` / `riverOutletOutside` |
| 능선·계곡·협곡 | 전체 | 제외 | 자르지 않고 전체(자르면 끝이 테이퍼되어 지형이 바뀜) |
| 산·언덕 | 정상이 안쪽이면 전체 | 완전히 안쪽일 때만 | 정상이 안쪽이면 전체 · 정상이 밖이면 `landformPartial dropped` |
| 호수 | 전체 · `lakePartial kept` | 제외 | 전체(분지는 자를 수 없음) |
| 해안선 | — 항상 제외 · `coastExcluded` (지도 끝까지 이어지는 요소) | | |
| 오브젝트 | 원점 기준. 발자국이 경계를 넘으면 `objectCrossesBoundary`, 건물이면 `foundationSupport` | | |
| 지형 레이어 | 영역 정점만(다각형 마스크) | | |

숨겨진 누락이 없도록 **모든 제외·절단·연결 해제는 의존성 목록**에 남고, 캡처 화면의 “경계·의존성”과 라이브러리 상세에 표시됩니다. 요소 토글(건물/기타 오브젝트/나무/도로/산·언덕/강·호수 형상/초기 물/지형 레이어)로 뺀 것은 종류별 개수로 “요소 선택으로 제외”에 표시됩니다.

## 5. 설계도 생성
캡처 화면에서 이름·설명·카테고리(자동 추정 또는 직접)·태그(쉼표)를 정하고 **저장 전 포함 내용**(건물·오브젝트·나무·도로 구간·지형지물·물 개수, 영역 크기·기준 높이·기복 범위, 의존성)을 확인합니다. 저장하면 2D 지도 썸네일(지면 음영·색, 물, 도로, 건물 발자국, 나무 — `minimap.ts`, WebGL 불필요)과 함께 라이브러리에 들어갑니다. 예: 단독 주택, 아파트 단지, 상업 거리, 공업 단지, 교차로 구역, 숲, 산악 지형, 강 유역, 호수 주변 마을, 도시·자연 혼합 — 모두 **예제 설계도 10종**으로 기본 제공됩니다(`builtin.ts`: 헤드리스 월드에서 실제 도구로 만든 장면을 캡처, 결정론적).

## 6. 라이브러리 UI
설계도 탭: [설계도 만들기 ▾(사각형/다각형/현재 선택)] [가져오기] [현재 월드를 템플릿으로] [새 월드…], 검색(이름·설명·태그·카테고리, 한/영 모두), 카테고리 칩(전체·★즐겨찾기·건물·주거·상업·공업·기반시설·도로·자연·혼합 지역·전체 월드), 최근 사용 줄, 썸네일 카드(★, “예제” 배지, 개수), 상세(설명·태그·크기·용량·의존성·작업: 배치/이름 변경/복제/내보내기/삭제, 템플릿은 새 월드로 열기/현재 월드에 적용·시드). 오브젝트 팔레트와 같은 칩·카드·검색 스타일입니다. 저장소는 브라우저 **IndexedDB**(사용할 수 없으면 세션 메모리 + 경고) — 서버 업로드 없음. 예제는 읽기 전용(복제하면 편집 가능), 즐겨찾기/최근 사용은 예제에도 됩니다.

## 7. 미리보기 · 배치 · 회전 · 정렬
- **Ghost Preview**: 설계도를 고르면 로컬 좌표의 오브젝트를 **한 번만** 배치 어댑터(Phase 11 BatchedMesh)로 만들고, 커서를 따라 **그룹 변환만** 바꿉니다 — 이동 중에는 기하를 다시 만들지 않고, 월드 문서·물리·충돌체를 건드리지 않습니다(1000동 미리보기 60 FPS, draw call 13).
- **위치 고정(pin)**: 클릭하면 그 자리에서 전체 계획을 한 번 계산하고, 오브젝트가 실제로 설 자리(≤ 600개; 그보다 크면 강체 미리보기 + 충돌 오브젝트만)·붙을 도로·지형지물 윤곽·연결선·발자국(검증 색: 초록/주황/빨강)을 그립니다. 다시 클릭하면 옮겨지고, Esc는 고정 해제.
- **옵션**: 회전(±90°, ±15°, 숫자, R/Shift+R, T), 격자 스냅(G, 빌드 격자, 최소 1 m), 지형 높이에 맞춤(끄면 원본 절대 높이 — 해수면 기준 설계도에 필요), 높이 보정, **상대 높이 유지**(강체 배치: 지면에 다시 앉히지 않음), **도로 방향에 맞춤**(가까운 도로 접선에 설계도의 가장 긴 도로/로컬 x축을 맞춤, 현재 방향에 가까운 쪽), **주변 오브젝트에 맞춤**(가장 가까운 오브젝트의 방향 + 90° 배수).
- **상대 변환 보존**: 모든 요소가 같은 강체 변환을 받으므로 건물·도로·자연의 상대 위치가 유지됩니다. 회전 시 도로 노드·제어점·강 점·산 중심이 함께 돌고, **산·능선 거칠기 노이즈는 `frame`(원점·방향)으로 함께 돌아 같은 기복**이 됩니다(테스트: 대응점 높이 일치). 지형 격자는 90° 배수가 아닌 회전에서 쌍선형(높이)/최근접(칠·지반) 재표본.
- **높이 기준**: 대상 기준 높이 D = 배치 발자국 경계의 사전-지형지물 지면 평균(지형 맞춤 켬) 또는 원본 절대 기준(끔) + 보정. 오브젝트: 지면에 선 것 → 이번 편집이 끝난 **최종 지형**에 안착(`WorldEdit.addSeat`), 떠 있던 것 → 그 지면 + 원래 높이, 상대 높이 유지 → D + `base`.
- **크기 조절은 지원하지 않습니다**: 균일 크기라도 건물 구조 해석(층고·경간·부재 단면)과 지형·물 모델(1 m 격자, 수로 최소 폭)의 기준이 바뀌어 “같은 설계도”가 다른 물리 대상이 되기 때문입니다(UI에 이유 표시).

## 8. 지형 병합 정책 (`place.ts`)
Phase 19 비파괴 레이어를 그대로 씁니다: 모든 정책은 **대상의 조각(sculpt)·칠(paint) 레이어와 지반(soil)에 한 번의 패치**로만 씁니다. 대상의 기본 지형·기존 조각·지형지물·도로는 각자의 레이어로 남고, 실행 취소는 정확히 이 변경만 되돌립니다(테스트: 직렬화 바이트 동일).

| 정책 | 결과 |
|---|---|
| 대상 지형 유지 (preserve) | 아무것도 쓰지 않음. 오브젝트·도로는 현재 지면 위 |
| 설계도 기복 더하기 (offset, 기본) | 설계도의 **조각 레이어(사용자가 만든 기복)** 를 대상 지면에 더하고 칠 적용. Phase 19 지역 배치와 같은 의미 |
| 설계도 지형 적용 (apply) | 영역 안의 사전-지형지물 지면 = 설계도 `surface` + D. 칠 = 설계도 칠, 없으면 설계도 기본 지표(대상과 다를 때), 지반 = 설계도 지반 |
| 경계 혼합 (blend) | apply × smoothstep(0, 폭, 경계까지 거리). 칠·지반은 가중치 ≥ 0.5에서만 |

지형지물(산·강·호수)은 정책과 별개로 “포함” 토글을 따르며 대상 레이어와 함께 합성됩니다(대상 지형지물과 겹치면 `featureOverlap` 경고 — 합이 쌓임을 알림). **경고**: 대상과 설계도 지형 높이 차(최대/평균), 대상 기존 조각 면적(apply/blend가 그 위에 적용), 영역 안 기존 도로 재정지, 원본 해수면 차이, 지형 형상 없는 설계도(자동으로 offset). 도로를 지워도 다른 레이어가 사라지지 않음은 Phase 19 구조 그대로이며 배치한 월드에서 다시 테스트했습니다.

## 9. 도로망 연결 (`blueprintRoads.ts`)
| 정책 | 동작 |
|---|---|
| 분리 유지 (separate, 기본) | `insertSubnetwork` — 저장된 그대로, 새 id. 기존 도로와의 교차는 연결하지 않고 개수만 경고 |
| 기존 도로에 연결 (connect) | 구간마다 `drawRoad`(손으로 그린 도로와 같음): 끝점 스냅, 교차 → 교차로. 분할된 기존 구간을 보고 |
| 끝점만 연결 (snap) | 그대로 넣은 뒤 **열린 끝(삽입 구간 하나만 쓰는 노드)** 만 3 m 안 기존 노드에 병합, 아니면 가까운 기존 도로를 분할해 T 교차로. 중간 교차는 만들지 않음 |

내부 노드 참조는 새 id로 재연결되고, 결과는 매번 `assertValid`로 검증, 블록 용도(zone)는 구간이 1:1로 남은 블록만 새 키로 옮깁니다(아니면 `zonesDropped`). **기존 도로 삭제 금지**: 결과에서 사라진 기존 구간이 “분할”이 아니면 배치를 거부(`roadRemoved`). 미리보기에는 열린 끝이 만날 기존 노드/도로가 점선으로 표시되고, 원본에서 다른 도로와 이어졌던 열린 끝은 `roadExternal`로 알립니다. 부착된 오브젝트(가로등·건물)의 링크는 붙인 도로 위에서 다시 측정됩니다. *(브라우저 검증에서 발견·수정: 열린 끝이 기존 도로 중심선 바로 위에 있으면 분할 노드가 그 끝 노드 자체가 되는데, 병합 단계가 그 노드를 지워 연결이 버려지던 문제 — 회귀 테스트 추가.)*

## 10. 모듈형 건물 보존
부재·재료·접합(형상에 내재)·기초 설정·외관·구조 사양이 설계 표에 그대로 들어가고, 객체별 사용자 물리값·지진 속성·경사 정렬도 보존됩니다. 배치된 건물은 설계 객체를 공유하므로 Phase 18의 저장 최적화(설계 표 1회 저장)와 분석 캐시가 유지되고, 배치 후 건물 편집 모드에서 자유롭게 수정할 수 있습니다(수정하면 그 건물만 새 설계값). 캡처는 설계별 기본 물리·지진값을 캐시해 1000동 캡처 비용을 줄였습니다.

## 11. 자연환경 보존
산·계곡·강·호수·지형 조각·칠·지반·숲(나무 = 식생 목록)이 들어갑니다. 해안선은 지도 단위라 제외(보고). 강과 호수는 **지형 형상**(경로·폭·깊이·둑 경사·바닥 재질·사행·정지 방식·교차 정책 / 호숫가·깊이·수면)과 **초기 물 설정**(채움·유입·하류 / 채움 여부)을 따로 다룹니다(캡처·배치 양쪽 토글). 강 유입·출구가 영역 밖이면 의존성 경고를 남기고, 잘린 강을 완성된 강처럼 꾸미지 않습니다: 배치 시 잘린 끝이 다른 강·호수·월드 경계와 만나는지 검사해 `riverUnconnected` / `riverJoins`로 알리고 연결선을 그립니다.

## 12. 수문 · 홍수 호환
배치 결과는 일반 레이어·지형지물이므로 기존 경로 그대로입니다: 최종 지형 = 충돌체 = 물 바닥, 강 수로·호수 분지·도로 배수(빗물받이)·지표별 침투·경계 조건(`hydrologyPlan`). 배치 미리보기에서 놓일 물에 대해 `hydrologyPlan` 검사(고정 수위 경계 위 유입, 출구 없는 유입 등)를 돌려 경고합니다. 실행 중 수심·유속은 설계도/템플릿의 월드에 들어가지 않으며(Phase 14의 `*.water.json`은 별도 기능 그대로), 실험 시나리오는 **월드 템플릿의 “실험 설정 포함”** 으로만 명시적으로 저장합니다. 테스트: 배치한 강 유역에서 60 s 흐름 — 질량 수지 오차 < 1e-6 (닫힌 경계, 유입 포함), 물 끈 배치는 초기 물 0, 블루프린트 월드의 결정론(아래 §20).

## 13. 의존성
캡처가 기록하는 종류: `roadExternal`(영역 밖으로 이어지는 도로 끝), `roadPartial`, `riverInflowOutside`, `riverOutletOutside`, `riverPartial`, `lakePartial`, `landformPartial`, `coastExcluded`, `foundationSupport`(영역 밖 지형에 걸친 기초), `sharedDesign`(영역 밖 건물과 공유하던 설계 — 사본 포함), `externalLink`(담지 않은 도로에 연결된 오브젝트 — 연결 해제), `groupPartial`, `objectCrossesBoundary`, `seaLevel`. 각 항목은 처리 결과(포함/잘림/제외/연결 해제/복사/참고)를 가집니다. 배치 때 자동 복구 선택지: 도로 끝 → “끝점만 연결”/“연결” 정책, 강 끝 → 연결 검사·경고, 해수면 → “지형 높이에 맞춤” 끄기(절대 높이). 복구할 수 없는 참조(파일 내부의 깨진 id)는 가져오기 단계에서 거부합니다.

## 14. 원자적 배치 · Undo / Redo
배치 = `planPlacement`가 만든 **하나의 `WorldEdit`**(오브젝트 추가 + 도로망 + 지형지물 목록 + 레이어 패치 + 안착 지시) → `applyEdit` 한 번. 레이어 → 재합성 → 도로 굽기 → 링크 추종 → 최종 지면 안착 순으로 처리되며, 어디서든 예외가 나면 모든 배열을 되돌리고 오브젝트 맵을 커밋하지 않습니다(테스트: 깨진 도로망 주입 → 직렬화 바이트 불변). 1000동 + 도로 + 지형도 실행 취소 1단계(테스트 · 브라우저), 다시 실행은 같은 결과(직렬화 동일).

## 15. 월드 템플릿 (`templates/`)
```
{ format: 'disaster-sim/world-template', version: 1, id, meta{name, description, tags, author?, createdAt, updatedAt},
  includesExperiment, builtin?{kind, seed}, world: <스키마 v7 프로젝트 파일 그대로>, preview{counts, thumbnail} }
```
월드는 프로젝트 파일과 같은 형식으로 저장되어 같은 검증·이전 경로로 열립니다. “실험 설정 포함”을 끄면 시나리오를 기본값으로 비웁니다. **기본 템플릿 8종**: 빈 평지, 작은 마을, 밀집 도시, 해안 도시(남쪽 수위 상승 시나리오 포함), 산골 마을, 강 유역 마을(집중호우 시나리오 포함), 공업 지구, 숲과 호수 — 헤드리스 월드 스토어(`scratchWorld`: 앱과 **같은 편집 파이프라인**)에서 환경 프리셋·도시 빌더·도로·숲 계획으로 생성하고, 오브젝트 id를 생성 순서로 다시 매겨 **같은 종류 + 시드 = 같은 문서(지문 동일)** 입니다. 시뮬레이션 시드도 템플릿 시드로 설정됩니다.

적용 방식은 UI에서 명확히 나뉩니다: **새 월드로 열기**(현재 월드를 닫음, 저장하지 않은 변경은 자동 저장본에만 — 확인 창) / **현재 월드에 적용**(지형·도로·자연·오브젝트 교체 = 실행 취소 1단계, 환경·실험 설정 교체는 실행 취소 대상이 아님을 확인 창에 명시).

## 16. 새 월드 만들기 마법사
상단 막대 [새 월드…] 또는 설계도 탭: ① 이름 + 월드 크기(“200 m × 200 m · 지형 격자 1 m — 현재 엔진이 지원하는 유일한 크기”, 선택지 없음) ② 템플릿(기본 8 + 내 템플릿, 지도 썸네일·설명) ③ 시드(무작위 버튼; 저장된 템플릿은 저장된 그대로라 시드 비활성) ④ 미리보기(생성된 월드의 지도·개수·실험 설정 여부) ⑤ 만들기 → ⑥ 편집 모드 + 선택 도구로 진입.

## 17. Import / Export 형식 · 검증 · 보안
- 내보내기: `<이름>.blueprint.json` / `<이름>.world-template.json`. 설계도는 **정렬된 키의 정규 JSON**(같은 값 = 같은 바이트, 저장→읽기→저장 동일).
- 가져오기: 파일 → 검증 → **미리보기 대화상자**(종류, 썸네일, 크기, 개수, 설명, 이전/버전/미사용 항목/보정 메모, 중복) → 추가. **중복**: 같은 id 또는 같은 내용(id·시간·썸네일을 뺀 내용 해시) → “같은 내용이 이미 있음” / “같은 ID 항목 있음”, [새 항목으로 추가] 또는 [기존 항목 바꾸기](예제는 바꿀 수 없음).
- 검증: JSON 구문, 크기(≤ 64 MB, 템플릿 128 MB), 개수 한도(오브젝트 2만, 식생 5만, 설계 5천, 노드·구간 5천, 지형지물 500, 격자 변 ≤ 2001), 좌표 유한·|v| ≤ 1e5, 필수 필드, id 형식·중복, 모든 내부 참조, 설계 부재(Phase 17 검사, 잘못된 부재는 제외·보고), 지형지물 매개변수(Phase 19 한계로 보정·보고), 지형 코덱 디코드.

## 18. 버전 관리
`version`(이 형식 2) + `minReaderVersion`(이 버전을 읽으려면 필요한 최소 리더). 리더 정책:
- 더 새로운 파일이라도 `minReaderVersion ≤ 2`면 읽습니다: 모르는 **최상위 필드**, 모르는 **종류의 항목**(새 오브젝트 유형·지형지물 종류·그 부착), 아는 항목의 **모르는 필드**를 버리지 않고 `unsupported`에 그대로 보관 → 내보낼 때 같은 자리에 다시 씁니다(테스트: 왕복 보존). 쓰지 않는 항목은 가져오기 대화상자와 배치 경고(`unsupported`)로 알립니다.
- `minReaderVersion > 2`면 “이 버전에서 읽을 수 없는 새 형식”으로 거부.
- Phase 21–40에서 새 요소(예: 동적 지형 변형 상태가 아닌 초기 조건)를 넣을 때는 새 최상위 필드/항목 종류로 추가하고, 의미가 바뀌는 경우에만 `minReaderVersion`을 올립니다.

검증 중 발견·수정: ① 열린 도로 끝이 기존 도로 중심선 위에 있을 때 ‘끝점만 연결’이 연결을 버리던 버그(§9), ② 체크 토글·회전 입력·경계 정책 버튼이 좁은 패널에서 잘리던 레이아웃, ③ 마법사/라이브러리 썸네일이 한꺼번에 생성되어 UI가 멈추던 문제(직렬 큐), ④ 캡처 카테고리 자동 추정(건물+시설물 = 기반시설로 분류되던 문제).

## 25. 과학적 한계 — 설계도는 실험 환경을 재사용하는 도구
설계도를 복사했다고 물리 조건이 같아지지는 않습니다. 설계도는 **구조적 속성**(건물 설계·재료·기초, 도로 단면·배수, 지형 형상·지표·지반, 초기 물 설정)을 옮기지만, 결과는 **놓인 곳의 환경 조건**에 함께 좌우됩니다:
- 지형 경사·기초 접촉(같은 건물도 경사지에서는 기초 지지 면적이 다름 — 배치 시 `foundation` 경고),
- 지반(설계도 지반은 “지형 적용/혼합”에서만 옮겨짐; 기복 더하기는 대상 지반),
- 바람 노출(주변 건물 wake·모서리 가속, 숲 차폐 — 주변이 다르면 국소 풍속이 다름),
- 주변 건물·충돌(파편, 연쇄 붕괴), 침수 깊이(대상의 강·해수면·경계 조건·배수가 다름), 도로·배수 상태(대상 도로망과 연결 여부, 빗물받이 용량).
**같은 결과는 같은 조건에서만** 기대할 수 있습니다: 같은 월드(또는 같은 템플릿 + 시드) + 같은 설계도 + 같은 배치 옵션 + 같은 이벤트 + 같은 시뮬레이션 시드. 잘린 강의 유입량은 상류를 대신하는 **근사**이며, 연결되지 않은 물 공급원은 경고로 남깁니다. 모든 모델의 한계(Phase 8–19 문서)는 그대로 적용됩니다.

## 26. 알려진 제한사항
- 크기 조절 없음(이유 §7). 지형 격자는 90° 배수가 아닌 회전에서 재표본(쌍선형, cm 양자화) → 원본과 수 cm 차이 가능.
- 해안선은 설계도에 들어가지 않음(지도 단위). 능선·계곡·협곡은 자르지 않음(통째/제외). 호수는 자르지 않음.
- 지형 병합은 사전-지형지물 지면(기본+조각)을 기준으로 하므로 대상의 산·계곡 지형지물은 “적용” 영역 위에 **더해집니다**(경고) — 대상 지형지물을 지우지 않는 비파괴 선택.
- 1000동 배치는 커밋 ~0.4 s + 배치 메시 재생성으로 첫 프레임까지 ~1.2 s(프로덕션, 이 머신). 미리보기·편집 FPS는 영향 없음.
- 라이브러리는 브라우저별(IndexedDB) — 다른 기기와 동기화 없음(파일로 내보내기/가져오기). 썸네일은 2D 지도(3D 렌더 아님).
- 템플릿 “현재 월드에 적용”에서 환경·실험 설정 교체는 실행 취소 대상이 아님(확인 창 명시).
- v1 클립보드/자연 지역을 이전한 설계도는 기준 높이 정보가 없어 높이가 원본 의미와 다를 수 있음(지역: 절대 높이, datum 0).
- 브라우저 A/B에서 자연 장면 시뮬레이션 tick이 이 빌드에서 더 높게 측정된 회차가 있었으나, 같은 머신 헤드리스 A/B에서는 두 빌드가 같은 범위(§22) — 시뮬레이션 코드 경로는 바뀌지 않았고 차이는 측정 잡음으로 판단.

## 27. Phase 21 동적 지형 변형 엔진과의 연결
- **초기 조건과 동적 상태의 분리**: 설계도·템플릿은 초기 지형 레이어만 담고, 동적 변형(침식·산사태·싱크홀 결과)은 Phase 14 물 상태처럼 별도 상태로 둘 것. 설계도 형식에는 동적 상태 자리가 없음(의도).
- **지형 변형 = 새 레이어**: 동적 변형은 조각 레이어를 덮어쓰지 말고 “변형 레이어”(시뮬레이션 중 런타임 전용, 리셋 시 폐기)로 합성 순서에 추가 → 원본 월드 복원·설계도 지형과 충돌 없음.
- **지반 레이어 활용**: 설계도가 옮기는 `soil`·지표가 산사태·액상화의 재료 입력이 됨. 경사·지반 경고(`foundation`, `terrainDiff`)를 변형 위험 미리보기로 확장 가능.
- **경계·의존성 모델 재사용**: 변형이 영역 밖 지형에 의존하는 경우(산사태 시작 사면이 영역 밖)를 같은 `dependencies` 종류 추가로 표시.
- **버전 정책**: 새 지반 매개변수는 새 필드(구 리더는 보존·무시), 의미 변경 시에만 `minReaderVersion` 상향.
