# Phase 32.1 — 극한 중력 성능 감사 (Performance Hardening)

기준 `f2bf8f1`(Phase 32 완료) → 최종: 이 문서를 넣은 커밋 “Phase 32.1 (7)”(main). 로컬 커밋만, push 없음. Phase 33은 시작하지 않았습니다.

## 1. 감사 목적

Phase 32 블랙홀·극한 중력 시스템의 대규모 장면 비용을 줄이되, 물리 결과(궤도·조석·포획·구조 파괴·장부)와 결정론, Phase 30–31
비활성 동일성을 바꾸지 않습니다. 원칙: 계측 → 가설 → 독립 검증 → 최적화 → 차등 비교 → 반복 측정. **모든 최적화는 비트 단위로 같은
결과**를 내도록 설계했고(§24), 그렇지 않은 것은 채택하지 않았습니다. 검증 중 실제 물리 결함 1건을 찾아 별도 커밋으로 고쳤습니다(§19).

## 7. KDK 분석

코드는 지시서 식과 같습니다(`src/celestial/integrator.ts`): 하위 스텝마다 kick ½h·g(x) → drift h·v → kick ½h·g(x′), 끝의 가속도를 다음
하위 스텝 시작에 재사용(n 하위 스텝에 가속도 n+1회). **물체 1000개 장면에서 KDK 구간 비용의 92 %는 적분이 아니라 접촉 질의
`touching()`**이었습니다(58만 7천 회 × 16 µs, 부하 하; 조용한 머신에서도 KDK 구간 268–300 ms/시뮬s 중 적분 자체는 ≈ 2 ms) — 물체마다 Rapier
`contactPairsWith` → 쌍마다 `contactPair` 콜백(WASM 경계 + 임시 객체). 적분 대상은 접촉·수면이 아닌 물체뿐이라 실제 KDK는
4만 5천 회(평균 1.2 µs)였습니다. 하위 스텝 결정(`segmentTimescale`)과 가속도 샘플은 이미 할당 없이 계산되고 있었습니다.

## 8. Rapier 분석

- `world.step` = 물체 1000개 장면 전체 시간의 54 %(조용한 머신 ≈ 745 ms/시뮬s, A/B 동일 — 이벤트 플래그가 Rapier 비용을 늘리지 않음).
  중력원 주위로 모인 더미의 접촉 해석이며, 물리를 바꾸지 않고는 줄일 수 없습니다.
- **κ 감사**: `freeKappa() = (n+1)/(2n)`(n = 솔버 반복)는 Rapier 0.21이 한 스텝 동안 상수 가속도에 대해 보이는 응답의 실측값입니다.
  독립 측정(`src/__audit__/p321/kappa.probe.ts`): n = 1, 2, 4, 8, dt = 1/60·1/120, 질량 1·100·10⁴ kg, 감쇠 0·0.05·0.5, 초기
  속도 0·7 m/s — κ가 (n+1)/(2n)과 최대 1.2 %(f32 위치 반올림, y = 100 m) 이내, 속도 v₁ = (v₀ + g·dt)/(1 + d·dt)가 1.3·10⁻⁷ 이내.
  질량·감쇠·초기 속도와 무관하고, 엔진이 실제 반복 수에서 κ를 계산하므로 설정이 바뀌어도 따라갑니다. **물리 상수가 아니라 Rapier
  버전의 성질**이므로 회귀 테스트로 고정했습니다(`src/physics/kappa.test.ts`: 원점 근처, 오차 < 2·10⁻³) — 적분 방식이 다른 버전이면
  궤도가 조용히 바뀌지 않고 이 테스트가 실패합니다.
- 접촉 질의 대체(§21 변경 2): Rapier 충돌 이벤트로 접촉 상태를 유지. WASM 호출 감소: 접촉 질의(물체당 스텝당 쌍 수만큼 → 0),
  `isDynamic`(물체당 스텝당 1 → 0), 접촉 힘 이벤트의 물체 조회(이벤트당 2 → 0).

## 9. 중력장 샘플링

점질량원 ≤ 4개 — 공간 자료구조 없이 선형 순회가 맞습니다. 구조물 경로에서 같은 스텝에 같은 부재 중심을 두 번 샘플하던 것(Phase 31
비율, Phase 32 들림)을 한 번으로 합쳤고, 중력원 램프·성장처럼 μ만 바뀌는 동안은 부재·중력원 쌍의 기하(q·√q, dy, 테이퍼)를 재사용합니다.
물체 경로(`visit`)의 g·Φ 샘플은 장부와 Rapier 힘에 모두 필요해 그대로 둡니다. 가속도만 필요한 경로에서 구배를 계산하지 않는 것은
이미 그랬습니다(구배는 `sampleAt`·토크·인스펙터에서만).

## 10. 조석 하중

층 수평 하중(`celestial.lateral`)은 1000동에서 ≈ 1 ms/스텝(층 수 × 중력원 수 샘플) — 병목 아님. 들림 검사(`celestial.uplift`)가
매 스텝 모든 근처 건물의 모든 부재를 샘플·스캔하던 것이 주 비용이었습니다(§21 변경 2–4).

## 11. 구조 모델

남은 구조 비용은 실제 응답 계산입니다: 붕괴 모델(하중 재적용 시 해석 전파 `propagate`/`distribute`), 층 모델 `stepUnit`(수평장이
있는 동안 모든 유닛), 지진 손상 평가(`evaluateDrift`, `updateBuilding`). 이것들은 이번 단계에서 바꾸지 않았습니다(§28).
`0ad6fe0`의 유효 층(`nLive`) 처리는 그대로이며 회귀 테스트가 유지됩니다(바람·폭발·천체 수평장이 같은 유효 층 판정을 씀; 이번 캐시는
층 모델에 관여하지 않음).

## 12. 파편

파편 생성·잔해 정착 경로는 바꾸지 않았습니다. 탑 붕괴 파편 장면(23)의 개선(−25 %)은 접촉 질의와 접촉 힘 이벤트 경로에서 나옵니다.
1000개 파편 전용 장면은 추가하지 않았습니다(장면 23·25·28이 파편을 만듦).

## 13. 강착 입자

시험 입자는 Rapier 강체가 아니라 런타임의 자체 배열(`px`, `pv`)에서 KDK로 적분됩니다(충돌 없음, 지면 착지·포획·이탈만) — 이미
분리된 경로이며 2000개 장면(16)의 비용 ≈ 70 ms/시뮬s는 A/B 동일(1.02, 잡음 범위).

## 14. 렌더링

1000동 + 중력원(크롬 검사 46과 같은 세계): 프레임의 69–78 %가 시뮬레이션 틱이었고, 나머지(React·R3F·WebGL, 삼각형 113만, draw call
21)는 ≈ 16 ms였습니다. 렌더링 쪽은 바꾸지 않았습니다 — 30 FPS 목표는 시뮬레이션 틱을 줄여 달성했습니다(§27). GPU 시간은 headless
Chrome에서 직접 잴 수 없어 “프레임 − 시뮬레이션 틱”으로만 보고합니다(추정값).

## 15. React / R3F

오버레이·HUD·인스펙터·결과 경로는 바꾸지 않았습니다. 오버레이가 꺼져 있으면 장 샘플을 하지 않는 구조는 Phase 32 그대로입니다
(CelestialLayer가 켜진 오버레이만 계산). 시뮬레이션 상태 발행은 기존 주기입니다.

## 16. 메모리

핫패스 할당 제거: 부재 중심 `toWorld` 배열(건물·부재·스텝마다), 구배 텐서의 임시 배열(중력원·호출마다). 6회 이상 반복 자원 검사
(§25): heap·DOM·리스너·geometry·texture·program·Rapier world 증가 없음.

## 19. 물리 정확도 — 발견한 결함

**궤도 적분기가 고정 물체를 자유 물체로 적분**(Phase 32 결함, `306485a`에서 수정). 적분 대상 판정이 “잠자지 않음 + 접촉 없음”뿐이라,
고정(fixed)으로 바뀐 물체(잔해에 묻힘, 정착한 파편, 위험이 고정한 물체)에 접촉이 남아 있지 않으면 KDK 대체가 적용됐습니다. Rapier는
고정 물체를 움직이지 않으므로 대체식이 (½ − κ)·g·dt²씩 매 스텝 옮겼습니다(중력원 아래 ≈ 2 cm/s). 접촉 질의 교차 검사 중
발견했고, 실패 테스트를 먼저 썼습니다(`celestial.sim.test.ts`: 중력원 아래 고정으로 바꾼 차는 자세가 정확히 그대로 — `f2bf8f1`에서
2초에 10 cm 이동으로 실패). 기준 빌드에서 고정 물체가 적분기에 들어가는 횟수를 세어 보니(장면 23: 2351회, 11: 931회) 모두 접촉
질의가 참이라 실제로 적분된 적은 없어, **44개 비교 장면의 결과는 이 수정으로 바뀌지 않았습니다**(차등 0).

## 20. 테이퍼 감사

영향 반경 테이퍼: Φ(r) = −μ∫_r^∞ a(r′)w(r′)dr′(테이퍼 구간은 Simpson 128), g = −μ·w·r⃗/q^{3/2}. dΦ/dr = μ·a·w이므로 **g = −∇Φ가
정의상 성립**(가속도와 퍼텐셜을 따로 테이퍼하지 않음 — 보존장). 구배 T_ij = μw(3r_ir_j/q^{5/2} − δ_ij/q^{3/2}) + g_i·w′(r)·r_j/(r·w)에
**테이퍼 도함수 항이 들어 있습니다**(`addGradient`: dw = −sm′(u)/(R − inner)/r). 독립 확인: 중심 차분과의 최대 상대 오차 9.0·10⁻⁸
(테이퍼 안·밖 동일, `accuracy.probe.ts`), 기존 테스트 “g = −∇Φ (central differences), untapered and tapered” 통과. 결함 없음.

## 31. 추가 수정 (2026-10-27): 중력원 아래 접촉력 임계값

**발견.** 물체 1000개 장면을 다시 분석하던 중, 중력원 주위 더미에서 접촉력 이벤트가 시뮬레이션 10초 때 스텝당 3439건까지 늘고 손상 기록이
상한(20000)에 닿는 것을 확인했습니다. 원인: 충돌 판정 임계값(Phase 31 규칙 — 임계값 = 계수 × 정지 하중)이 균일 중력만으로 계산되어,
중력원이 국소적으로 수십 g로 누르는 물체는 **가만히 놓여 있어도** 매 스텝 “충돌”로 기록되었습니다. 예: 쌓아 둔 차 두 대가 안정된 뒤
중력원(μ 5·10⁴ m³/s², 지하 12 m, 약 36 g₀)을 켜면 3초 안에 충돌 기록 360건과 함께 두 대 모두 파괴되었습니다.

**수정** (`src/simulation/gravity/runtime.ts`). 천체 중력원이 있을 때, 임계값을 **물체 위치의 국소 중력** 크기로 다시 정합니다. 국소 중력이
마지막으로 정한 값보다 10 % 넘게 바뀔 때만 다시 설정합니다(`THR_SHARE`). 중력원이 사라지면 균일 중력 규칙으로 돌아갑니다. 천체 중력원이 없는
장면에서는 이 코드가 실행되지 않으므로 Phase 30·31 결과는 그대로입니다. 지면과의 접촉은 원래 충돌 손상 대상이 아닙니다(타격체 없음).

**시험.** `celestial.sim.test.ts` — “contact-force thresholds follow the local field”: 쌓아 둔 두 대 + 중력원 → 체력 1·1, 충돌 기록 0.
수정 전 코드에서는 체력 0·0으로 실패합니다. 차 위로 떨어뜨린 차는 여전히 충돌로 기록됩니다.

**영향 (차등 검사 44개 장면, opt5 기준).** 결과가 그대로인 장면: 궤도·탈출·근접 통과·쌍성·강착·두 중력원, 약/강 중력우물, 건물 100동, 프리셋
gentleOrbit·circularOrbit·ellipticalOrbit·escape·flyby·binary·accretion·nearLake·comparison(시간 측정 값과 새 필드 `thrL`만 다름).
나머지 천체 장면은 의도대로 바뀌었습니다. 물체끼리 눌려 있는 접촉이 더 이상 손상으로 쌓이지 않습니다. 손상 기록 예: 물체 100개 2540 → 642,
