## 3. H1 — 중력 에너지 장부

**지적된 `ledger.body(…, phi, phi)` 자체는 결함이 아닙니다.** `pre()`가 스텝 시작 위치 x₀에서 m·(Φ(x₀, tₖ) − Φ(x₀, tₖ₋₁))(∂Φ/∂t 항)를 먼저 장부에 넣고, `post()`는 같은 시각 tₖ의 장으로 U = ΣmΦ(x₁, tₖ)만 기록합니다. 합을 펼치면

Φ(xₙ₊₁, tₙ) − Φ(x₀, t₀) = Σₖ[Φ(xₖ₊₁, tₖ) − Φ(xₖ, tₖ)] (공간 이동) + Σₖ[Φ(xₖ, tₖ) − Φ(xₖ, tₖ₋₁)] (시간 변화)

이므로 시간 항과 공간 항은 이미 분리돼 있었습니다(독립 기준 테스트 3·4·5–8·10·13b가 이를 확인). 그러나 같은 점검에서 **실제 결함 4개**가 나왔습니다(수정 전 새 테스트 19개 중 16개 실패):

| ID | 심각도 | 위치 | 기존 동작 | 재현(수정 전) | 수정 |
|---|---|---|---|---|---|
| H1a | 높음 | `ledger.ts` `balance` | 반암시적 오일러의 에너지 오차(자유낙하에서 스텝당 −½·m·g²·dt²)가 '기타 일'(접촉·감쇠)로 분류 | 7 kg, 3.71 m/s², 2 s 자유낙하: 기타 일 −1.61 J(실제 기타 힘 0) | 적분기 몫 ε = Σ½·m·dt·g·(v₁ − v₀)를 별도 항으로. W_기타 = ΔK − W_g + ε → 자유 비행에서 정확히 0 |
| H1b | 중간 | `runtime.ts` `pre` | 장부 스텝 뒤(잔해 더미가 물체를 들어 올림 등, `setBodyPose`)의 이동이 '장 변화의 일'로 기록 | 일정 2 g에서 5 kg을 3 m 들어 올림: W_field = 294 J(정답 0); 지지된 물체 램프 W_field 257.6 J(정답 196.2) | W_moved = m·(Φ(x′, tₖ₋₁) − Φ(x, tₖ₋₁)) — 이전 시각의 장을 다시 준비해 새 위치에서 계산(결정론적, 이동한 물체만) |
| H1c | 중간 | `ledger.ts` | 영역 중력원이 한 번 켜지면 이후 실행 내내 퍼텐셜·장 확인이 NaN | 영역 중력원 1 s 후 종료: U·잔차 계속 NaN | 스텝별 장 확인 R_Φ와 에너지 확인 R_Φ − ε를 퍼텐셜이 있는 스텝에서만 합산, 중력원이 끝나면 U 다시 보고, 공백 횟수 `potentialGaps` |
| M4 | 낮음 | 벤치·결과 | 잔차 / 순(net) W_g — 진동하는 물체에서 분모가 0에 가까움(국소 우물 0.69) | — | 총 경로 일 Σ|m·g·Δx|(`workGravityGross`)을 척도로 보고 |

물리식(지시서 §2):

- dU/dt = m·∂Φ/∂t + m·∇Φ·v → W_field = Σm·ΔₜΦ(x), W_g = Σm·g·Δx (적분기가 실제로 적용한 힘 g(x₀, tₖ) = Rapier의 G + ForceLedger의 g − G).
- Δ(K + U) = W_field + W_moved + W_기타 + (R_Φ − ε). 균일장에서 R_Φ = 0(정확), 공간 의존장에서 O(dt), ε은 O(dt).
- 비보존장(영역 중력원)에서는 퍼텐셜을 만들지 않고 W_g = ∫m·g·dx(경로 일)와 W_기타 = ΔK − W_g + ε(자유 비행에서 0)로 검증합니다.

15개 장면(독립 기준, `src/simulation/gravity/ledger.test.ts` — 반암시적 오일러 대역 엔진): 1 정지+일정 g, 2 자유낙하(닫힌 식 ½·m·g²·dt²·n, dt 1/60→1/120→1/240에서 오차 비 2.000), 3 정지+램프(W_field = m·Δg·h 정확), 4 이동+램프(궤적을 따라 해석적 ∂Φ/∂t), 5 1→3 g, 6 3→0 g, 7 반전, 8 펄스, 9 방사형 보존장(조화 우물 궤도, 오차/총일 < 5 %, dt 절반마다 비 > 1.7), 10 세기가 변하는 방사형장, 11 국소 비보존장(경로 일 = 별도 적분), 12/13 중력원 켜짐·꺼짐(퍼텐셜 복귀), 13b 방사형 중력원 종료(퍼텐셜 도약 = 장의 일), 14 복수 중력원 합성(dt 1/4에서 비 > 3), 15 장 변화 중 생성·제거. + 스텝 사이 이동 2개. Rapier 실제 실행: `gravity.sim.test.ts`(기존) + `lifecycle.sim.test.ts`(§5).

## 4. H2 — 적설 묶음의 질량·엔탈피

**확정(높음).** `ClimateWorld.depositPacket`이 `pk.done = true`를 먼저 하고 지면 칸이 없으면 반환 — 묶음이 저장소 합계에서 빠지고 지면에도 없었습니다. 월드 동쪽 가장자리에 걸친 창고(1.2 m × 300 kg/m³ 눈): **수정 전 물 장부 잔차 2.99·10⁻³ (닫힘 조건 10⁻⁸ 위반)**, 직접 빈 칸 배열: 묶음 소유 상태 불명. `dropStore`에도 같은 경로가 있었습니다.

수정: 지면 칸이 없으면 질량과 엔탈피를 **경계 유출**(`water.boundaryOut`, `energy.boundaryOut` — 기대값 식에 포함)로 기록하고, 목적지에 기록한 뒤에만 `done = true`, 목적지 `to = 'ground' | 'outflow'`. 묶음 ID = `packets` 배열 색인(재사용 없음). 상태는 지붕 저장소 → 낙하 운반 → 정지 운반 → 지면 / 경계 유출 중 하나뿐입니다.

불변식 M₀ = M_지붕 + M_운반 + M_지면 + M_유출(물·에너지 장부 잔차 < 10⁻⁸)을 `packets.sim.test.ts`에서: 빈 칸(수정 전 실패), 월드 가장자리(수정 전 실패), 집 지붕 파괴 → 바닥 정지 → 수신 부재 강제 파괴 → 재낙하 → 지면(2 g), 여러 패널 동시 파괴 + 실행 중 미정착 묶음(저장소에 포함 확인), 복원·재실행 동일. 정상 붕괴·중앙 착지·패널 전체 파괴는 기존 `roof.sim.test.ts`.

남은 근사(문서화): 부재가 파편(Rapier 물체)으로 나가면 묶음은 **이탈 위치** 아래에 내려놓습니다(파편 궤적을 따라가지 않음; 파편 질량에는 눈이 포함되지 않아 이중 계산 없음). 낙하 수 초 동안 상변화 없음.

## 8. M3 — 대규모 도시의 구조 모델 생성 지연

**확정(중간).** 스텝당 40개 생성 제한 자체는 필요하지만(1000동 동시 생성 시 최악 스텝 128 ms), 세 가지 문제가 있었습니다(`structures.sim.test.ts`, 수정 전 3개 모두 실패):

1. 동시성 — 100동, 1 g → 5 g 급변: 건물마다 t = 1.000 / 1.017 / 1.033 s에 따로 적용.
2. 순서 의존 — 같은 도시를 역순으로 만들면 건물별 파괴 시각이 다름(결과 해시 다름).
3. 이력 누락 — 늦게 만든 모델은 1에서 현재 비율로 한 번에 뛰어 **완만한 램프를 급격한 하중(동적 증폭 Ω)으로 오분류**: 1000동, 3 s 램프 → 2.5 g에서 480동, 200동 2 s 선형 램프 → 3 g에서 80동.

수정(`gravity/structures.ts`): 위치 기준 정규 순서(x, z, y, 같은 위치일 때만 id), 실험 계획이 닿는 건물은 런타임 첫 스텝부터 미리 준비(계획에 시간이 있으면 변화 전에 완료), **모든 해당 건물의 모델이 준비될 때까지 어느 건물에도 비율을 적용하지 않음**(모두 같은 스텝에 적용 — 모델 없는 N동 도시는 ⌈N/40⌉ − 1 스텝 늦게 함께 반응), 급변 여부는 모델 자신의 점프가 아니라 **그 부재의 마지막 적용 이후 장의 이력**(스텝당 > 0.05 g₀)으로(`setGravityRatio(…, sudden)`). 결과: 40동 t = 1.000(제때), 41동 모두 1.017, 100동 모두 1.033, 정·역순 해시 동일, 램프 오분류 0, 1000동 램프 최악 스텝 128 → 31 ms. 카메라·렌더링은 순서에 관여하지 않습니다(모델 생성은 시뮬레이션 스텝 안에서만, 엔티티 위치로).

## 9. M4 — 국소·방사형 중력장 잔차의 정의

기존 보고값은 벤치의 `|ΔU − W_field + W_g| / |W_g(순)|`이었습니다. 국소 우물 0.69는 우물 중심 근처에서 진동하는 물체들의 순 일(10.5 kJ)이 작아 생긴 **작은 분모 효과**였습니다(스텝·물체당 ≈ 0.4 J의 1차 적분 오차). 이제 구분해서 보고합니다(벤치 행·결과 카드·CSV): 보존장(균일 — R_Φ 정확 0, 방사형 — R_Φ O(dt), 총 경로 일 대비), 비보존장(영역 — 퍼텐셜 없음, 경로 일과 W_기타로 검증), 시간 의존장(W_field), 경계 불연속(테이퍼 없는 영역: 비보존으로 처리), 퍼텐셜 미정의 상태(공백 횟수). 지표: 에너지 절대 잔차 R_Φ − ε, 총 경로 일 대비 상대 잔차, 누적 W_g, W_field, W_moved, ΔU, ΔK, W_기타(충돌·감쇠), 경계 출입 K·U, dt 수렴(§3 테스트 2·9·14). 잔차를 0으로 만드는 보정은 하지 않았습니다. 벤치 수치는 §20.

## 13. 수정하지 않은 항목과 근거

- `ledger.body(…, phi, phi)` — §3의 전개로 정확함(테스트로 확인).
- Rapier·ForceLedger 중복(§9 지시) — Rapier는 균일 부분 G만, ForceLedger는 m·(g(x) − G)만 적용합니다(`duplicateForces() = 0`, 기존 테스트 '국소 방사형 중력원'). 부력은 하향 성분 ρ·V·g_down(무게는 Rapier가 적용 — 이중 아님), 지진 관성력은 지반 가속도(중력과 무관), 화산탄·분출물은 발사 시 장 벡터로 비행, 구조 자중은 Rapier가 아니라 구조 모델(kM)에서만. 질량이 다른 두 물체의 낙하 가속도 동일(기존 자유낙하 테스트, 질량 7 kg 대역 + Rapier 차량).
- `extra / GRAVITY` — §7.
- 구조 생성 예산 40 — 유지(무제한이면 1000동에서 128 ms 정지).
- 바람 미끄러짐·전도 추정(인스펙터·바람 양식, `windLoad.ts`) — 스텝 밖 UI 추정값이라 지구 g 기준(D 표시 대상, §22). 실제 미끄러짐은 Rapier 접촉(실제 g)으로 계산됩니다.
- 운석 진입 대기 척도고도 9.81(`atmosphere/runtime.ts`) — 행성 대기 기준(B/C; 국소 실험장이 상층 대기의 g를 대표하지 않음).
- 지진 PGA의 g 단위, 충격 피해 정규화 m·g₀ — 지구 기준 척도(B).
