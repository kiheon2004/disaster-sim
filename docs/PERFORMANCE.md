# 성능 측정 (Phase 8–10 이후)

측정 환경: Apple M3, Chrome headless (`--use-angle=metal`, 실제 GPU), **production build** (`vite build && vite preview`, `?devtools`로 측정 훅 활성화), 1600×900.
장면: `성능 테스트 장면` (건물 10%, 나무 35%, 차량 15%, 사람 25%, 가로등·표지판·담장 15%), 바람 40–45 m/s 동풍, 돌풍 25%.

## 시뮬레이션 스텝 비용 (렌더링 제외, `controller.advance()`)

| 오브젝트 | 건물 구성요소 | 장애물 | ms / 스텝 (60 Hz) | 실시간 대비 |
|---|---|---|---|---|
| 100  | 1,068 | 13  | 4.3–7.1 | 2.4–3.9× |
| 500  | 4,675 | 65  | 9.2–14.6 | 1.1–1.8× |
| 1000 | 7,890 | 130 | 15.8–18.4 | 0.9–1.06× |

최적화 전(Phase 8 직후) 1000개: 43.9 ms/스텝(0.38×). 적용한 최적화:
정적 지점의 장애물 효과 캐시(풍향이 바뀔 때만 재계산), 장애물 투영 길이 캐시, 건물 외피 요소 3단계 교차 평가(20 Hz),
입자 바람 샘플 4스텝 간격 갱신.

## 브라우저 프레임 (재생 중, 실제 GPU)

| 오브젝트 | Draw calls (전 → 후) | FPS 시각화 ON | FPS 시각화 OFF | 시뮬레이션 속도 ON / OFF | FPS 일시정지 |
|---|---|---|---|---|---|
| 100  | 966 → 245   | 53 | 60 | 0.99× / 1.00× | 48–58 |
| 500  | 3,850 → 968 | 21 | 18 | 0.52× / 0.35× | 29 |
| 1000 | 7,146 → 1,828 | 12 | 17 | 0.20× / 0.29× | 25 |

* 프레임당 물리 예산(12 ms)을 넘으면 시뮬레이션이 **느려지고**(슬로 모션) 화면은 계속 반응합니다. 고정 스텝이므로 결과(피해 순서)는 동일합니다.
* 시각화 ON/OFF 차이는 측정 오차 범위 수준입니다. 화살표는 529개 지점을 약 8 Hz로 샘플링(≈1–2 ms), 입자는 3프레임마다 교차 샘플링합니다.
* 렌더링 개선: 정적 부품을 오브젝트당 1개의 버텍스 컬러 지오메트리로 병합, 피해 링 InstancedMesh, 400개 이상일 때 작은 오브젝트 그림자 생략.

## React 리렌더 (재생 중 4초, 개발 빌드 카운터)

| 컴포넌트 | 렌더 횟수 |
|---|---|
| SimulationScene / SimEntity | 0 (런타임 재생성 시에만) |
| InspectorPanel, ObjectPalette, WindForm | 0 |
| Timeline | 시뮬레이션 상태 발행 주기(≤10 Hz)에 맞춰 갱신 |

3D 오브젝트의 위치·상태 갱신은 모두 `useFrame` + ref로 처리되며, UI 상태는 10 Hz로 스로틀된 `simStore`만 구독합니다.

## 재현 방법

```bash
npm run build && npx vite preview --port 4173
# 브라우저: http://localhost:4173/?devtools  → 메뉴(⋯) → "성능 테스트 장면 (N개)"
```
