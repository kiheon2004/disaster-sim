# 성능 측정 (Phase 11 엔진 최적화 이후)

측정 환경: Apple M3 (8코어), Chrome headless (`--use-angle=metal`, 실제 GPU), **production build** (`vite build && vite preview`, `?devtools`로 측정 훅 활성화), 1600×900, DPR 1.
장면: `성능 테스트 장면` (seed 99 — 건물 10%, 나무 35%, 차량 15%, 사람 25%, 가로등·표지판·담장 15%), 바람 42 m/s 동풍, 돌풍 25%, 4초 상승. 측정 전 6초를 동기식으로 진행해 **최적화 전/후 모두 같은 장면 상태·같은 카메라**(48, 42, 62 → 원점)에서 시작합니다.

> **측정 신뢰도 주의** — 측정 중 같은 머신에서 다른 앱(Electron 앱 등)이 CPU를 크게 사용해 load average가 2~140 사이로 요동했습니다. 그래서 절대값보다 **같은 시점에 번갈아 실행한 전/후 비교**가 의미 있습니다. 브라우저는 전/후를 오브젝트 수별로 교대로 2회 실행해 중앙값을, CPU(Node) 벤치는 교대로 3회 실행해 최솟값을 사용했습니다. 부하가 낮았던 순간 1000개 장면에서 HUD로 관찰한 값은 **59.7 FPS, 시뮬레이션 1.00×, 시뮬레이션 6.4 ms/프레임**(물리 2.3, 바람장 2.4, 피해 1.8 ms)였습니다(단일 관찰값).

## 3. 적용하지 않은 최적화와 이유

* **Web Worker** — 최적화 후 렌더링 CPU는 1000개에서 ~4 ms로 줄었고, 남은 비용은 시뮬레이션 tick입니다. 부하가 낮을 때 1000개 시뮬레이션은 6.4 ms/프레임(1.00×)으로 프레임 예산 안에 들어왔습니다. Worker로 옮기려면 렌더 어댑터·인스펙터·결과 패널이 동기적으로 읽는 런타임 상태(엔티티 포즈·플래그·부품 상태·피해 이벤트)를 매 프레임 직렬화하거나 `SharedArrayBuffer`(COOP/COEP 헤더 필요)로 공유해야 하고, Rapier WASM도 Worker에서 다시 초기화해야 합니다. 현재 수치로는 복잡도 대비 이득이 불확실해 **이번 Phase에서는 도입하지 않았습니다**. 시뮬레이션이 2,000개 이상이거나 지진·홍수처럼 시스템이 늘어나 tick이 지속적으로 10 ms를 넘으면 재검토합니다(전제: 런타임 상태를 typed-array 스냅샷으로 분리).
* **시뮬레이션 LOD / 60 Hz 미만 판정** — 사람·나무·차량 피해와 Sway(나무가 부러질 때 초기 자세로 쓰임)를 낮은 주기로 돌리면 결과가 달라집니다. 결정론 요구사항 때문에 시각 전용 시스템(입자)만 낮췄습니다.
* **물리 바디 수면(sleep)** — 바람 하중이 매 스텝 바디를 깨우므로 수면을 허용하면 결과가 바뀝니다.
* **같은 위치·같은 tick의 샘플 중복 제거(위치 셀 캐시)** — 조사 결과 같은 스텝에서 같은 지점을 두 번 샘플하는 경로가 없었습니다(엔티티는 WindForce에서 1회 샘플 후 `localWind`를 피해·Sway가 재사용, 외피는 정적 캐시, 시각화 화살표는 별도 격자). 위치를 셀로 양자화해 재사용하면 값이 바뀌므로 적용하지 않았습니다.
* **편집 모드 배치 렌더링** — 이번 범위는 시뮬레이션 엔진. 파츠 빌더를 공유하므로 같은 어댑터 방식으로 옮길 수 있습니다.

## 7. 남은 병목

1. **시뮬레이션 tick** (1000개 ~20–28 ms/스텝, 부하 시): Rapier 물리 ~8.5 ms(동적 바디 451개, 바람이 매 스텝 깨움), windForce ~7 ms(그중 바람 샘플 ~2.6 ms, 나머지는 Rapier JS 바인딩 호출 `linvel`/`addForceAtPoint`), damage ~7 ms. 다음 후보: Rapier 호출 일괄화(속도 배열 일괄 조회), 그다음 Worker.
2. **GC** — 1000개에서 프레임당 ~10 ms. 남은 할당: Rapier 바인딩의 객체 반환, `getPose`, 피해 행동 함수들의 벡터 연산.
3. **바람 시각화** — 1000개에서 ON/OFF 차이 30.0 → 37.5 FPS. 화살표 529개 8 Hz + 스트릭 700개(1/3씩 매 프레임) 샘플.
4. **편집 모드**는 여전히 오브젝트별 메시(1000개 ≈ 1,800 draw call).
