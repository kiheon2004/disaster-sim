## 1. Phase 37 목표

한 줄의 한국어·영어 문장(또는 정규 명령)으로 월드를 편집하고, 재난을 놓고, 실행을 제어하고, 질문하는 것. 기준은 "명령으로 한 편집이 마우스로 한 편집과 구별되지
않는다"였습니다 — 같은 스냅, 같은 배치 검사, 같은 실행 취소 기록, 같은 저장 형식, 같은 결정론.

- **추측해서 실행하지 않는다.** 읽지 못한 문장은 실행하지 않고 가까운 명령 2–3개와 도움말을 보여 줍니다. 한 조각이 빠진 문장은 그 조각만 되묻습니다.
- **읽은 대로 보여 준다.** 자연어의 해석 결과는 항상 정규 명령으로 되돌려 보여 줍니다("이렇게 이해했습니다: …"). 스크립트는 정규 명령으로 씁니다.
- **미리 보고 확정한다.** 편집은 미리보기(문서 불변) → Enter 확정 = 실행 취소 한 단계 → Esc 취소. 질의·카메라·선택·실행 제어는 바로 적용.
- **물리는 바꾸지 않는다.** 시뮬레이션 코드는 명령 층을 import하지 않습니다(시험). SCHEMA_VERSION 7 그대로, v1 동일성 차이 0.

## 2. Phase 36 연동

- 편집 규칙은 Phase 36의 순수 코어를 그대로 부릅니다: `snapPoint`(도로 접면·차선 스냅), `planPlacement`·`checkPlacement`·`checkStamp`(배치 검사), `transformObjects`·
  `alignObjects`·`distributeGaps`·`matchObjects`(변형·정렬), `copyProperties`, `createBlueprint`/`instantiateBlueprint`(복제), `drawRoad`, `applyDab`(지형), `planForest`,
  `createInstance` + `placement.set`(재난). 명령 전용 사본은 만들지 않았습니다. 없던 코어(그룹·플래그, 재난 칸 접근·잘림, 층수 설계, 공통 칸 편집)는 추출해 UI와 함께 씁니다(§17).
- 입력 소유권(36 §6): 열린 계획은 제스처와 같은 표를 따릅니다 — 모드 전환·문서 교체·편집 도구 무장·재난 배치 무장이면 취소(`app/inputPolicy.ts`).
- 실행 취소(36 §18): 명령 하나(또는 스크립트 하나)가 월드 기록의 **한 항목**입니다. 별도 명령 기록은 없습니다 — "방금 거 취소"는 월드 실행 취소 그 자체입니다.
- 36 §26 잔여 가운데 명령 때문에 커지는 다섯 가지를 처리했습니다(§17). 물리·렌더 잔여와 교차로 마감 높이 계단은 손대지 않았습니다.

- 동사는 한국어 별칭이 있습니다(배치·선택·추가·제외·이동·회전·크기·설정·정렬·분배·맞춤·복사·그룹·그룹해제·이름·숨김·표시·잠금·잠금해제·삭제·복제·지형·칠하기·도로·숲·재난·
  실행·일시정지·리셋·배속·보기·실행취소·다시실행·개수·목록·측정·정보). 대소문자·전각 문자는 구별하지 않습니다.
- **수치는 저장 단위**입니다: m, °, s, J, m/s, W, K. 자연어의 "MJ·kW·분·°C·km/h"는 파서가 환산해 정규 명령으로 보여 줍니다.
- **방위와 각도**: +x = 동, −z = 북(기존 나침반·미니맵과 같음). `heading=<°>`는 인스펙터의 "Y 방향" 값입니다(반시계, 0 = 객체의 로컬 +x가 동쪽) — 마우스로 넣는 수와 같습니다.
  "북쪽을 보게" 같은 방위 낱말은 종류별 앞 축(건물·사람 = 로컬 +z, 차량 = 로컬 +x)으로 환산합니다.
- **도로의 좌우**는 구간의 a → b 진행 방향 기준이고(오른쪽 = +), `side=north` 같은 방위는 도로의 방향과 비교해 옆으로 바꿉니다. 남북으로 난 길의 "북쪽"은 옆이 아니라 끝이므로 되묻습니다.
- 읽지 못한 낱말이 하나라도 남으면 명령으로 받지 않습니다(`extra` 오류). 같은 열쇠를 두 번 쓰는 것도 오류입니다.

## 6. 자연어 범위

규칙 파서입니다(형태소 분석기·언어 모델 없음). 한 줄을 읽는 순서:

1. 정규 명령이면 그대로. 정규 문법의 표기(`열쇠=값`, `type:` 등, `->`, ` where `)가 있는데 문법에 맞지 않으면 오류이고, 자연어로 다시 읽지 않습니다.
2. **부정문·조건문은 규칙보다 먼저 거부**합니다("…지 마", "말고", "빼고", "않", don't / except / without, "…면", "마다", if / until / every).
3. 낱말 자르기(사전 최장 일치). **사전에 없는 낱말이 하나라도 있으면 그 절은 "모름"** 입니다.
4. 절 나누기(쉼표·그리고·then·-고/-서) → 절마다 24개 부류 규칙을 정해진 순서로 시도. 한 규칙이 **모든 내용 낱말을 다 썼을 때만** 그 규칙의 답을 받습니다.
5. 아무 규칙도 못 읽은 절만 옛 재난 문법으로(값을 읽는 5종, 모든 낱말이 옛 문법의 낱말일 때만).
6. 결과 Intent를 정규 문자열로 썼다가 다시 읽어 검증합니다.

어휘는 `PALETTE`(객체 종류·프리셋)와 재난 등록부의 한·영 이름에서 만들고, 별칭·단위 명사·조사·수사만 `aliases.ts` 한 파일에 손으로 둡니다.

## 7. 참조 해결

- **대상**: 선택(`selection`), 직전 결과(`last`), 지시어(`it` = 선택이 있으면 선택, 없으면 직전 결과 — 어느 쪽인지 요약에 표시), 전부, id(앞부분만 쳐도 하나로 정해지면 인정,
  여럿이면 되묻기), 그룹 이름, 객체 이름, 종류(+프리셋). 그 뒤에 조건(층수·경사·높이·근처·도로 위·숨김·잠김·경고)과 순위(가장 큰·가장 높은·가장 가까운)와 개수 제한.
- **객체 순서**는 (종류, 일련번호, id)입니다. id는 난수라 id만으로 정렬하면 같은 스크립트가 다른 결과를 냅니다.
- **모호하면 묻습니다**: 이름이 같은 그룹 둘, 순위의 동점(편집 명령만 — 질의는 전부 보여 줌), 교차로가 둘 이상일 때의 `junction`, 같은 급의 길이 둘일 때의 `road:main`,
  `road:any`. 후보마다 완전한 정규 명령이 붙어 있어 고르면 그대로 실행 경로로 갑니다.
- **잠금·숨김**: 잠긴 객체는 편집에서 빠지고 빠진 수를 알립니다. 숨긴 객체는 종류·전부로 쓸어 담을 때는 빠지고, id·선택·`where hidden`처럼 직접 가리키면 포함됩니다.
- **위치**: 좌표, 도로 노드, 구간의 한 점(`seg:s2@0.5`), 교차로, 커서 아래 지면 점(`cursor` = "여기" — 포인터가 뷰포트를 떠나도 마지막 점을 기억), 화면 중심이 지면과 만나는 점
  (`view` = "저기"), 지도 중심, 객체·선택·그룹의 중심, 지형 요소(`feature:hill`), 방위 오프셋(`north(node:n4, 10)`), "옆"(`next(last)`).
- **도로**: 구간 id, 두 노드 사이(`road:n1-n2`), 큰길(`road:main` = 가장 넓고 긴 길 — 교차로를 지나 같은 단면으로 곧게 이어지는 구간을 한 길로 봄), 가장 가까운 길.
- 빈 대상은 오류입니다(아무것도 없는 것에 대한 명령은 실행하지 않음). 예외는 질의 둘: "몇 개야?"는 0, "어떤 것이?"는 빈 목록으로 답합니다.

## 8. 위치·배치 생성

- **도로 옆 N채**(`place … along=<도로> side=…`): Phase 36 스냅 엔진의 도로 접면 규칙 그대로입니다 — 보도 바깥 1 m 뒤, 건물 앞면(로컬 +z)이 도로를 향함. 간격(`gap`)은 바닥면
  가장자리 사이 거리. 곁길이 나가는 쪽의 그 구간은 비웁니다. 자리가 모자라면 들어가는 만큼 놓고 "N채 중 M채"를 알립니다(Chrome S5).
- **차**는 차선 중심에 진행 방향으로, **사람**은 보도에 놓입니다. 지점마다 열려 있는 갓길 쪽 차선을 다시 고르므로 좁아지는 구간 너머의 끝난 차선(`lanes[i] = null`)에는 놓이지 않습니다.
- **한 곳에 N개**(`at=`): 그 점을 가운데로 한 줄. 월드(±100 m) 밖으로 나가는 항목은 거부로 표시됩니다 — 200 m 지도에서 주택 100채는 한 줄에 들어가지 않습니다(21채, §22).
- 모든 항목은 `checkPlacement`(경사·떠 있음·묻힘·바퀴 접지·물속·도로 밖)와 겹침 검사를 거쳐 `ok / 경고 / 거부`로 나뉘고, 거부 사유는 요약과 유령 표지에 나옵니다.
- **지형**(`terrain raise|lower|flatten|smooth`, `paint`): 영역을 브러시 획 프로그램(`applyDab`의 반복)으로 바꿔 저장소의 획 경로로 적용합니다 — 마우스 브러시와 같은 층(조각·칠)에 기록되고,
  도로는 다시 구워지고, 땅에 서 있던 객체는 따라 앉습니다. `by=`는 가운데의 정확한 높이 변화입니다(획의 강도 단위가 아님).
- **도로**(`road A -> B`): `drawRoad`(노드 3 m 스냅, 기존 길과 만나면 분할·십자) — 도로 도구의 직선 그리기와 같은 규칙.
- **숲**(`forest <영역>`): `planForest` — 거부 사유 6종(물·경사·도로·건물·겹침·월드 밖)을 그대로 보고합니다. `seed=`를 주면 그 씨앗, 없으면 명령에서 유도한 씨앗.
- **씨앗**: 만들어지는 모든 객체에 씨앗이 명시됩니다. 같은 문장·같은 문서 → 같은 나무 모양·같은 차 색(Chrome S10).

## 9. 미리보기와 확정

- **미리보기 = 같은 실행을 복제 문서에서.** `previewIntents`가 문서를 지형 배열까지 복제(`forkDocument`)한 임시 저장소에서 확정과 **같은 코드**를 돌리고, 원본과의 차이
  (`diffDocuments`: 생긴 것·없어진 것·옮겨진 것·바뀐 것·지형 높이 변화·새 도로·재난)를 그립니다. 그래서 편집에 따라오는 일(올린 땅 위의 건물이 따라 올라감, 도로와 함께 움직인 객체)
  도 미리보기에 그대로 나옵니다. 편집 문서는 건드리지 않습니다(시험: 문서·기록·지형 바이트 불변).
- **계획 해시**: 실행 중 만들어진 id를 `new#k`·`group#k`로 바꾼 뒤의 연산 목록 해시. 확정 때의 해시가 미리보기의 해시와 같아야 합니다(시험). 계획을 세운 뒤 문서가 바뀌었으면
  확정 전에 다시 계획하고, 결과가 달라졌으면 적용하지 않고 새 미리보기를 보여 줍니다.
- **"옮겨짐"의 기준은 자세**입니다(숫자가 아님). 저장소는 지형이 바뀐 곳에서 40 m 안의 땅 위 객체를 다시 앉히면서 회전 값을 (−π, π] 범위로 다시 씁니다 — 5.5 rad로 저장된
  객체는 −0.78 rad가 됩니다. 자세는 같습니다. 미리보기는 위치 1 nm·방향(쿼터니언) 1e-9 안의 차이를 "다시 쓰임"으로 따로 세고 이동·변경에 넣지 않습니다(`samePose`,
  `DocDiff.rewritten`). 고치기 전에는 5000개 장면의 빈 구역에 지형을 올리면 "736개 이동"으로 나왔습니다.
- **바로 적용**: 질의·카메라·선택·실행 제어·"지금 실행" 재난. 편집은 미리보기 → Enter. 설정 "작은 편집은 바로 적용"(기본 꺼짐)을 켜도 삭제·20개 초과·지형·도로는 미리보기를 거칩니다.
- **큰 편집**(200개 초과, 지도 면적의 50 % 초과)은 Enter를 한 번 더 받습니다(§19).
- **수명**: 열린 계획은 모드 전환·문서 교체·편집 도구 무장·재난 배치 무장·글 수정에서 닫힙니다. 닫히면 유령·표지가 하나도 남지 않습니다(Chrome S21).

## 10. 실행 취소 — 명령 하나 = 한 단계

`worldStore.batch(fn)`:

```ts
batch: <T>(fn: () => T) => { ok: true; value: T; changed: boolean } | { ok: false; reason: 'locked' | 'busy' | 'error'; error?: unknown }
```

- 일괄 안의 `applyEdit`·`setExperiment`·`setGroupName`·`updateSimulationSettings`·지형 획·도장(차 설정 복사 포함)이 기록 항목 **하나**로 합쳐집니다
  (객체 + 도로 + 지형 패치 + 층 패치 + config + 그룹 이름). 기록 호출 9곳을 한 깔때기(`record`)로 모았고, 일괄 중에는 `past`에 넣지 않습니다.
- **롤백은 스냅숏**입니다. 시작할 때 지형 3층과 층 8개를 복사해 두고(200 m 지도 1.1 MB), 실패하면 통째로 되돌립니다. 도로 굽기와 브러시 확정은 지형을 제자리에서 고친 뒤 예외가
  나면 스스로 복원하지 않으므로(감사 E6) 항목 역적용에 기대지 않습니다.
- **확정은 실제 차이**로 기록합니다: 시작 스냅숏과 지금을 비교한 최소 사각형의 지형·층 패치. 지형 획이 여러 번이어도 패치는 하나입니다. 바이트 상한(`HISTORY_BYTES`)은 합친 항목에 적용됩니다.
- **변화 없음 → 단계 없음.** 내용으로 비교합니다(객체는 값 비교 — 잠갔다 푼 객체는 변화가 아님). 변화가 없으면 원래 문서 참조를 되돌려 놓습니다.
- **거부**: 일괄 중의 실행 취소·다시 하기·트랜잭션·획·문서 교체, 문서 잠금 중(시뮬레이션 실행 중)의 편집, `busy()` 중의 시작. 중첩 일괄은 바깥 일괄에 합류합니다.
- `config` 기록은 **바뀐 쪽만**(settings 또는 scenario) 담습니다. 전에는 둘을 함께 되돌려, 재난 하나를 실행 취소하면 그 뒤에 바꾼 시뮬 설정이 같이 옛 값으로 돌아갔습니다(감사 E2).
- 불변식(시험 `world/batch.test.ts`, `command/run.test.ts`, `command/golden.test.ts`): 확정 → 되돌리기 = 시작과 **비트 동일**(직렬화 문서 + 지형·층의 꼭짓점 배열 전부),
  다시 하기 = 확정 직후와 비트 동일, 도중 예외 → 시작 상태 + 단계 없음 + 다시 하기 목록 보존.
- 시뮬레이션 실행 중에는 편집 명령을 거부하고 이유를 보여 줍니다. 질의·카메라·선택·실행 제어·재난 명령은 됩니다(재난은 마우스 배치와 같이 허용 — 결정 필요 항목).

## 11. 재난 명령

- 명령으로 놓은 재난은 마우스로 놓은 것과 **같은 `PhenomenonInstance`**입니다: `def.defaults()` → `placement.set(템플릿, [x, z])`(0.1 m 반올림) → `createInstance` →
  `setExperiment`. 시험이 `placeAt`(마우스 경로)의 결과와 키를 뺀 나머지가 같음을 확인합니다. 핀·인스턴스 목록·실행 취소도 같습니다.
- **칸 값은 저장 단위**입니다(`energy=1.8e9` = 1.8 GJ). 칸 접근·한계·잘림은 실험 패널과 함께 쓰는 `phenomena/fields.ts`입니다. 한계를 벗어난 값은 잘라서 적용하고 요약에
  "1e13 → 1e12"처럼 표시합니다. 모르는 칸 이름은 오류(그 종류의 칸 목록을 보여 줌)입니다. 계획 단계에서 스키마를 확인하므로 불러올 때 조용히 사라지는 스펙은 만들어지지 않습니다.
- **위치**는 `placement.set`으로만 넣습니다(칸 이름이 종류마다 달라서). 전역 재난(중력·균일 대기 등)에 위치를 주면 "이 종류는 위치가 없습니다"를 알리고 위치 없이 놓습니다.
  지도 밖 위치는 거부(진앙은 예외).
- **시작 시각**(`start=<s>`): 편집 모드에서는 실행 시작 뒤 그 초, 실행 중에는 지금부터 그 초 — 요약에 어느 쪽인지 적습니다. `now` = 놓고 바로 실행(그 명령이 만든 인스턴스만).
- **단일 상태**: 전역 바람, 지도 전체 비, 같은 변의 수위 상승은 하나만 있을 수 있습니다. 둘째를 놓으면 "앞의 것을 대신합니다"를 경고합니다(놓는 것 자체는 마우스처럼 허용).
- **제어**(`disaster <인스턴스> stop|pause|resume|delete|move`): 종류마다 지원이 다릅니다 — 정지 + 일시정지: 지진·비·수위 상승·물 유입·토네이도 / 정지만: 바람·열원 /
  나머지 11종은 시작 전 취소만. 지원하지 않는 제어는 실행하지 않고 그 이유를 말합니다(`phenomena/controls.ts` — 이벤트 클래스의 메서드 유무와 시험으로 묶음).
- **옛 재난 문장**("강풍 불게 해", "규모 7 지진을 발생시켜"): 새 문법이 먼저 읽고, 읽지 못한 문장만 옛 문법(값을 실제로 읽는 바람·지진·비·수위·물 유입 5종)으로 넘어갑니다.
  결과는 `disaster … now` — 문서에 인스턴스를 놓고 바로 실행하는 한 단계입니다. 전에는 문서를 거치지 않고 실행에만 넣어 핀도 실행 취소도 없었습니다.
  "지진 멈춰"는 이제 지진을 시작하지 않습니다(전: M6.5 지진 시작 — 감사 D3).

## 12. 실행 제어·카메라

- `run` · `pause` · `reset` · `speed=<k>`는 재생 단추와 같은 액션을 부릅니다. 문서를 바꾸지 않으므로 기록이 없습니다.
- `focus <대상>` / `focus at=<위치>`: 대상의 바닥면 범위가 화면에 들어오게 카메라를 옮깁니다(선택은 바꾸지 않음).
- `undo` · `redo`는 월드 실행 취소 그 자체입니다. 실행 중에는 거부합니다.

## 13. 질의 (읽기 전용)

- `count`(종류별 개수), `list`(표: 종류·이름·id·위치·층수·구조·방향·높이·크기·경고 … 최대 200행, 넘으면 알림), `info`(한 객체의 자세한 값), `measure`(범위·높이·면적, 두 위치 사이 거리·고저차),
  주제 질의 `disasters`·`groups`·`roads`·`sim`.
- 문서·기록·선택을 바꾸지 않습니다(시험). 표의 행을 누르면 그 객체로 갑니다(UI).
- 아무것도 해당하지 않으면 개수는 0, 목록은 빈 표입니다.

## 14. 명령창 UI

- **자리와 크기**: 화면 아래 타임라인 밑의 한 줄. 입력란 32 px + 요약 줄 22 px는 늘 보이고 높이가 변하지 않습니다(글자를 칠 때 3D 화면 크기가 흔들리지 않게). 그 위의 **결과 영역**
  (계획·질문·오류·표·도움말·스크립트)만 열리고 닫히며, 높이는 `min(160px, 100vh − 640px)`이고 안에서 스크롤합니다. 옛 서랍(`CommandPanel`)을 대신했고, 옛 Chrome 스크립트가 쓰는
  `command-input`·`command-toggle`·placeholder의 "Enter"·`ui.commandOpen`은 그대로입니다.
- **레이아웃**(결과 영역을 연 상태, 오른쪽 패널 열림 — Chrome S20의 합격 조건): 3D 면적 1920×1080 51.0 %, 1440×900 40.6 %, 1366×768 40.1 %, 1280×720 41.0 %(기준 35 %).
  가로 스크롤 없음, 잘린 단추 없음(Phase 36 S19는 잘린 단추를 기록만 했고 여기서는 조건입니다), 명령창이 3D 화면을 덮지 않음.
- **키**: `/`(물리 키 `Slash`, 숫자판의 ÷는 아님)와 Ctrl·⌘ + K가 입력란으로 갑니다 — 편집 모드와 시뮬레이션 모드 모두(단축키 처리기에서 배치 키·시뮬레이션 분기보다 앞). `aria-modal`·
  `role="dialog"`를 쓰지 않아 `modalOpen()`이 단축키를 막지 않습니다. 입력란에 초점이 있는 동안 편집 단축키는 쉽니다(`isTyping`).
  `isTyping`은 이제 슬라이더·체크박스·색 칸을 타이핑으로 보지 않습니다(전에는 슬라이더를 한 번 건드리면 모든 단축키가 죽었습니다 — 감사 U9). 그 칸이 스스로 쓰는 키(슬라이더의 화살표 등)만 넘깁니다.
- **Esc 순서**: 맥락 메뉴 → 자동 완성 목록 → 열린 계획(또는 질문) → 입력란에서 나가기. 뷰포트에 초점이 있어도 열린 계획이 선택 해제보다 먼저 닫힙니다.
- **한글 입력기**: Enter·Tab·↑·↓·Esc는 조합 중이면 명령창의 동작을 하지 않습니다 — `isComposing`, `keyCode 229`, 자체 `compositionstart/end` 깃발 셋 중 하나라도 참이면(셋 다 단위 시험).
  Chrome S2는 CDP `Input.imeSetComposition`으로 실제 조합을 만들고(조합 시작 이벤트 발생, Enter 키 이벤트에 `isComposing = true`) 확인합니다. 실제 macOS 한글 입력기·Safari·Firefox는 확인하지 못했습니다.
- **입력 중 미리보기**: 글자마다 바로 계획하지 않고 150 ms 뒤에(디바운스) 초안 계획을 만듭니다. 직전 초안이 50 ms를 넘었으면 400 ms, **300 ms를 넘었으면 입력 중 미리보기를 멈추고**
  ("실시간 미리보기 멈춤") 파서만 따라가며 Enter에서 계획합니다. 초안은 확정할 수 없습니다 — Enter가 초안을 열린 계획으로 바꾸고, 그다음 Enter가 확정입니다.
- **요약 줄**: 상태(기호 + 글자: ○ 대기 ◇ 초안 ◆ 계획 ◈ 확인 ? 질문 ✕ 오류 ✓ 완료 — 색만으로 나타내지 않음), 이해한 정규 명령, +생성 ~변경 −삭제·지형 면적·도로·재난 개수, 경고 수
  (경고 항목은 한 번만 셈), 지금 Enter와 Esc가 하는 일.
- **결과 영역**: 열린 계획(줄마다 정규 명령·개수·참고·경고·항목 목록 — 정상/경고/거부와 그 사유를 낱말로, 확정·취소 단추), 질문(후보 단추, 숫자 키, 올리면 3D 강조), 빠진 조각 되묻기,
  모름(이유 + 후보 단추), 오류, 완료(질의 표는 실제 `<table>`, "이것들 선택", 행 클릭 = 그 객체 선택).
- **↑ / ↓ 기록**(브라우저 `ds.commands.history`, 50개), **Tab 자동 완성**(정규 동사·종류·프리셋·그룹 이름·객체/노드/구간 id·재난 종류와 칸 이름·그 동사의 `열쇠=` — 순수 함수 `complete.ts`).
- **도움말**(? 단추): 부류별 예문 4–6개(말뭉치에서 — 말뭉치는 필요할 때 따로 내려받는 조각 142 kB), 정규 명령 표(동사마다 한 줄 이상 — 시험이 빠진 동사를 잡음), 키.
- **스크립트 편집기**(§15)와 **오른쪽 클릭 맥락 메뉴**: 뷰포트에서 누름–뗌 이동이 5 px 미만인 오른쪽 클릭에만 뜨고(끌면 카메라 이동 그대로), "여기에 놓기 …"·"여기에 재난 …"이 그 좌표가 채워진
  명령을 명령창에 넣습니다(실행하지 않음 — 같은 계획 경로). 지면 점은 포인터 추적기의 값이고, 없으면 항목이 꺼져 있습니다.
- 문구는 `src/i18n/locales/en|ko.p37ui.ts`(186개, 한·영 열쇠와 `{매개변수}` 짝 시험), 계획·오류 문구는 `p37cmd`, 파서 문구는 `p37nl`.
- 3D 쪽(`src/rendering/command/`): 미리보기 층은 계획의 차이를 **기존 렌더러로** 그립니다 — 배치 도구의 일괄 유령(`PlanPreview`), 지형 도구에서 꺼내 공유한 높이 변화 열 지도

  장면에 객체가 하나도 남지 않습니다(S21). 명령으로 놓은 재난은 핀을 **선택하지 않고** 보여 줍니다 — 핀을 선택하면 입력 정책이 객체 선택을 지우는데, 객체 선택은 다음 명령의 "이것들"이기 때문입니다.

## 15. 명령 스크립트

- 여러 줄(`.dscmd.txt`, 일반 텍스트, `#` = 주석, 500줄까지)을 한 번에 계획 → 전체 미리보기 → 확정 = **한 단계**. 설정으로 줄마다 한 단계. 한 줄이라도 실패(오류·되묻기)하면
  전체가 취소되고 문서는 그대로입니다.
- 앞줄의 결과를 뒷줄이 가리킵니다(`last`, `it`, 방금 만든 그룹 이름). 줄마다 그때의 문서로 계획합니다(일괄 안에서 중간 문서를 읽음).
- 문서에는 저장하지 않습니다(SCHEMA_VERSION 7 그대로). 명령 기록(브라우저 `ds.commands.history`, 50개)에서 스크립트를 만들 수 있습니다.
- 글을 코드로 평가하지 않습니다 — `eval`·`Function`은 저장소에 없고(시험), 줄마다 정규 문법 또는 규칙 파서만 탑니다.
- **골든 스크립트** 3편(`src/command/golden/*.dscmd.txt`): 기본 월드(14줄), `sampleTown()`(19줄), 템플릿 "산골 마을"(15줄). 시험(`golden.test.ts`)이 편마다 확인하는 것 —
  한 단계로 기록됨, 편집 줄마다 실제로 무언가 바뀜, 결과의 id 정규화 해시·지형 바이트가 기록값(`golden.json`)과 같음, 시작 문서의 사본에서 다시 돌리면 계획 해시와 결과가 같음,
  월드를 새로 지어(객체 id가 달라짐) 돌려도 id를 뺀 결과가 같음, 되돌리기 = 시작과 비트 동일, 다시 하기 = 결과와 비트 동일, 저장 형식(§18: 내용·지형 비트, 두 번째 저장부터 바이트 동일, 스키마 7, 새 최상위 열쇠 없음). 해시는 프로세스를 바꿔 돌려도 같았습니다.
  기록값 가운데 결과 해시(`end`)는 한 번 다시 기록했습니다 — 일괄 확정이 "처음 상태로 돌아온 객체는 원래 객체로 둔다"(§10 `settleObjects`)를 얻으면서, 지형 편집 근처에 있던 객체의 회전 숫자
  표기가 결과 문서에서 달라졌기 때문입니다(자세는 같음). 시작·계획 해시는 그대로였습니다.

## 16. 언어 모델 어댑터 (만들지 않음 — 이음매만)

- `src/command/IntentProvider.ts`: 인터페이스 `IntentProvider`, 기본 구현 = 규칙 파서(`ruleProvider`), 그리고 **가짜 공급자 시험**(`provider.test.ts`)뿐입니다. 네트워크 코드와 키 처리는
  없습니다. 실제 공급자를 만들지는 사용자 결정 항목입니다(§26).
- 공급자가 돌려줄 수 있는 것은 Intent JSON뿐이고, `providerOutcome`이 그것을 같은 zod 스키마 → 정규 문자열로 쓰기 → 다시 읽기 → 처음 것과 같은지 비교에 통과시킵니다. 문법이 쓸 수 없는
  값·모르는 열쇠·빈 목록은 "모름"입니다. 통과한 것은 규칙 파서의 결과와 **같은** 해석 → 계획 → 미리보기 → 확정 경로를 탑니다(결과의 출처는 `source: 'provider'`).
- 공급자에게 보여 줄 문맥(`summarizeForProvider`)은 요약입니다: 종류별 개수, 사용자가 붙인 이름, 그룹 이름, 선택·도로 노드·구간·재난의 id, 1 m로 반올림한 커서·화면 중심 점
  (목록은 100개에서 자름). 문서 전체·기하·매개변수·지형·설정은 들어가지 않습니다.
- 만들 경우의 조건(명세 §16): 기본 꺼짐, 키는 저장소에 커밋하지 않고 브라우저 저장소에만, 문서·자동 저장·내보내기 파일에 넣지 않음.

- **v1 동일성**(Phase 36 최종 결과와 비교, 35.5·36과 같은 탐침·비교 도구, 커밋 `4ed406c` — 그 뒤 커밋은 시험·스크립트·문서뿐): 기존 32/32, Phase 31 20/20 + 1/1, 미분 44/44,

## 24. 언어 처리의 한계

- **규칙 파서입니다.** 규칙 문서와 말뭉치에 있는 틀의 문장을 읽습니다. 그 밖의 문장은 "모름 + 가까운 명령"이 정상 동작이고, 뜻을 짐작해 실행하는 경로는 없습니다. 말뭉치 100 %는
  "말뭉치의 문장"에 대한 수치이지 임의의 문장에 대한 수치가 아닙니다.
- **한국어는 사전으로 자릅니다**(형태소 분석 없음). 붙여 쓴 글도 조각이 모두 사전에 있으면 읽습니다("큰길북쪽에2층주택세채간격2미터"). 사전에 없는 낱말 하나가 그 절을 "모름"으로
  만듭니다. 사전 낱말 안의 띄어쓰기("큰 길")는 읽지 못합니다. 어미는 등록한 동사의 명령형·-요·-서·-고·-(으)세요·-(으)ㄹ래·-ㅂ니다까지이고, "-도록", "-면 좋겠어", 높임 "-시-"는 읽지 못합니다.
- **수**: 고유어 수는 단위 명사와 함께 99까지("세 채"), 한자어 수는 단위와 함께("삼십 도"), 억·만·천·백은 숫자 뒤에서만("18억"). 소수의 한글 표기("영 점 오")는 읽지 못합니다.
- **부정문·조건문은 정규식으로 거부**합니다. 해가 없는 문장을 거부할 수는 있어도("30 m 안 나무" — 조사 없는 "안") 반대는 없습니다. "선택에서 빼고 …"도 "빼고" 때문에 거부됩니다.
- **한 대상에 종류 둘**("나무와 차를 선택"), 대각선·카메라 기준 이동, 간격을 지정한 분배, 수종을 지정한 숲, 목표 높이로 올리기("3 m로 올려"), 프리셋에 없는 차로 수는 정규 문법에 없어
  "모름"입니다. 도로와 놓인 재난은 카메라·삭제·숨김의 대상이 아닙니다("큰길 보여 줘" → 모름. 재난 삭제는 "화재 지워" = `disaster fire delete`).
- **"보여 줘 / show"는 카메라**입니다. "hide trees then show them"의 show도 카메라(focus)로 읽습니다 — 숨김 해제는 "다시 보여 줘 / unhide / show … again".
- **한 낱말**: "나무"·"폭발"처럼 종류 이름만 치면 배치 명령으로 읽습니다(규칙 문서의 "동사 없는 명사구 = 배치"). 위치가 없으므로 어디에 놓을지 되묻고, 실행까지는 계획과 Enter가 더 필요합니다.
- **단위 없는 수**는 되묻습니다("5 옮겨" → 얼마나?). 상대적인 양("더 빠르게", "조금만")도 되묻습니다.
- **"여기"** 는 포인터가 마지막으로 있던 지면 점, **"저기"** 는 화면 중심이 지면과 만나는 점입니다. 포인터를 한 번도 뷰포트에 올리지 않았으면 위치를 되묻습니다.
- **후보 제안의 질**은 낮습니다. 공유하는 낱말과 편집 거리로 고른 정규 명령 틀 37개 가운데 2–3개라, 엉뚱한 틀이 나오기도 합니다(읽지 못한 이유는 따로 표시).
- 재난 문장의 일부는 옛 문법이 읽습니다(상대 시작 "태풍이 끝나고 5초 뒤", `발생`·`중지`). 옛 문법이 정규 명령으로 쓸 수 없는 값(점증, 진원 깊이, 비 영역 …)을 읽으면 버리지 않고 거부합니다.

## 27. Phase 38 연동점

- **Intent가 이음매입니다.** 새 입력 수단(음성, 언어 모델, 매크로 단추)은 `Intent[]`만 만들면 해석 → 계획 → 미리보기 → 확정을 그대로 탑니다. 언어 모델은 `IntentProvider`(§16)에 꽂습니다.
- **새 명령**은 `intent.ts`(스키마) → `canonical.ts`(문법·포매터) → `plan*.ts`(계획) → `rules.ts`·`aliases.ts`(문장) → 말뭉치 순으로 더합니다. 도움말의 명령 표는 동사가 빠지면 시험이 잡습니다.
- **일괄 단계** `worldStore.batch(fn)`는 명령 전용이 아닙니다 — 여러 편집을 한 실행 취소 단계로 묶어야 하는 도구(도시 생성기, 템플릿 적용)가 그대로 쓸 수 있습니다.
- **미리보기 = 복제 문서에서 같은 실행 + 차이**(`previewIntents`, `diffDocuments`)는 마우스 도구의 "적용 전 미리보기"에도 쓸 수 있습니다(지금 도구마다 따로 있는 미리보기 대신).
- 문법에 없는 것으로 확인된 요구: 여러 줄 배치, 완만한 지형 감쇠, 목표 높이로 올리기, 수종을 지정한 숲, 도로·재난을 대상으로 하는 카메라·삭제, 한 대상에 종류 둘, 템플릿·Blueprint 적용 명령
  (템플릿 교체는 UI 액션 안에만 있어 순수 코어가 없습니다).
- 결정 대기 항목(§26 위 표) 가운데 "실행"의 뜻과 `heading`의 뜻은 문장 해석에 직접 걸려 있어 먼저 정하는 편이 좋습니다.
