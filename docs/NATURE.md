# Phase 19 — Natural Environment & Landscape Creator

산·계곡·강·호수·해안·숲을 마우스로 만들고, 그 자연환경에서 기존 태풍·지진·홍수 시뮬레이션을 그대로 돌릴 수 있게 했습니다. 핵심은 **비파괴 지형 레이어**입니다: 기본 지형·사용자 조각·자연 지형지물·도로가 각자의 레이어로 남고, 최종 지형은 정해진 순서로 결정론적으로 합성됩니다. 그래서 도로를 지워도 그 사이에 만든 산·강이 사라지지 않고, 강을 고쳐도 사용자가 깎은 언덕이 남습니다. 모든 수치는 SI(m, s, m³/s).

## 1. 기존 시스템 분석 (작업 전)

| 부분 | Phase 18 |
|---|---|
| 높이장 | `TerrainData` 201×201 정점 `heights`(float32, 1 cm 양자화)·`ground`·`soil`. **하나의 배열**이 Rapier 높이장(시뮬레이션 로드 시)·물 바닥(셀 = 두 충돌 삼각형 평균)·렌더러·배치·접촉 마찰의 원천 |
| 브러시 · 프리셋 | `applyDab`가 최종 높이를 제자리에서 수정, 획 = 사각형 패치 1개 = 실행 취소 1단계. 프리셋은 전부 교체 |
| 도로 | 도로가 덮은 정점의 원래 값을 `roads.underlay`에 보관하고 최종 높이를 덮어씀. 브러시가 도로 아래를 바꾸면 변화량을 underlay에 더하고 다시 굽기 |
| 물 | `WaterField`가 최종 지형에서 바닥·투수·Manning·배수를 만듦(물 이벤트 시작 시 1회). 기준 수위, 경계(auto/closed/open/fixedLevel), 물 공급원·수위 상승·강우, 실행 중 물 상태 스냅샷 |
| 건물 · 오브젝트 | 지면 오브젝트는 지형 변경 후 재안착(`followTerrain`), 건물 기초 정책(다시 맞춤/위치 유지), 도로 링크 |
| 식생 | `tree`: 바람(줄기 파단·전도)·지진 반응, 홍수는 노출만. 바람장 장애물은 건물만 |
| 저장 · 스냅샷 | v6(최종 지형 + 도로망 + 설계 테이블), 시뮬레이션은 문서 복사본에서 실행 |

**소유권 문제**: 최종 높이 하나를 브러시·프리셋·도로가 모두 고칩니다. underlay는 “도로 아래 원래 값”만 기억할 뿐 그 값이 기본 지형인지 사용자가 깎은 것인지 산 생성기인지는 사라집니다. 편집 가능한 자연 지형지물이 들어오면, 하나를 고치거나 지울 때 무엇을 되돌릴지 정할 근거가 없습니다.

## 2. 비파괴 지형 레이어 — 데이터 모델과 합성 순서

```
Base Terrain           base.heights / base.ground       프리셋, 불러온 지형
+ User Sculpt Layer    sculpt  (Δh, cm 단위)             브러시 획
+ Landform Features    Σ Δh                             산·언덕·능선·계곡·협곡
= Landform L
⊓ Water / Coast        min(L, 단면)                      강·호수·해안 (단면은 L에서 계산)
+ User Paint Layer     paint (지표 종류, 255 = 없음)      재질 칠
= Natural Terrain N    natural.*  (파생 캐시, 저장 안 함)
⊕ Road Grading         Phase 18 bake를 N 위에서
= Final Terrain        TerrainData — 충돌체·물 바닥·렌더러·배치·마찰
```

* **결정론 · 순서 무관**: 가산(합)과 깎기(최소값)는 교환 법칙이 성립 → 지형지물의 생성 순서와 무관(테스트: 순서를 뒤집어도 비트 단위 동일). 재질은 가장 낮게 깎은 지형지물이 이깁니다(동률은 목록 순서).
* **사각형 단위 합성**: 사각형만 다시 합성한 값 = 전체 합성 값(테스트). 강은 경로 전체의 L에서 바닥을 정하므로, 강의 영향 범위와 겹치는 변경은 그 강 전체로 넓혀 합성합니다(`expandForRivers`).
* **지형지물은 불변 값**(편집 = 새 객체), 정점 레이어는 typed array를 제자리 수정 + 사각형 패치로 실행 취소.
* 파생 캐시에는 `culvert`(암거 정책 강 수로 정점)와 `roadBase`(둑 정책 강 수로를 뺀 높이)도 있습니다(§10).

## 3. 도로와 지형의 충돌 해결

* 도로는 언제나 **현재의 N** 위에서 굽습니다. `underlay`는 N에서 파생되는 호환용 값입니다.
* **도로 삭제** → 그 자리는 현재 N(그 뒤에 만든 산·강·조각 포함). 과거 스냅샷으로 덮어쓰지 않습니다.
* **도로 아래 지형 편집** → 브러시 획 끝에 변화량이 Sculpt 레이어로 가고, 사각형 합성 → 겹치는 도로 다시 굽기(정지 도로는 새 지형에 맞춰 다시 정지).
* **지형지물 편집/삭제** → 영향 사각형(강이면 강 전체) 합성 → 도로 영향 범위로 넓혀 굽기.
* 검증(테스트 + 브라우저): ① 산 → 산 위 도로 → 도로 주변 조각 → 도로 삭제 ⇒ 조각·산 유지, 도로 변경만 제거(최종 = N). ② 도로 먼저 → 산 추가(도로가 산 위로 다시 정지) → 산 삭제 → 도로 삭제 ⇒ 사용자 조각만 남음. ③ 강 생성/삭제 사이의 조각 유지.

## 4. 지형 브러시

기존 올리기·내리기·평탄화·다듬기·지표 칠하기·토양 칠하기에 추가:

| 도구 | 동작 |
|---|---|
| 고원 | 누른 지점 높이보다 **높은 것만** 깎아 평평한 꼭대기(채우지 않음) |
| 능선 붓 / 골짜기 붓 | 날카로운(원뿔형) 단면으로 올림 / 내림 — 끌면 능선 / 골짜기 |
| 경사로 | 누른 점 A에서 커서 B까지 직선 경사(시작 시점의 높이 hA → B의 원래 높이) |
| 요철 | 시드 값 잡음(같은 시드 = 같은 무늬) |
| 침식(근사) | **열적 침식** 한 단계: 안식각 ≈ 33°(1 m 셀당 0.65 m)보다 가파른 정점의 초과 높이 일부를 가장 낮은 이웃으로, 지표 침식성 비율로. 부피 보존. 하천 침식·퇴적 모델이 아님 |

설정: 크기, 세기, **감쇠**(부드럽게/선형/날카롭게/평평하게), **모양**(원/사각), **시드**(요철), **높이 제한**(올리기는 최고 이상, 내리기는 최저 이하로 가지 않음 — 기존 높이는 자르지 않음). 획마다 **최대 상승/하강과 면적**을 패널에 실시간 표시. 새 옵션이 없을 때 기존 브러시 결과는 그대로입니다(기존 테스트).

## 5. 산 · 언덕 · 능선 · 계곡 · 협곡

| 지형지물 | 단면 | 범위(200 m 월드) |
|---|---|---|
| 산 | h·(1−t²)³·(1 + ½r·fBm) | 반경 8–100 m, 높이 3–60 m |
| 언덕 | h·½(1+cos πt) | 높이 1–20 m |
| 능선 | 경로를 따라 h·(1−t²)²·끝 감쇠 | 폭 6–80 m, 높이 1–40 m |
| 계곡 | −h·(1−t²)² (U자) | 깊이 1–30 m |
| 협곡 | 평평한 바닥(폭의 절반) + 가파른 벽 | 깊이 1–30 m |

* 클릭(산/언덕) 또는 경로 클릭 + 더블클릭/Enter(능선·계곡·협곡). 만든 뒤 **편집 도구**로 선택·핸들 드래그·값 수정·삭제.
* 같은 시드·매개변수 = 같은 지형. 인스펙터가 고도·경사·레이어 기여(각 지형지물의 Δh)를 보여 줍니다.
* **높이장 한계**: 정점마다 높이 하나 — 동굴·오버행·아치는 만들 수 없고, 그런 것처럼 표시하지 않습니다(협곡 설명에 명시).

## 6. 강

* **그리기**: 상류 → 하류 순서로 클릭, 더블클릭/Enter 완료. 제어점은 편집 도구로 드래그.
* **매개변수**: 폭(≥ 3 m), 깊이, 둑 경사(수평:수직), 바닥 재질, **사행**(진폭·파장·시드, 양 끝은 고정), 바닥 경사 정책, 도로 교차 정책.
* **바닥**: 경로를 따라 L의 10 m 이동평균 − 깊이. `내리막` 정책은 하류로 갈수록 **절대 높아지지 않음**(누적 최솟값) — 역경사 없음. `지형 따라` 정책은 평균 그대로(역경사 경고).
* **단면**: 바닥 폭 안은 평평, 밖은 1:둑경사로 올라가 L과 만나는 곳까지 — 깎기만 합니다(min).
* **경고**: 역경사(10 m 구간에서 0.2 m 이상 상승), 급경사(> 15 %), 깊은 절토(L − 바닥 > 깊이 + 4 m), 도로와 교차(교량 구조 없음).
* **삭제 · 수정**: 강의 깎기만 사라지고/바뀌고 다른 레이어는 그대로(테스트).
* **최소 폭 3 m** = 물 격자 3칸: 1 m 격자보다 좁은 수로는 해석할 수 없어 더 좁은 강은 만들지 않습니다(명시적 정책).

## 7. 강 · 호수 수문 모델

**수로(지형)와 물(상태)을 분리**합니다. 강을 그렸다고 물이 생기지 않습니다.

| 설정 | 의미 |
|---|---|
| 강 초기 수심(깊이 대비 %) | 시뮬레이션 시작 시 수로에 바닥 + fill·깊이까지 물 |
| 상류 유입(m³/s) | 상류 끝의 정상 유량 = 기존 **물 공급원** 이벤트(실행 내내) |
| 하류 끝 | 지도 가장자리(6 m 이내)면 그 변을 이번 실행에서만 **open** 경계로(사용자가 고정 수위로 정한 변은 유지) |
| 호수 물 채우기 | 시작 시 분지(다각형 안, 바닥 < 수면)의 셀을 목표 수면까지 |
| 해안 | 바다 = 월드 기준 수위(Phase 14 경계 · 수위 상승 이벤트) |

* 물 자체는 기존 Phase 14 솔버가 계산합니다(수심·유속·질량 예산). 초기 물은 예산의 `initial`, 유입은 `sources`에 들어가 **질량 보존**이 그대로 닫힙니다(테스트: 오차 < 10⁻⁶ 상대).
* **비정상 물 생성 방지**: 유입 지점이 고정 수위 경계 위면 유입을 **적용하지 않음**(물을 넣고 빼기를 끝없이 반복하므로), 출구 없는 지속 유입은 경고(물이 쌓임), 하류가 고정 수위 경계면 유지·기록. 로그·인스펙터에 표시.
* **월드 파일과 물 상태 구분**: 파일에는 물이 없고 설정만 있습니다. 실행 중 물 상태 스냅샷(Phase 14)을 불러온 경우 그것이 지형지물의 초기 물보다 우선합니다.
* 편집 모드 미리보기: 시작할 물(채운 호수·강)을 반투명 수면으로 표시 — “시작 상태의 그림”이고 흐름 계산이 아님.
* 검증(테스트): 1 % 경사 계곡의 강에 6 m³/s 유입 → 150 s 후 하류 40 m 지점 수심 > 0.05 m, 유속 +x(하류), 열린 가장자리로 유출 > 0, 강 밖은 마름, **경로를 바꾸면 물이 새 경로로**; 물을 채운 호수 20 s → 부피 불변(10⁻⁶), 호수 밖 0; 수로로 연결된 두 분지 → 높은 쪽 수위 하강·낮은 쪽에 물(높은 수면 → 낮은 수면).

## 8. 호수

* 호숫가를 클릭(≥ 3점), Enter. **수면 = 호숫가 최저점 − 여유(기본 0.3 m)** — 분지가 물을 담을 수 있게. 깊이·호숫가 폭(바닥이 깊어지는 거리)·바닥 재질·물 채우기.
* 단면: 다각형 안에서 수면 − 깊이·smoothstep(호숫가까지 거리 / 호숫가 폭).
* **수면–지형 모순 검사**: 호숫가가 수면보다 낮으면 “물이 넘침” 경고(인스펙터·시뮬레이션 로그). 강이 호수에서 나가는 곳은 의도된 출구입니다.
* **제거 정책**: 호수를 지우면 분지와 물 채우기 설정이 함께 사라집니다(월드에는 물 상태가 없으므로 남길 물이 없음; 실행 중인 물은 그 시뮬레이션에만 있음). 분지만 남기려면 물 채우기를 끄면 됩니다.

## 9. 해안선 · 해변

* 해안선을 그리고 바다 쪽(그린 방향의 오른쪽/왼쪽)을 고릅니다. 선은 양 끝에서 지도 밖까지 연장됩니다.
* 바다 쪽: 해수면 − 해저 경사·거리(최대 수심까지), 육지 쪽: 해변 폭 안은 해수면 + 해변 경사·거리, 그 뒤는 1:2 사면으로 L과 만남(절벽 단차 없음). 재질 모래/암반 등.
* 해수면 = 월드 기준 수위(보기 섹션). 해안선을 바꾸면 지형이 바뀌므로 수위 상승 시 물이 들어오는 경로도 바뀝니다(물 솔버가 같은 지형을 씀).
* **파랑·조석·해안 침식은 계산하지 않습니다**(UI·문서에 명시).

## 10. 강과 도로의 교차

교량이나 암거 구조물은 만들지 않습니다. 강마다 정책을 명시합니다:

| 정책 | 처리 |
|---|---|
| 암거 근사(기본) | 수로 정점(바닥·둑, L보다 0.2 m 이상 낮은 곳)은 도로 정지가 **건드리지 않음** → 물이 도로 아래로 통과. 도로 메시는 수로 위에도 그려지지만 충돌체에는 구멍이 있어 차량은 지날 수 없습니다(교량 구조 없음) |

## 13. 식생과 바람 · 홍수 (선택 설정, 기본 꺼짐)

두 반응 모두 **프로젝트 설정으로만 켜집니다**. 꺼진 상태는 Phase 18과 비트 단위로 같아 기존 골든(바람·지진·홍수·복합)이 바뀌지 않습니다.

**캐노피 바람 차폐**: 숲 안의 수관 높이 풍속은 열린 땅보다 낮고, 숲 가장자리에서 수관 높이의 몇 배 거리에 걸쳐 조정됩니다(숲 가장자리 풍동·LES 연구: 조정 구간 ~5–10 h, 깊은 숲 수관 상단 풍속 ~40–60 %). 모델: 각 나무·16방향마다 바람이 오는 쪽 수관 덮개를 따라 가장자리까지의 거리(fetch ≤ 60 m)로 `1 − 0.5·(1 − e^(−fetch/3h))`를 그 나무의 국지 풍속에 곱함. 가장자리·외딴 나무는 1(그대로). 건물·다른 물체에는 적용하지 않습니다(“나무가 많으니 바람이 약하다” 같은 임의 감소 없음). 테스트: 바람이 들어오는 가장자리 줄의 하중은 동일, 안쪽은 < 80 %.

**나무 홍수 반응**: 잠긴 줄기(+물에 닿은 수관)의 흐름 항력 전도 모멘트 vs 뿌리판 용량(설계 풍속에서 나무가 받는 밑동 모멘트 — 가로등·표지와 같은 기준), 물에 10분 이상 잠긴 젖은 땅은 용량 −40 %. **뿌리의 토양 보강은 모델링하지 않은 제한된 근사**입니다. 테스트: 5 m 해일성 흐름에서 켜면 전도, 끄면 0. 1 m·2 m/s 정도의 흐름에서는 9 m 나무가 쓰러지지 않습니다(용량 ~30 kN·m 대비 모멘트 ~0.6 kN·m — 실제로도 홍수 전도는 대부분 세굴·부유물 때문).

## 16. 자연환경 프리셋

산악 계곡, 강 유역, 해안 평야, 숲 언덕, 호수 지대, 도시·자연 혼합. 각각 기본 지형 + 지형지물(+물 설정) + 도로 + 건물(Phase 17/18 도시 빌더) + 숲(숲 계획기)을 **새 지형의 임시 합성 위에서** 계획(호숫가 높이 확인, 나무·건물이 새 물을 피함) → 오브젝트·도로·레이어 교체를 **실행 취소 1단계**로 커밋. 같은 시드 = 같은 월드(테스트), 모두 이후 편집 가능. 생성 266–649 ms.

## 17. 실행 취소 / 다시 실행

조각 획, 지형지물 생성·편집·삭제, 강·호수·해안, 재질 칠, 숲 획, 프리셋, 레이어 지역 붙여넣기 — 모두 원자적 1단계. 기록 항목 = { 오브젝트, 최종 지형 패치, 도로망, **지형지물 목록(불변 참조) + 레이어 패치(기본/조각/칠/자연 캐시)** }. 레이어 편집 중 예외가 나면 모든 배열을 복원하고 다시 던집니다(테스트: 잘못된 도로망과 함께 보낸 편집 → 문서·지형 그대로). 실행 취소 후 최종 지형 = 충돌체·물 바닥의 원천이므로 일관성이 유지되고, 도로 underlay·자연 캐시도 패치로 함께 돌아옵니다(테스트: 5단계 왕복 스냅샷 동일, 브라우저 12단계 전체 왕복 동일).

## 18. 저장 / 불러오기 (스키마 v7)

```json
"landscape": { "version": 1,
  "base":   { "elevation": "<cm-delta-rle>", "ground": "<u8-rle>" },
  "sculpt": "<cm-delta-rle>" | null,  "paint": "<u8-rle>" | null,
  "features": [ { "id": "f1", "kind": "mountain", ... }, ... ], "next": 4 }
```

* 최종 지형(`terrain`)도 계속 저장합니다(v6까지와 같은 블록). 불러올 때 레이어를 합성하고 도로를 구워 **저장된 지형과 다른 정점 수를 보고**(`recomposedVertices`; 이 버전이 쓴 파일은 0 — 테스트·브라우저).
* **마이그레이션**: v1–v6 → 저장된 지형에 도로 underlay를 되돌린 **자연 지형이 기본 지형**, 조각·칠·지형지물 없음, 최종 지형은 그대로. 도로 지형 변경과 새 레이어가 충돌하지 않습니다(테스트: v6 파일의 도로 삭제 → 완전한 원래 땅).
* 잘못된 지형지물은 제거·보고(종류·점 수·id 형식), 값은 한계로 클램프.
* **왕복 결정론**: 저장 → 불러오기 → 저장이 **바이트 단위로 같음**. 이를 위해 모듈형 건물 부재를 고정 키 순서로 쓰고, 불러온 오브젝트의 키 순서를 생성 순서와 맞췄습니다(브라우저 검증에서 발견).
* 직접 지형 배열을 고친 문서(이전 코드 경로·도구)는 `adoptTerrain`이 레이어를 지형에 맞춰 다시 세웁니다.

## 19. 원본 월드 보존

시뮬레이션은 문서 복사본에서 실행되고, 지형지물의 물은 실행에만 존재합니다. 테스트: 산 + 강 + 도로 + 건물 + 나무에서 강우 + 지진 20 s ×2 → 두 실행의 물 부피·피해 이벤트·도로 상태가 같고(결정론), 문서 지문과 저장 문자열이 실행 전과 같음. 브라우저 20번: 강우·홍수·태풍·지진·복합재난 다섯 번 실행 뒤 문서 동일.

## 24. 알려진 제한사항

* **높이장**: 동굴·오버행·아치 불가(정점마다 높이 하나).
* **1 m 홍수 격자**: 3 m보다 좁은 수로는 만들지 않음, 그 이상도 수로 단면은 1 m 셀로 근사(거터·작은 도랑의 흐름 단면 해상 불가). 연석 15 cm 같은 단차는 1 m 경사.
* **침식·퇴적·하천 지형 진화 없음**: 침식 브러시는 열적 침식의 형태 근사, 강·해안은 시뮬레이션 중 변하지 않음.
* **파랑·조석·해안 침식 없음**. 바다는 정적 기준 수위 + 수위 상승 이벤트.
* **식생 생장·생태계 없음**. 캐노피 차폐·나무 홍수 반응은 선택 설정의 근사(뿌리 토양 보강 없음).
* **동적 산사태·싱크홀**은 Phase 21–22.
* 교량·암거 구조물 없음(교차 정책은 물 흐름만 근사; 암거 위 도로는 충돌체가 비어 차량 통과 불가).
* 브러시 획이 강 수로 안을 올리면 획 끝에 강이 다시 깎습니다(강 레이어가 조각 위).
* 지형 프리셋은 기본 지형을 바꾸고 조각·칠을 지웁니다(지형지물은 유지).
* 측정 회차에 따라 머신이 30 Hz 제한 상태가 되어 FPS가 cap에 걸림(§20).

## 25. Phase 20 Blueprint 확장 지점

* `landscape/region.ts` — **자연 지역**: 사각형 안의 지형지물(앵커 기준 상대 좌표, 지역 id) + 조각·칠 레이어 조각을 JSON으로(`format: disaster-sim/nature-region`). 붙일 때 새 id, 조각은 더하고 칠은 덮어씀, 기본 지형·도로는 그대로, 실행 취소 1단계(`applyEdit({ landscape: { features, next, layers } })`). 해안선은 지도 규모라 제외. 테스트: 산·강·조각을 담아 100 m 옮겨 붙이면 같은 높이가 재현됨.
* Phase 18 도로 Blueprint(연결/분리 정책) · Phase 17 설계 테이블과 합치면 “도시 + 자연” 블루프린트 라이브러리가 됩니다.
* 지형지물은 불변 값 + 검증된 스키마(`landscape/schema.ts`) — 라이브러리 항목의 형식으로 그대로 쓸 수 있습니다.
