# Phase 17 — Modular Building Creator & Structural Customization

사용자가 건물을 직접 만들고(매개변수 또는 부재 단위), 그 구조적 차이가 기존 바람·지진·홍수 실험에 물리적으로 반영되게 하는 것이 목표입니다.
모든 기능은 GUI로 사용할 수 있고 자연어 명령은 바뀌지 않았습니다. **실제 건축 구조 설계·안전 평가에 쓸 수 없는 설명 가능한 근사 모델**입니다(§12).

## 1. 기존 건물 아키텍처 분석 (Phase 0–16)

| 구성 | 위치 | 동작 |
|---|---|---|
| 데이터 | `WorldObject` (`type:'building'`) | 평면 `params`(층수·폭·깊이·층고·색·간판·옥상설비), `physics`(질량 = W·D·H·250 kg/m³, 설계풍속 80 m/s), 생성된 외장 `components`, `seismic`(구조형식 4종 + 배율, 기초 3종) |
| 정의 | `objects/definitions/building.ts` | 상자 충돌체, 외장 부품(창·간판·지붕패널·파라펫·옥상설비) |
| 렌더링 | `parts/objectParts` → `SimRenderAdapter` | 셸(BatchedMesh) + 외장 종류별 InstancedMesh; 편집 모드도 같은 어댑터(Phase 16 청크) |
| 바람 | `WindForceSystem` + `behaviors/building.ts` | 하중비 `(v/windResistance)²` 피로, 외장 부품별 판정 |
| 지진 | `SeismicState` → `StructuralModel` | 건물당 ≤5 자유도 전단 사슬, **층별 균일** 강성·강도(기준식 주기 `Ct·Hˣ`, 형식별 `cy`), Park–Ang 손상, 기초 스프링·미끄럼·지지력→기울기, D≥1 → 전체 붕괴 |
| 홍수 | `behaviors/flood.ts` | 내부 침수 지연, 마감재 손상, 횡수압 vs `cy·W` |
| 통합 손상 | `interactions/integrity.ts` | 재난별 채널, 잔여강도 `1−0.3·D` |

결론: 질량·풍하중 용량·지진 강성/강도가 **서로 독립된 스칼라**였고(구조를 바꿔도 풍하중 용량은 그대로), 기둥·벽이 어디 있는지 아는 코드가 없었습니다.

### 설계 결정
1. **추가형·선택형**: 모듈형 건물 = 기존 `building` + 선택 필드 `building: BuildingDesign`. 없으면 레거시 건물로 Phase 16 경로 그대로(골든 테스트가 구조적으로 영향받지 않음). 불러오기는 자동 변환하지 않음.
2. **부재가 원본**: `spec`(매개변수) → 부재 생성 → 이후 부재 단위 편집. 수동 편집 후 매개변수 재생성은 경고(실행 취소 가능). 층 추가/제거는 부재 연산이라 수동 편집 유지.
3. **외형(type)과 구조 역할(role) 분리**: 벽은 내력/비내력/외장, 기둥은 주(횡력)/보조(중력), 창·문은 항상 개구부.
4. **명시적 어댑터**: `analyzeBuilding(design)` → `toStructural`(`structuralAdapter.ts`) → 기존 `StructuralModel`(층별 배열 선택 입력 추가, 없으면 비트 단위 동일).
5. **파생 필드 동기화**: `params`(경계상자)·`physics`(질량·설계풍속)·`seismic`·외장 `components`를 설계에서 파생 → 경계상자만 아는 기존 시스템(바람 wake, 홍수 장애물, 충돌체)도 그대로 동작.
6. **런타임 부재 손상은 문서와 분리**(`RuntimeEntity.modular`, typed array).

### 충돌 검토
| 위험 | 대응 |
|---|---|
| 골든·회귀 결과 변화 | 모듈형 경로는 `building` 필드가 있을 때만 실행. 기존 골든 파일 수정 없음, 전부 통과 |
| 부재 수만큼 렌더 비용 | 재료 외형별 InstancedMesh 6개(장면 전체 공유), 내부 부재 컬링, 원거리 LOD, 부재별 React/useFrame 없음 |
| 입력 충돌 | 단일 `editorStore.tool`에 `'building'` 추가; 부재 선택은 이 도구에서만 |
| 저장 호환 | 선택 필드, 스키마 v5 유지 |
| StructuralModel 변경 | 층별 입력은 선택. 균일 경로는 같은 연산 순서(지진 테스트·골든 통과) |
| 지형 재편집 문제(Phase 16 알려진 문제) | 배치 시 정렬을 객체에 저장(`terrainAlign`), 건물은 기초 정책(다시 맞춤/위치 유지) |

## 2. Phase 16 메모리 증가 — 원인 확인·수정

`scripts/bench-selection-memory.mjs`: 시나리오별 N회 반복, 강제 GC(--expose-gc + CDP collectGarbage) 후 힙, `renderer.info.memory`, canvas/document 리스너 수.

**원인(확인됨)**: drei `TransformControls`는 R3F `<primitive>`로 마운트되는데 R3F는 primitive를 dispose하지 않습니다. three-stdlib 컨트롤은 생성 시 document에 `pointerup`(+ 대상 요소에 pointerdown/move) 리스너를 걸고 `dispose()`에서만 제거하므로, **기즈모가 마운트될 때마다 컨트롤 전체(핸들 메시 ~80개·지오메트리·머티리얼)가 document 리스너에 붙잡혀** 남았습니다. 추가로 `SelectionBox`의 `EdgesGeometry`가 dispose되지 않았습니다. 지오메트리 추적(생성 후 미해제·씬 밖) 결과 X/Y/Z/XY… 핸들 메시가 남는 것을 직접 확인했습니다.

**수정**: `ManagedTransformControls`(언마운트 시 dispose), `SelectionBox` 지오메트리 해제, 선택 대상 탐색을 layout effect로(복제·실행 취소 시 1프레임 동안 떨어진 노드에 붙는 콘솔 오류 해결).

| 시나리오 (1000개 장면, 40회, GC 후) | 수정 전 KB/회 · 남은 리스너 | 수정 후 KB/회 · 리스너 |
|---|---|---|
| 같은 오브젝트 선택/해제 | 335 · +40 | 17.7 (재측정 39.8) · 0 |
| 다른 오브젝트 선택 | 356 · +40 | 7.5 · 0 |
| 다중 선택/해제 | 363 · +40 | 6.0 · 0 |
| 단일↔다중↔배치 렌더 경로 전환 | 588 · +80 | 7.9 · 0 |
| 기즈모 모드 전환 / hover | 13 / 10 | 0.8 / 2 |

160회로 늘리면 같은 오브젝트 반복의 증가분이 회당 **~3 KB**로 수렴합니다(40→160회: 0.69→1.05 MB). 힙 스냅샷 차이는 작은 Array/Object(회당 ~8개)뿐이며 메시·지오메트리·컨트롤은 없습니다 — 이 잔여분의 출처는 **확인하지 못했고**(React/R3F 내부 캐시로 추정), 메모리 누수라고 단정하지 않습니다.
회귀 방지: `gizmoLifecycle.test.ts`(drei TransformControls 직접 사용 금지, dispose 보장, 외곽선 해제) + 벤치 `ASSERT=1`(회당 50 KB·리스너·지오메트리 증가 시 실패).

## 3. Building Creator UI (KO/EN)

왼쪽 패널 **건물** 탭:
* 선택 없음 → **새 건물**: 프리셋 6종, 매개변수 폼(SI 단위), 실시간 구조 해석 요약·경고, **배치**(고스트 → 클릭, 브러시/선형/영역도 가능).
* 모듈형 건물 선택 → **건물 편집**: 매개변수 변경은 **미리보기**(문서 미변경, 뷰포트에 초안 표시) → **적용/취소**, 층 추가/제거, **부재 편집**, 기초 정책, 지지 없는 부재 허용, 새 건물.
* 레거시 건물 선택 → **부재 모델로 변환**(명시적) + 변환 보고서.

**건물 부재 편집 모드**(도구 `'building'`, 다른 도구와 입력 분리): 상단 도구 막대(부재 종류별 추가, 이동/회전, 격자·층·구조 접합점 스냅, 내부 보기, 하중 경로, 층 단면, 복제, 삭제, 완료), 부재 클릭 선택(Shift 다중), 기즈모(드래그 1회 = 실행 취소 1단계), 단축키(Delete, Ctrl+D, Ctrl+A, W/E, R 회전, X, H, Esc 단계 종료).
건물 전체 선택(기존 선택 도구: 오브젝트 기즈모·그룹)과 부재 선택(이 모드)은 서로 다른 도구라 조작이 섞이지 않습니다.

**다중 선택 크기 조절**(Phase 16 미지원 → 확장): 선택 중심 기준 균일 크기 조절, 실행 취소 1단계. 모듈형 건물은 그룹과 함께 이동하지만 크기는 유지 — 크기는 설계 매개변수이므로 건물 탭에서 바꿉니다(인스펙터에 안내). 부재 다중 선택은 이동·수직축 회전·재료·역할·기존 손상 일괄 변경을 지원하고, 부재 치수는 단일 부재의 수치 입력으로 바꿉니다(단면 크기가 곧 강성·강도라 드래그 스케일로 암묵 변경하지 않음).

## 4. Parametric Building System

`BuildingSpec`: 폭·깊이(m), 층수, 기준층/1층 높이(m), 지붕(평·박공·외쪽)+경사(°), 구조형식(RC 골조·철골 골조·조적·목구조), 주구조/바닥/외장 재료, 외관 형식(개별창·띠창·커튼월), 창 면적 비율, 기초(독립·전면·말뚝), 기둥 간격 목표(m), RC 코어벽, 최상층 천장 슬래브, 용도(적재 질량), 색, 간판, 옥상설비.

* 검증(`validateSpec`): 숫자 아님·0 이하·범위 밖·비정수·높이>150 m·비구조 재료(유리/경량 외장을 구조재로) → **오류**(적용/배치 차단, 조용한 보정 없음). 조적>5층·목조>6층·장경간·1층 과대(연약층)·창 비율 과대(내력벽 약화)·60 m 넘는 골조 무코어 → **경고**.
* 저장 파일 등 외부 입력은 `normalizeSpec`로 기본값/범위 보정(불러오기 경로).
* 생성 규칙(`generate.ts`): 정수 경간 격자, 기둥 크기 = 상부 층 축력/허용응력과 세장비 하한, 보 춤 = 경간/12(RC)·/20(강)·/15(목), 층고·슬래브 두께, 외벽 경간별 패널+창, 1층 남측 문, 지붕·파라펫·박공 단, 기초(독립·띠·전면·말뚝).
* 기존 건물 변환(`convert.ts`): 크기·층수·형식·기초를 그대로 옮기고, 사용자가 바꾼 물성(질량·설계풍속·내구도…)·지진 배율·기초 매개변수는 **수동값으로 유지**, 계산값으로 바뀌는 항목(질량·창 수·감쇠)과 **변환 안 되는 항목**(1층 진열창)을 보고서에 표시.

## 5. Modular Components

`BuildingMember`: 고유 ID(건물 내 고유, 전역 ID = `건물ID/부재ID`), 종류(기초·기둥·보·슬래브·벽·창·문·지붕), 부모 건물(문서 소유 관계), 로컬 변환(위치·Euler 회전), 치수(박스), 재료, 구조 역할, 층, 호스트 벽(창·문), 파사드, 기존 손상(원본 월드 손상 상태).
질량 기여·하중·사용률·강성/강도 기여·변위 용량은 해석이 계산하고(인스펙터 표시), 시뮬레이션 손상은 런타임 상태입니다.

## 7. Simplified Structural Model (`buildings/analysis.ts`)

| 단계 | 방법 |
|---|---|
| 접합 | 부재 AABB가 6 cm 이내로 맞닿으면 접합(y축 sweep-and-prune) |
| 하중 경로 | 종류별 지지 규칙: 기둥·벽 → 바로 아래(≤0.6 m) 수직 부재 우선, 없으면 보·슬래브(전이); 보 → 양 끝의 기둥·벽(보조보만 주보에 걸림 — 교차보 상호지지 순환 금지); 슬래브 → 아래 보·벽·기둥; 지붕 → 아래 부재; 창·문 → 호스트 벽. 지면에서 위로 고정점 반복으로 **지지 여부** 결정 |
| 하중 분배 | 위에서 아래로 자중+받은 하중을 지지 부재에 **같은 몫**으로 전달(지배면적 근사) |
| 사용률 | 기둥: 압괴·오일러 좌굴, 내력벽: 압축×세장 감소, 보: 단순/캔틸레버 휨, 슬래브: 1방향 판 휨 |
| 질량 | 부재 체적×밀도×단면 채움×(1−개구율) + 용도별 적재(주거 150·사무 200·창고 450·공장 300 kg/m², 지붕 50) |
| 층 강성 | 골조 기둥: **Muto D값법** `a·12EI/h³`(a = k̄/(2+k̄), 1층 (0.5+k̄)/(2+k̄), k̄ = 보/기둥 강성비); 벽: 연속 벽체를 균등 횡하중 캔틸레버로 보고 각 층의 처짐 증분/전단(하층 강, 상층 연) + 전단 유연도 1.2h/(G·t·L), 개구부 ×(1−r)^1.5 |
| 층 강도 | 기둥: (상·하단 접합부 모멘트)/h, 접합부 모멘트 = min(기둥, 보 합) — 약한 보는 보 항복 기구; 벽: min(전단, 휨+중력 rocking 0.9NL/2h)·(1−r) |
| 주기 | 층 질량·강성의 전단 사슬, 역반복법; 기준식 `Ct·Hˣ`의 0.6–1.6배로 경계 보정(보정 여부·배율 표시) |
| 기타 | 질량중심, 층 질량, 가장 약한 층(역삼각형 분포 요구 대비), 연약층(<위층 70 %), 비틀림 편심(표시만), 경고 목록 |

**어댑터**(`structuralAdapter.ts`): 층 → ≤5 자유도(5층 이하 1:1, 그 이상은 1층 단독 + 4개 그룹; 그룹 강성 직렬, 강도 최소), 층 변위 = 그룹 변위 × 층 유연도 몫. 감쇠·경화·붕괴변위·손상 임계값은 강성 가중 재료값. `StructuralModel`은 방향별 강성·감쇠·강도의 층별 입력, `scaleStory`(부재 파괴), `truncateFrom`(부분 붕괴)을 추가로 지원합니다.

프리셋 결과(편집 화면 수치): 주택 T 0.21/0.23 s(기준식 0.18) · 아파트 0.37/0.68 s(0.61) · 오피스 1.03/1.48 s(1.20) · 창고 0.22 s · 공장 0.65 s(보정) · 타워 4.98 s(상한 보정, 원시 5.5 s).

## 8. Load Path · Foundation · Terrain

* 지지/비지지 판정, 근사 하중 분배, 접합(맞닿음), 기초 지지, 경고(비지지 = 오류, 과하중·캔틸레버·연약층·횡저항 부재 없음·기초 없음·흙 위 직접 부재 …).
* 부재 편집 모드의 **하중 경로 표시**: 부재→지지 부재 선(사용률 색), 비지지 부재 빨간 상자.
* 지지 없는 부재를 만드는 편집은 확인을 받고(“그래도 적용”), 설계 옵션으로 경고 없이 허용 가능. **시뮬레이션에서는 시작하자마자 떨어집니다**(원본 월드에서 과하중인 부재도).
* 기초–지형 접촉(`foundation.ts`): 평면 7×7 표본, 각 점의 기초 바닥(기초 부재·경사 플린스) vs 지면 → 접촉 비율, 비지지 면적, 근입 깊이(최소·최대·평균), 경사, 매몰, 정적 지지압/허용 지지력(토질×기초 형식).
* **지형 편집 정책**(건물 탭에 표시·설명): *기초 다시 맞춤*(기존 동작) / *월드 위치 유지*(위치·플린스 깊이 고정 → 낮아진 땅은 비지지 면적, 높아진 땅은 매몰). 사용자가 직접 옮기면 새 자리에 다시 맞춤. 지형 편집과 건물 변경은 실행 취소 1단계.
* Phase 16 알려진 문제(경사면 정렬이 재편집 시 사라짐): 배치 시 정렬을 `terrainAlign`으로 저장하고 재안착이 이를 사용 — 해결·테스트.
* 지진 기초 스프링·미끄럼·지지력은 접촉 비율을 반영합니다.

## 9. Wind Integration

* 구조 설계풍속 = 방향별(바람이 x면 깊이×높이 면, x방향 부재 강도) 가장 약한 층 기준 수평 용량에서 계산 → 크기·높이·구조·재료에 따라 달라짐(주택 ~63 m/s, 아파트 ~120 m/s).
* 외장(유리·외장 패널·문·지붕재·파라펫·옥상설비)은 재료별 설계압으로 개별 판정 → **외장 파손과 구조 손상을 구분**(오피스 48 m/s: 외장만 파손, 구조 건전 — 테스트).
* 구조 피로 → 가장 약한 층 부재에 손상 표시, 파괴 시 그 층부터 붕괴(1층이면 전체). 부분 붕괴 후 남은 부분은 노출 높이 비율만큼 하중이 줄어듦.
* 다른 재난의 부재 파괴 → 잔여 강도(reserve)로 바람 하중비 증가.
* 기존 바람 골든 3종 변경 없음.

## 10. Earthquake Integration

* 층별 질량·강성(방향별)·강도로 만든 축약 모델, 기초 스프링(토질·접촉), 층별 변위 재구성.
* 부재 손상 = 층 최대 변위 / 부재 변위 용량(재료 × 축력 비율 감소 × ±25 % 결정론적 편차 × 기존 손상). 파괴 부재 → 강성·강도에서 제거 → 하중 경로 재해석(지지 잃은 부재 낙하, 재분배로 과하중이 된 수직 부재 파괴, 최대 6회) → 수직 용량 40 % 미만 층은 그 위와 함께 **부분 붕괴**(위층은 큰 파편, 충돌체·바람 wake·구조 모델을 그 층에서 절단).
* 창·외장·문은 그 층의 층간변위로, 지붕·간판·옥상설비는 층 가속도로 판정.
* 같은 지진(0.8 g)에서: 목조 주택 균열만, 철골+코어 오피스 붕괴 없음, RC 아파트·공장은 부재 파괴 — **높이나 재료로 정한 규칙 없음**(주기·강도·연성·연약층의 결과). 1층을 높이면 1층 변위 집중(테스트).

## 11. Flood Integration

* 횡수압·흐름 하중 vs **1층 부재 기반 수평 용량**(구조 배율·잔여강도 포함).
* 목재·조적 1층은 침수 시간에 따라 강도 최대 20 % 감소, 빠른 흐름(>1.5 m/s)에서 독립/전면 기초 세굴 감소(근사, 문서화).
* 문·외장 패널이 수압으로 열리면 개구부 → 내부 침수 빨라짐(창 파손과 동일 규칙). **실내 유체 흐름은 시뮬레이션하지 않으며**(내부 수위는 단일 지연 값) 그렇게 표시하지 않습니다.
* 마감재 손상에 외벽 재료 물 민감도 반영(목재 1.3 … RC 0.7).
* 물 솔버 질량 보존 그대로(테스트: 상대 오차 < 1e-9), 결정론 유지.

## 12. Damage Visualization

부재별 색 변화(손상도 → 균열 색), 파괴 부재 숨김 + 파편, 깨진 유리, 외장 탈락 시 내부 골조 노출, 부분 붕괴(위층 큰 파편, 아래층 유지), 전체 붕괴(기존 파편), 기존 균열 표시·응력 색·지진 변형(부재에도 적용), 홍수 젖음 색.
인스펙터는 **외관 균열만 있는 건물**(부재 손상 0, 남은 강도 100 %)과 **강도가 줄어든 건물**(남은 강도 < 100 %, 파괴 부재)을 구분해 보여줍니다. 연쇄 붕괴는 하중 경로 재분배 범위까지만이며, 낙하 충격·동적 연쇄는 Phase 25로 남깁니다.

## 15. Blueprint · Undo / Redo

* Blueprint v1에 `building`(부재·재료·치수·기초 설정·외관·구조 매개변수; 접합은 기하에서 다시 계산)과 `terrainAlign` 추가. 부재 ID는 건물 지역 ID라 사본마다 새 건물 ID로 전역 ID가 새로 정해지고 호스트 참조는 그대로 유효합니다. 부재 복제는 새 `u<n>` ID + 호스트 벽을 함께 복제하며 참조를 재연결합니다.
* 층 추가/제거, 재료, 부재 추가/삭제/이동/회전, 치수, 구조형식, 기초 정책 — 모두 `applyEdit` 1회 = 실행 취소 1단계. 새 객체를 끝까지 만든 뒤 커밋하고 설계 검증(유한·양수 치수, 고유 ID) 실패 시 아무것도 바뀌지 않습니다(테스트).
* 설계는 불변 값: 사본·불러온 동일 설계·시뮬레이션 스냅샷이 같은 객체를 공유(모든 편집 연산이 입력을 바꾸지 않음을 동결 객체로 테스트).

## 20. 과학적 한계 (구조 정확성을 과장하지 않음)

* **사용한 근사**: 부재 상자 + 단면 채움, 지배면적 하중 분배, D값법 골조, 캔틸레버 벽체, 층 전단 사슬(≤5 자유도로 집계), 기준식 대역으로 주기 보정, 층간변위 기반 부재 손상, 재분배 몇 회의 하중 경로 재해석.
* **구조적 가정**: 강막 슬래브(층 내 같은 변위), 비틀림 없음(편심은 표시만), 두 수평 방향 독립, 접합부는 강접(목재 반강접 0.3)/핀(보조 부재), 외장·칸막이는 강성 0, P-Δ는 층 단위.
* **재료 출처**: §6 표 — 공개 기준서의 대표값 반올림, 인증값 아님.
* **유효 범위**: 평면 3–60 m, 1–40층, 구조 높이 ≤150 m, 층고 2.2–8 m. 조적 >5층·목조 >6층·60 m 넘는 무코어 골조는 경고(검증 범위 밖). 높은 골조의 원시 주기는 실제보다 길어(플랜지·슬래브 결합·아웃리거 미반영) 대역 경계로 보정됩니다.
* **설명하지 못하는 파괴**: 전단 취성 파괴의 상세(띠철근), 접합부 파괴, 좌굴 후 거동, 비틀림 붕괴, 낙하 층 충격·팬케이크 연쇄 붕괴, 액상화, 기초 세굴의 지반 역학, 실내 침수 흐름, 화재.
* **기존 모델과의 연결**: 바람 = 같은 풍속장·피로식(용량만 부재 기반), 지진 = 같은 지반운동·`StructuralModel`(층별 입력), 홍수 = 같은 물 솔버·하중식(용량·개구부·재료만 부재 기반), 잔여강도 = 통합 손상 + 부재 reserve.
* **실제 안전성 평가에 쓸 수 없는 이유**: 하중 조합·안전율·상세 규정이 없고, 재료값은 대표값이며, 응력·변형을 부재 내부에서 계산하지 않고, 검증 데이터와 비교한 적이 없습니다. 결과는 **상대적 경향**을 보여주는 교육·실험용입니다.

## 21. 알려진 문제

* ~~1,000동 같은 대량 모듈형 장면은 파일이 큽니다(45 MB)~~ → Phase 18 스키마 v6에서 해결: 공유 설계 테이블 + 파생 `components` 미저장(무손실). 같은 1,000동 장면 47.2 MB → 0.74 MB, 설계가 모두 다른 경우 52.8 → 31.0 MB(docs/ROADS.md §24).
* 부재 회전은 수직축만(지붕 패널 경사는 생성기만). 부재 단면 치수는 수치 입력(드래그 스케일 없음).
* 같은 층 그룹(6층 이상 건물의 2층 이상)은 집계된 자유도로 풀리므로 부분 붕괴가 그룹 경계 층에서 시작됩니다.
* 수동으로 만든 특이 구조(공중 보 전이 등)에서 지지 규칙은 근사이며 판정이 직관과 다를 수 있습니다(하중 경로 표시로 확인).
* 선택 반복 시 회당 ~3 KB 잔여 증가 → Phase 18에서 힙 스냅샷 차이로 분석: 새로 남는 노드의 대부분은 V8 JIT 코드(InstructionStream·deopt 데이터)와 Blink 페인트/레이아웃 캐시이며 앱 객체는 회당 ~0.15 KB. 1,200회까지 GC 후 힙 증가가 회당 6.5 → 1.0 → 0.23 KB로 수렴(누수 아님) — docs/ROADS.md §24.
* 매개변수 미리보기 중에는 층 추가/부재 편집 버튼이 비활성(적용/취소 후 사용).
* 벤치마크는 다른 작업으로 부하가 높은 머신에서 측정했습니다.
