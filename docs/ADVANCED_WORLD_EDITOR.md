## 1. Phase 36 목표

코드나 좌표 입력 없이 3D 화면에서 도시와 자연을 정밀하게 만들고, 재난을 배치해 실행하고, 원본으로 돌아와 고쳐 다시 실행하는 흐름을 끊김 없이 만드는 것.
기능 수보다 그 흐름의 완성도와 물리 엔진과의 정합성이 기준이었습니다. 원칙은 세 가지였습니다.

- **있는 것을 고쳐 쓴다.** 지형·도로·건물·Blueprint·선택·변형 도구는 Phase 16–35.5에 이미 있었습니다(감사 §1). 새 이름의 중복 도구를 만들지 않고, 빠진
  부분과 결함만 고쳤습니다. 새 모듈은 입력 소유권(`editor/input/`), 스냅(`editor/snap/`), 피킹(`editor/pick.ts`), 수치·속성 규칙(`editor/build/numericTransform.ts`,
  `propertyCopy.ts`), 아웃라이너, 자동 저장, 구조 충돌체·층 변위·가새처럼 없던 기능뿐입니다.
- **문서와 런타임의 분리를 지킨다.** 시뮬레이션은 여전히 `WorldDocument`를 바꾸지 않고, 리셋하면 원본입니다(Chrome S17).
- **옛 결과를 지킨다.** 구조 설정이 없는 파일(v1)의 물리 결과는 비트 동일해야 하고(§21), 물리를 바꾸는 수정은 구조 v2에서만 켜집니다.

## 4. 편집 아키텍처

```
  포인터·키보드 ─► 입력 정책(app/inputPolicy.ts) ─► 활성 도구 하나 ─► 제스처(editor/input/gesture.ts)
                         │                              │                    │  └ 카메라 잠금(소유, cameraLock.ts)
                         │                              └► 스냅(editor/snap) └► 트랜잭션(worldStore begin/commit/cancel)
                         └► 선택 초점 하나(객체 | 재난 핀)                              └► 실행 취소 한 기록(지형·도로·객체·재난)
  WorldDocument(편집 문서) ──시작──► SimulationRuntime(복사본) ──리셋──► 원본 그대로
```

편집은 모두 `worldStore`의 기존 한 단계 편집(`applyEdit`)과 새 트랜잭션을 거칩니다. 연속 편집(기즈모·필드 끌기)은 `beginTransaction` → `{ history: false }` 쓰기 →
`commitTransaction`(변화가 있으면 한 단계, 없으면 없음) 또는 `cancelTransaction`(시작 전 객체 복원)입니다. 지형 획은 기존 begin/end에 `cancelTerrainStroke`를 더했고,
획 상태는 이제 저장소마다 따로입니다(템플릿을 만드는 임시 저장소가 앱의 획을 지우던 문제).

## 6. 입력 소유권

**카메라 잠금**(`editor/input/cameraLock.ts`): OrbitControls의 `enabled`를 접근자로 바꿔 "잠금을 가진 소유자가 없음"을 돌려주고 직접 쓰기는 무시합니다. 전에는 6곳이
`enabled`를 주인 없이 썼고 마지막에 쓴 쪽이 이겼습니다. drei `TransformControls`의 `dragging-changed` 쓰기는 무시되고, 그 대신 기즈모 래퍼가 소유 잠금을 겁니다.

**제스처**(`editor/input/gesture.ts`) — 모든 끌기에 같은 규칙:

| 끝나는 방식 | 결과 |
|---|---|
| 포인터 놓음, 버튼 없이 움직임(놓음을 놓친 경우) | 확정(한 단계) |
| 창 포커스 잃음, 탭 숨김 | 확정 |
| Esc | **취소** — 키는 더 가지 않음(선택 해제·도구 나가기와 겹치지 않음) |
| pointercancel, 언마운트, 모드 전환, 문서 교체 | 취소 |

적용: 객체·그룹·부재 기즈모, 상자 선택, 지형 획, 대량 브러시, 영역 그리기, 도로 노드/제어점, 지형 요소 손잡이, 숲 칠하기, Blueprint 캡처 사각형, 재난 핀 드래그.
전에는 도구마다 규칙이 달랐습니다(지형은 Esc에 확정, 숲은 버림, 기즈모·핀은 Esc·blur 무시, pointercancel은 아무도 처리 안 함).

**입력 정책**(`app/inputPolicy.ts`): 재난 배치를 무장하거나 핀을 고르면 편집 도구를 나가고 객체 선택을 비웁니다. 반대로 편집 도구를 켜면 배치가 해제됩니다. 객체를
고르면 핀 선택이 풀립니다("핀 선택 → 건물 선택 → Delete"가 재난을 지우던 문제). 오른쪽 패널을 닫으면 배치가 해제됩니다. 모드 전환·문서 교체 때는 제스처·잠금이 정리됩니다.

**단축키**(`app/hotkeys.ts`, `editor/input/keys.ts`): 글자·괄호는 물리 키(`e.code`)로 읽습니다. 한글 입력기 상태에서도 단축키가 듣고, Shift+[ / ]도 동작합니다.
조합 중(`isComposing`), 입력란, 모달 대화상자가 열린 동안, 드래그 중에는 단축키가 동작하지 않습니다. 피커의 Esc/Backspace는 캡처 단계에서 처리하고 멈춥니다.

**개발 서버의 기즈모**: React StrictMode가 마운트 직후 정리 함수를 한 번 돌리면서 래퍼가 살아 있는 기즈모를 dispose했습니다. 그래서 `npm run dev`에서는 Phase 17부터
기즈모 손잡이를 잡을 수 없었습니다(프로덕션 빌드는 정상). dispose를 한 작업 늦추고 재마운트가 취소하게 했습니다.

## 8. Transform Gizmo

기즈모는 여전히 drei `TransformControls` 하나(`ManagedTransformControls`)이고 쓰는 곳은 셋(객체·다중 선택·부재)입니다. 바뀐 것:

- 드래그 = 제스처 + 트랜잭션: 놓으면 한 단계(움직이지 않았으면 단계 없음), Esc·pointercancel·언마운트는 시작 전 변형 복원.
- 다중 선택·부재 회전의 방향을 쿼터니언에서 읽음: 120°가 60°로, 180°가 0으로 확정되던 오류.
- 이동은 스냅 엔진을 거침(§9): 잡은 축만 바뀌고(X 화살표는 X만), 방향은 바꾸지 않음.
- 잠긴 객체에는 기즈모가 나타나지 않음.

Q로 월드/객체 축을 바꾸고, X·Y·Z로 그 축의 손잡이만 남깁니다(다시 누르면 해제, 뷰포트 힌트에 표시). 객체 축에서 한 축 손잡이를 끌 때는 월드 스냅을 하지 않습니다(축 제약이 깨지므로).

**수치 편집**(인스펙터 `TransformSection`, 규칙은 `editor/build/numericTransform.ts`):

| 칸 | 단위·규칙 |
|---|---|
| 위치 (m) | x·z는 월드 정사각형 안(±100 m)으로 제한하고 알림, NaN·무한대는 거부. y는 지형 최저 −40 m부터(전에는 0 미만 불가) |
| 지면 위 높이 (m) | y − 그 자리의 앉힘 높이. 배치·기즈모와 같은 규칙 |
| 회전 (°) | X 기울기 · Y 방향 · Z 기울기(YXZ 순서) — 120° 방향이 (180, 60, 180)이 아니라 (0, 120, 0)으로 보임 |
| 크기 (배) | 0.1–10 |
| 지면에 놓기 / 경사 따르기 | 앉힘 자세(높이 + 경사면 기울기) / `terrainAlign` 1·0을 한 단계로 |

라벨을 끌어 바꾸는 것(scrub)도 트랜잭션이라 한 단계입니다. 화재·열 미리보기가 `rotation[1]`을 방향으로 읽던 곳은 전체 회전에서 방향을 읽게 고쳤습니다.

- 앞 순위 후보가 허용 거리 안에 있으면 이깁니다. 직전 대상은 허용 거리의 1.6배까지 유지해(히스테리시스) 경계에서 커서가 튀지 않습니다.
- 도로 접면·차선 스냅은 도로까지의 거리와 방향을 정합니다. 도로 방향으로는 이웃과 맞닿게 한 번 더 맞출 수 있습니다(Chrome S3에서 찾아 고침).
- 표시: 뷰포트 힌트에 "⌖ 스냅: 도로 접면 …"(글자 + 기호, 색만이 아님), 땅에 고리 + 기둥 표지.
- 바닥면은 설계 치수가 아니라 실제 부재 범위로 잽니다(주택 8 m 설계 → 8.4 m 바닥면).

## 10. 정렬

다중 선택 인스펙터: 정렬 **기준을 고름**: 원점(피벗, Phase 16 그대로) 또는 바닥면(경계: 최소·최대 = 가장자리 맞춤, 중심 = 바닥면 중심, 회전 포함)입니다.

- X·Z 최소·중심·최대, 원점 간격 균등 분배(기존), **바닥면 사이 간격 균등**(새, 처음·끝 고정)
- **기준 객체에 맞추기**: 같은 방향(경사면이면 다시 앉힘) / 같은 지면 위 높이(각자의 지면 기준) / 같은 크기
- **속성 복사**(§20 of spec, `propertyCopy.ts`): 크기·방향·매개변수(같은 종류)·물리(같은 종류)·구조(건물: 지진 특성 또는 부재 재료 → 구조 형식). 맞지 않는 쌍은
  건너뛰고 건수를 알림. 모듈식 건물의 크기·매개변수는 설계가 정하므로 복사하지 않음.

땅에 선 객체는 정렬 뒤에도 다시 앉힙니다. 도로에 연결된 객체는 움직이면 연결을 그 자리에서 다시 잽니다(`relinkMoved`). 길이 근처에 없으면 연결을 끊습니다. 전에는
옛 연결이 남아, 다음 도로 편집 때 옛 자리로 튀었습니다. 복제본도 원본 자리로 튀었습니다.

## 12. 지형

### 브러시 미리보기 (§22)

`previewDab` (`src/terrain/TerrainEditor.ts`)는 브러시 사각형 + 테두리 1점(다듬기·침식이 읽고 쓰는 범위, 실제 격자처럼 가장자리에서 잘림)을
임시 격자로 복사해 **실제 `applyDab`**을 1 s 분량 실행합니다: 20 × 0.05 s(완화형 브러시는 시간에 선형이 아니므로 프레임 크기 단계), 칠하기는 1회.
문서는 쓰지 않습니다. 시험: 9개 연산(올리기·내리기 사각+하한·평탄 flat·다듬기·고원·능선·계곡+상한·노이즈+시드·침식)에서 실제 20회 적용과 **정확히 같음**.

| 표시 | 내용 |
|---|---|
| 열 지도 | 지면에 드레이프, 예상 Δh: 올림 = 주황, 내림 = 파랑, 불투명도 ∝ \|Δh\| / 최대 \|Δh\| |
| 칠하기·토양 | 실제로 칠해질 꼭짓점만 그 지표 색 |
| 외곽선 | 실제 모양(사각 브러시 = 사각형, 최대 노름), 칠하기는 실제 칠하는 중심부 반경 r × (0.35 + 0.6 × 강도) |
| 평탄·고원 | 목표 높이의 수평 고리(반경 r/2) — 누르기 전엔 커서 높이, 누른 뒤엔 누른 점 높이 |
| 경사 | 누른 상태에서 A(누른 점) → B(커서) 직선 |
| 패널 | "미리보기(커서에서 1초): 최대 +x / −y m · 면적 z m²" |

갱신 ≤ 10 Hz(커서 0.1 m 이동·설정·지형 변경 시), 누르고 있는 동안은 숨김(실제 변화가 보임). 경사 도구는 누르기 전 A = B라 평탄으로 미리 봅니다.

## 15. 구조부재·가새

교육용 **축력 모델**입니다. 층 모델에 자유도를 더하지 않습니다(`buildings/brace.ts`).

| 항목 | 모델 | 근거 |
|---|---|---|
| 연결 | 두 **끝점**(중심 ± R·[L/2, 0, 0])을 6 cm 오차 안에 담는 부재에 연결합니다. 우선순위는 기둥 > 벽 > 보 > 기초 > 바닥판이고, 연결 형식은 거싯(`CK.GUSSET`, 용량 1.1·f_y·A)입니다. | 기울어진 상자의 AABB는 칸 전체를 덮어서, 접촉 규칙으로는 잘못된 연결이 생깁니다(감사 §5). |
| 중력 | 가새는 아무것도 받치지 않습니다. 자중은 두 끝 부재가 절반씩 받고, 질량은 잇는 두 층에 ½씩 나눕니다(기둥과 같음). | 해석기는 지지점들에 하중을 균등 분배합니다. |
| 강성(가새 1개) | k = E·A·cos²α / L / 2(평면 방향, 수평각 ψ로 x/z 분해) | **인장 전용**: EN 1998-1 §6.7.2는 X형 가새에서 인장 대각재만 해석에 넣고, §6.7.3은 세장비 λ̄를 1.3–2.0으로 둡니다. 대칭 층 스프링에서 가새 하나는 주기의 절반만 인장이라 ½입니다. |
| 강도(가새 1개) | V = (f_y·A + 0.3·N_cr)·cos α / 2 | 좌굴한 짝의 잔존 압축 0.3·N_cr(ASCE 41 / FEMA 356 정도)을 포함한 쌍 강도의 절반 |
| 좌굴 | θ_cr = (N_cr/EA)·L / (Δy·cos α) → 손상 ≥ 0.5(DAMAGED, 층 강성 ×0.8) | 층 변위 θ에서 축 변형률 ε = θ·Δy·cos α / L |
| 파단 | θ_u = ε_u·L / (Δy·cos α)를 변위 용량으로 둡니다(산포 ±25 %). ε_u는 강재 1 %, 목재 0.4 %, 그 밖 0.3 %. | 시험된 중심 가새의 파단 층 변위 2–3 %와 맞습니다. |
| 층 기여 조건 | 두 끝 부재가 지지되어 있고 연직 길이가 층 높이의 0.5–1.25배일 때만 셉니다. 시뮬레이션에서는 두 끝 부재가 모두 서 있을 때만 셉니다(`modular.ts` `braceHeld`). | 수평 가새(지붕면)나 두 층에 걸친 가새는 층 전단에 그대로 넣을 수 없습니다. |

**주기 보정**: 가새가 있는 방향은 따로 코드 주기를 씁니다. 가새 골조는 ASCE 7-16 표 12.8-2의 "그 밖의 구조"로 C_t = 0.0488, x = 0.75이고
(EN 1998-1 §4.3.3.2.2 C_t = 0.05), 모멘트 골조는 0.0724·H^0.8입니다. 그 방향 층 강성 중 가새 몫으로 둘 사이를 섞습니다(`analysis.ts` `braceShare`).

## 15b. 부분 붕괴 충돌체

`settings.simulation.structure = { model: 'v2' }`일 때만 씁니다. v1은 Phase 17의 상자 하나를 유지하고, 그 상자는 층 전체가 무너질 때만 잘립니다.
코드는 `simulation/structure/colliders.ts`(순수 함수)와 `cellCollider.ts`(교체)입니다.

- **셀**: 층 × 칸입니다. 칸은 설계의 칸 격자(`planGrid`, 축척 적용)이고, 바깥 칸은 부재 범위까지 늘린 뒤 전체를 원래 충돌 상자 안으로 자릅니다.
  층 경계는 해석의 층 바닥 높이입니다.
- **고체 규칙**:
  (a) 그 층(천장) 레벨의 살아 있는 바닥판이 셀 중심을 덮습니다.
  (b) 설계에 바닥판이 없는 셀(홀, 천장 없는 최상층)은 그 층의 살아 있는 구조 기둥·벽이 셀 안에 있습니다.
  (c) 엔진에 남은 부재(낙하·정지, 외부로 넘기지 않음)가 지금 그 셀을 차지합니다.
  붕괴된 층부터 위는 언제나 비어 있습니다(truncate와 같음).
- **정지 0.3 m 규칙**: 정지한 잔해는 밑면에서 0.3 m 위(바닥판 두께 정도)부터 셀을 차지합니다. 보 위에 남은 기둥 찌꺼기는 위층에 속합니다.

- **병합·상한**: 층마다 행 단위로 직사각형을 만들고, 같은 직사각형이 연속된 층이면 쌓습니다. 온전한 건물은 상자 하나입니다.

**Chrome 결과(구조 실험장 RC 건물, 모서리 폭발)**

| 에너지 | 구조 | 충돌체 |
|---|---|---|
| 1.2·10⁹ J | 기둥 9개, 바닥판 5개 파괴 | 셀이 하나도 열리지 않습니다. 무너진 부재가 셀 안에 정지해 있고(규칙 c), 캔틸레버로 남은 바닥판이 그 층 셀을 붙잡습니다(규칙 a). |

반대 방향의 오류, 즉 서 있는 구조 속으로 몸체가 들어가는 일은 일어나지 않습니다(셀은 꺼지기만 하고, 꺼지는 조건은 구조가 그 자리에 없을 때뿐).

## 25. 과학적 한계

- 모두 교육용 축약 모델입니다. 실제 건물·도로의 성능을 예측하지 않습니다.
- 편집 정밀도: 수치 칸은 cm 단위(소수 2자리)로 보이고 내부는 배정밀도입니다. 지형·도로·충돌체는 1 m 격자, Rapier는 f32 위치입니다.
- 스냅의 바닥면은 회전한 상자(OBB)이며 실제 외곽선(L자 평면 등)이 아닙니다.
- 폭 전환은 선형 테이퍼(설계 기준의 곡선형 변이 구간·차로 감소 표지 아님), 직선 차수 2 접합에만. 마이터는 평면 형상만(편경사·완화곡선 없음).
- 지형·충돌체는 1 m 격자: 연석은 한 칸 안에서 경사로, 테이퍼의 비스듬한 연석은 격자에 계단처럼 굽힘.
- 브러시 미리보기는 "커서를 1 s 그대로 둔 경우" — 끄는 동안의 실제 변화는 경로·속도에 따름.
- 지면 추종은 분류별 규칙(기초·지반 접촉 해석이 아님 — 그것은 Phase 17 기초 접촉 모델).
- 숲 입지는 규칙 거르기(지표·토양·물·도로·경사·고도) — 생태·성장·일조 모델 없음.
- 셀 충돌체: 층 × 칸 단위 고체이며 실내 공간·보는 표현하지 않습니다. 정지 잔해는 0.3 m 규칙에 따른 셀 점유로 근사합니다.
  엔진의 낙하 블록은 Rapier 몸체와 부딪히지 않습니다(규칙 c로만 막음).
- 가새: 축력 부재의 층 강성·강도·변위 한계이고 접합부 강성 행렬은 아닙니다. 인장 전용 강성, 좌굴은 손상 단계, 파단은 평균 축 변형률 한계입니다.
  층 2선형 스프링이라 핀칭 이력은 없습니다.
- 층별 변위 표시: 층 모델(≤ 5 자유도) 변위를 층에 나눠 그릴 뿐 부재 휨을 그리지 않습니다. 비틀림 회전은 없습니다.
- 잔해 표현: 시각 계수일 뿐 파편 크기 분포·먼지 질량의 물리 모델이 아닙니다.
