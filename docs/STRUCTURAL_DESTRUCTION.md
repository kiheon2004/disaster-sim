# Phase 25 — Advanced Structural Destruction, Progressive Collapse & Debris Physics

사용자가 만든 모듈형 건물(Phase 17)이 재난으로 손상될 때 **부재 단위의 파괴, 하중 재분배, 연쇄·부분 붕괴, 낙하 잔해, 2차 피해**가
계산되도록 하는 구조 파괴 엔진입니다. **구조공학 설계·안전 진단·붕괴 예측용 인증 도구가 아닙니다**(§37).
계산값과 시각적 근사를 구분해 표시합니다.

> 이 문서는 구현 전에 작성한 분석(§1–§2)과 설계(§3)로 시작해, 구현·측정·검증 결과(§4–§39)로 채웠습니다.

### 1.2 Phase 24 외벽 파괴가 구조 연결을 바꾸는가?
예 — 외벽(내력벽)이 면외로 파괴되면 `failMembers`로 같은 하중 경로 재해석을 거칩니다(지지를 잃은 위 부재 낙하, 수직 부재 과하중 파괴).
그러나 (1) 보·슬래브·접합부 과하중은 검사하지 않고, (2) 층 붕괴는 40 % 경험 규칙에 의해 즉시 일어나며, (3) 낙하가 아래층에 주는 충격은 없습니다.

### 1.3 이번 Phase에서 새로 필요한 것
1. 명시적 **구조 그래프**(부재·접합부·지지 관계·대체 지지 경로)를 설계당 한 번 만들고 공유.
2. **증분 하중 경로 해석**(변화한 영역만): 지지 상태는 아래→위, 하중은 위→아래로 변화량만 전파.
3. 모든 하중 부재(보·슬래브 포함)와 **접합부**의 수요/용량 검사, 갑작스러운 손실의 **동적 증폭**.
4. 파괴와 낙하의 분리: **낙하 블록의 시간 전개**, 아래층 충돌의 **운동량·에너지 수지**로 정지/연쇄 판정.
5. 질량이 보존되는 **잔해**(Rapier 조각 / 집계 잔해 더미 / 구조 내부에 쌓인 잔해) 장부.
6. 잔해 → 건물 부재·차량·사람·도로의 **2차 피해**와 원인 사슬 기록.
7. 지반 변형 → **기초 부재 지지 상실**.
8. 인스펙터·오버레이·타임라인·결과·편집 미리보기.

파이프라인에서의 위치: 지반 운동·구조 응답(Phase 13) → 해저드별 손상 평가(지진·바람·홍수·지반·운석·압력파) → **StructuralCollapseSystem**(재분배 1라운드, 낙하·충돌, 기록, 파편·잔해) → 파편 정리(DebrisSystem).
해저드는 **언제** 부재가 손상·파괴되는지를 계속 결정하고(기존 모델 유지), 엔진은 그 결과가 구조 전체에 **어떻게** 퍼지는지를 계산합니다. 엔진이 생기기 전과 같은 입력 경로(`failMembers`, `collapseFrom`, `modularCollapse`, 원본 월드 비지지 부재)가 모두 엔진을 거칩니다.

**비용 원칙**: 건물의 구조 상태는 처음 무언가가 바뀔 때 만들어지고(`structureOf`), 할 일이 있는 건물만 활성 목록에 있습니다. 파괴가 없는 장면에서는 시스템이 비활성(비용 0)입니다(§33).

## 4. 구조 그래프 (`graph.ts`)

- **설계 단위·공유**: 그래프는 설계(불변)와 스케일로 결정되므로 `WeakMap<설계, Map<스케일, 그래프>>`에 한 번 만들고 같은 설계를 쓰는 모든 건물이 공유합니다. 런타임 상태(손상·상태·하중)는 건물별 `CollapseModel`/`StructuralSolver`에만 있습니다 → 설계와 그래프는 절대 쓰이지 않습니다(테스트: 공유 설계 복사본 독립).
- **부재 데이터**: 종류(기둥·벽·보·슬래브·지붕·기초·창·문), 역할, 층, 박스, 질량·무게, `structural`(구조 역할 + 구조 재료), `lateral`, 용량, 지면 접촉 여부.
- **지지 후보 단계(tier)** — Phase 17 `analyzeBuilding`과 같은 종류별 규칙이지만 **모든 대안을 보관**하므로, 파괴 후 하중 경로는 기하를 다시 계산하지 않고 단계를 바꿔 찾습니다:

| 부재 | tier 0 | tier 1 | tier 2 | 그 밖 |
|---|---|---|---|---|
| 기둥·벽 | 아래 수직 부재(기둥·벽·기초) | 아래 보·슬래브(전이) | (비내력벽만) 골조에 매달림 | 바닥이 지면이면 흙 위 |
| 보 | 걸리는 기둥·벽, (2차 보) 1차 보 | | | |
| 슬래브 | 바로 아래 보·벽·기둥 | | | 지면 슬래브: 지반 |
| 지붕 | 평면 아래 부재 | 접하는 아래 부재 | | |
| 창·문 | 호스트 벽 | 접하는 다른 벽 | | |
| 기초 | 지반(지반 지지율) | | | |

- **연결(접합부)**: 후보 간선 하나가 하나의 하중 전달 연결이며 종류(`CK`)와 전달 용량을 가집니다(§6).
- **위상 순위**: 지지 부재가 항상 지지받는 부재보다 낮은 순위 → 지지 패스는 아래→위, 하중 패스는 위→아래로 한 번에 처리.
- **평면 격자(2 m)**: 낙하 블록 아래에 무엇이 있는지, 파편이 어떤 부재에 닿았는지 찾는 데 사용.
- **장식 부재와 구조 부재의 구분**: 외장·칸막이·창·지붕 마감은 질량과 하중 경로(매달림·얹힘)를 가지지만 `structural = 0` → 아무것도 지지하지 않고 중력 용량 검사를 받지 않습니다. 장식을 위한 예외 규칙은 없습니다.
- **기존 설계 호환**: 그래프는 기존 `BuildingDesign`(v1)만으로 만들어지며 새 필드를 요구하지 않습니다. 원본 월드에서 이미 파괴된 부재(초기 손상 1)는 `ABSENT`.
- **Phase 17 수정**: 슬래브가 이웃 칸의 같은 선상 보에 **모서리만 닿아도** 지지되던 규칙 오류(초기 접합부 사용률 > 1)를 `slabBears`로 고쳤습니다(분석·그래프 공통).

초기 상태는 Phase 17 분석과 **정확히 같습니다**(지지 여부·하중; 프리셋 전부 테스트). 보의 휨은 엔진이 하중 위치를 쓰므로 분석(등분포 가정)보다 작거나 같습니다.

## 5. 부재 상태 (`types.ts`)

```
INTACT ─(D ≥ 0.3)→ DAMAGED ─(D ≥ 0.7)→ SEVERE          (하중을 계속 받음, 용량 F·(1 − 0.3·D))
  └──────────(용량 초과 / 지지 상실 / 접합부 파괴 / 충돌)──────────→ FAILED (하중 안 받음)
FAILED → DETACHED (같은 스텝, 접합 해제)
DETACHED → FALLING (건물 내부 낙하 블록, 또는 평면 밖이면 Rapier 파편 / 집계 잔해)
FALLING → RESTING (아래층 위에 정지: 그 층의 정적 하중) | SETTLED (지면: 잔해 더미 / 정지 파편)
RESTING → FALLING (받치던 층이 나중에 무너지면 다시 낙하)
ABSENT: 원본 월드에서 이미 없음
```

- 모든 전이는 `canTransition`을 통과합니다(허용되지 않은 전이는 예외 — 테스트).
- **DETACHED 이후 부재는 하중을 받지 않습니다**: 해석기에서 `alive = 0`, 연결 전달 0. 쉬고 있는(RESTING) 잔해는 **무게만** 받치는 부재에 정적 하중으로 더해집니다(구조 부재로 돌아가지 않음).
- 부재별 기록: ID(설계 부재 id), 재료·기하(그래프), 용량(축·휨·전단·접합부), 수요(축·휨·전단 사용률, 마지막 평가), 손상 지수, 잔여 강도 계수, 연결 상태(간선 alive), 파괴 원인·시각·유발 부재·연쇄 뿌리·깊이·주 해저드, 2차 피해면 타격 파편·출처. 인스펙터에서 모두 볼 수 있습니다(§25).

- **상세 접합부 역학(볼트 군, 용접 목, 철근 정착, 패널 존)은 계산하지 않습니다.** η는 문서화된 판단값이며, 결과 화면·인스펙터에는 연결 종류와 전달 하중/용량만 표시합니다.

## 7. 부재 파괴 기준

| 부재 | 성분 | 용량 (Phase 17 재료표만 사용) |
|---|---|---|
| 기둥 | 축(압괴·좌굴) | min(f_c·A_eff, π²·E·k·I/h²) (= Phase 17) |
| 내력벽 | 축 × 세장비 | f_c·t·L·fill·(1−개구율)·max(0.3, 1−(h/t/40)²) (= Phase 17) |
| 보 | 휨 / 전단 | f_m·S·inertiaFill / v_m·A_v (RC 1.5 MPa·b·0.9h, 강 205 MPa·0.4A, 목재 4 MPa·⅔A, 조적 0.3 MPa) |
| 슬래브 | 1방향 판 휨 / 캔틸레버 | f_m·t²/6·fill (m당) |
| 기초·지면 슬래브 | 지지력 | 원본 월드 정적 지지비 기준, q_ult = 3·q_a, 지지율 f면 압력 1/f배 |
| 연결 | 전단 전달 | §6 |

- **수요**: 하중 경로 해석으로 계산한 축력, 보의 **하중 위치를 반영한** 휨·전단(지지점 사이 단순 지지, 한쪽 지지면 캔틸레버), 슬래브 판 휨, 연결 전달량.
- **판정**: 사용률 u = 수요 / (용량 × 잔여 계수) ≥ 1.25. 화면에는 **계산된 성분만**(축·휨·전단·연결·지지력) 표시하고, 계산하지 않는 성분(비틀림, 국부 좌굴, 피로 균열 등)은 표시하지 않습니다.
- **갑작스러운 손실의 동적 증폭**(GSA 2016 비선형 정적 절차): Ω_N = 1.04 + 0.45/(θ_pra/θ_y + 0.48), 재료 파괴 거동별 θ 비 연성 4(Ω ≈ 1.14)·준연성 1.5(≈ 1.27)·취성 0(≈ 1.98). **증가분에만** 적용, 서서히 늘어나는 하중(쌓이는 잔해·지반 지지 저하)은 증폭하지 않습니다.
- **횡력 파괴**: 층간변위(지진·압력파 충격·운석 지반 충격)는 Phase 13/17 층 모델이 부재별 변위 용량(재료 산포 ±25 %)으로 판정 → 원인 `drift`; 층 메커니즘(집약 모델 손상 지수·바람 피로·수압·토압) → `story`; 외벽 면외 SDOF(Phase 24) → `overpressure`.
- 수직 부재가 자기 용량(변위·축·층 메커니즘)으로 파괴되면 그 자리에서 **압괴**(위의 블록 아래에 강체 기둥처럼 남지 않음), 지지를 잃은 부재는 **낙하**합니다.

## 8. 잔여 강도

- 손상 지수 D(0–1, 해저드 무관)의 부재는 중력 용량 **F·(1 − 0.3·D)** — Phase 13 구조 모델 자체 법칙이자 Phase 15 통합 손상 정책(`STRENGTH_LOSS = 0.3`, `structure/policy.ts`에서 공유).
- D는 해저드별 손상의 **포락선(max)**으로 갱신되며 합산하지 않습니다. 같은 손상이 두 번 적용되지 않습니다(테스트: 지진 손상 후 용량이 정확히 F·(1 − 0.3·D) 한 번).
- 낙하 블록을 멈춘 층은 흡수 변형/변형 용량만큼 D가 오르고, 파편 타격을 견딘 부재는 E/W만큼 D가 누적됩니다(소성 일).
- **Phase 26 확장 지점**: `CollapseModel.setMaterialFactor(i, f)` — 손상과 다른 물리량(온도에 따른 강도 저하·재료 열화)을 위한 별도 계수, 잔여 강도와 **곱**으로 조합(두 번째 손상 지수가 아님). Phase 25에서는 아무것도 구동하지 않습니다(§38).

## 9. 하중 재분배 (`solver.ts`)

무작위 제거가 아닌 **그래프 기반 계산**입니다. 변화(부재 제거, 연결 파괴, 지반 지지 변화, 추가 하중, 용량 저하)는 큐에 쌓이고 `propagate()`가 영향 영역만 방문합니다:

1. **지지 패스(아래→위, 순위 힙)**: 바뀐 부재 위에 있는 부재가 지지 단계를 다시 고릅니다(아래 기둥을 잃은 기둥은 접합부의 보 위에 섬 = 전이). 아무 지지도 없으면 구조에서 빠지고(낙하 예정) 그 위로 전파.
   - **수직 연속성(TIER_MERGED)**: 자기 아래 수직 부재가 전이로만 받쳐지는 기둥·벽은 그 수직 부재 **와** 자기 층 접합부의 보·슬래브에 하중을 나눕니다 → 기둥 하나를 잃으면 위의 각 층이 자기 층 보로 자기 하중을 받습니다(골조 작용 근사). 한 층 접합부에 기둥 열 전체가 얹히는 비현실적 결과를 막습니다.
2. **하중 패스(위→아래)**: 방문 부재의 하중 = 자중 + 추가 하중 + 위에서 전달받은 몫, 선택된 단계의 살아있는 지지들에 등분(Phase 17 분담 근사). 몫이 바뀐 연결만 아래로 전파.
3. **검사**: 수요가 바뀐 부재·연결만(§7), 갑작스러운 변화는 Ω 증폭.

- 건물당 **스텝당 재분배 1라운드**(시간 순서가 기록되고 연쇄가 시간에 따라 진행). 초과 부재는 다음 라운드에서 파괴로 처리.
- **증분 = 전체 재해석**: 같은 손실에 대해 증분 결과가 Phase 17 전체 재해석 라운드와 일치(하중·지지, 테스트), 방문 부재 수는 변화 크기에 비례(테스트).
- **여유 용량(reserve)**: 어떤 부재 아래 하중 경로의 첫 부재·연결이 한계에 이르는 추가 정적 하중 — 낙하 블록·파편 타격의 저항에 사용.

## 10. 연쇄 붕괴 (`collapse.ts`, `falling.ts`)

이벤트 구동: 파괴가 있을 때만 그 건물의 모델이 활성. 지역 재해석만 수행.

- 구조에서 빠진 부재들은 지지 그래프의 연결 성분으로 **낙하 블록**을 이룹니다. 블록은 원래 위치 구조물의 수평 속도를 가지며 운동량을 더하지 않습니다.
- **자유 낙하**(정확한 등가속 운동, 공기 저항 없음) → 아래의 서 있는 부재·쉬는 잔해·지면과 첫 접촉(간격 5 cm 이내 동시 접촉).
- **충돌**(Bažant & Verdure 2007, Izzuddin et al. 2008의 에너지 수지 틀에서 축약):
  1. 완전 비탄성 충돌 v' = M·v/(M + m_R), 손실 ΔK = ½·M·v²·m_R/(M + m_R);
  2. 맞은 층은 **여유 정적 용량 P**로 강소성 저항, 변형 용량 δ_u(보·슬래브: θ_u·L/2, θ_u = 재료 기둥 변위각 용량; 축 부재 0.002·h);
  3. P ≤ M'·g → 파괴; 아니면 정지 거리 δ = ½·M'·v'²/(P − M'·g): δ ≤ δ_u면 **정지**(D = δ/δ_u, 블록은 그 층 위에서 RESTING), δ > δ_u면 층 **파괴**, W = P·δ_u 흡수 후 잔속도로 계속(팬케이크 붕괴, 도중에 멈출 수 있음).
  4. 에너지 수지는 정확히 닫힙니다: ½·M·v² + M'·g·d = ΔK + W + ½·M'·v_r² (테스트).
- 기록: 각 파괴의 원인·시각·라운드·유발 부재·연쇄 뿌리·깊이·주 해저드(뿌리의 해저드) → **붕괴 순서**(인스펙터·CSV·JSON).
- 쓸려 내려가는 비구조 부재(외장 등)는 블록 경로에서 압괴되어 블록에 합쳐집니다.

## 11. 부분 붕괴와 분류

분류는 표시용 임계값이며 계산에 쓰이지 않습니다:

| 분류 | 기준 |
|---|---|
| intact / damaged | 파괴 없음 / 손상 부재 있음 |
| local | 구조 부재 파괴, 떨어진 상부 질량 ≤ 5 % |
| partial | 떨어진 상부 질량 > 5 %, 서 있는 상부 ≥ 10 % |
| global | 서 있는 상부 < 10 % |

계산으로 나타나는 부분 붕괴 유형: 단일 기둥 손실 후 국부(전이 보 파괴, 위 골조 재경로 — 테스트), 상층 손실 후 강한 바닥에 정지(가벼운 지붕이 강한 바닥에 멈춤 — 테스트), 모서리·한쪽 칸 붕괴(지반 지지 상실 영역), 외벽만 탈락(압력파), 지붕·최상층 붕괴(지진), 1층 상실 → 전체 붕괴(테스트).

## 12. 붕괴 시간 전개

파괴 이벤트(상태 전이·기록)와 낙하·충돌·정지를 분리합니다. 부재는 즉시 사라지지 않습니다:
파괴 스텝 → DETACHED → 낙하(블록은 엔진 운동학, 평면 밖 부재는 Rapier 파편) → 충돌(정지/관통) → RESTING/SETTLED.
Rapier와의 통합: 평면 밖으로 나가는 부재만 Rapier 동체가 됩니다(§13). 건물 내부 낙하는 엔진이 정확히 계산(동체 수 폭증 방지)하고, 렌더러는 부재를 변위·압축된 위치에 그립니다.

## 13. 잔해 생성

| 종류 | 언제 | 물리 | 질량 |
|---|---|---|---|
| 낙하 블록 | 건물 내부에서 지지 상실 | 엔진 운동학 | 부재 질량 정확 |
| 쉬는 잔해 | 블록이 아래층에 정지 | 그 층의 정적 하중, 집약 지진 모델에 질량 추가(`StructuralModel.addMass`) | 정확 |
| 잔해 더미 | 블록이 지면에 도달 | 고정 충돌체(높이 ≥ 0.3 m 코어), 매몰, 도로 차단 | 정확, 형상은 근사(팽창 1.6, 안식각 37° 둔덕) |
| 파편 | 착지점이 평면 밖(구조물 운동·압력파 충격량·외장 탈락) | Rapier 동체, 다른 모든 것과 충돌 | 부재 질량 정확, 속도는 물려받음(추가 없음) |
| 집계 잔해 | 활성 동체 상한 초과·정지 후 총 상한 초과 | 동체 없음, 더미로 합침 | 정확(장부 이동) |
| 미세 입자 | 유리 | 시각 전용 파편, 질량은 외벽 발치(fines 계정) | 정확 |
| 먼지 | 붕괴·충돌 | **시각 전용**(양 끔/1×/2×, 결과 불변) | 질량 없음 |

- 모든 조각이 Rapier 동체가 되지 않습니다: 건물 내부 낙하는 엔진, 외부 이탈만 동체, 상한(`FRAGMENT_LIMITS` 활성 160 / 전체 600).
- **질량 이중 계산 없음**: 부재 질량은 언제나 장부의 한 계정에만 있습니다(§14). 기존 레거시 덩어리 파편(질량 자름)은 모듈형 건물에 더 이상 쓰이지 않습니다(레거시 건물은 그대로).

## 14. 질량·에너지·운동량 수지 (`ledger.ts`)

- **질량 계정**: structure / falling / resting / bodies / rubble / fines / left / unresolved. 질량은 계정 사이를 **이동**만 하므로 합계 = 원래 질량(부동소수 반올림 이내; 벤치마크 최대 잔차 2.8·10⁻⁸ kg). `unresolved`는 단순화가 놓을 곳을 찾지 못한 질량이며 0이어야 하고 0이 아니면 표시됩니다(모든 벤치마크·테스트에서 0).
- **에너지(J)**: 낙하 블록이 방출한 위치 에너지 = 충돌 손실 + 구조 흡수 + 지면 소산 + 운동 중(테스트: 끝나면 비율 1, 10⁻⁶).
- **운동량(kg·m/s)**: 파편의 수평 운동량 출처 — 구조물 운동에서 물려받음 / 압력파 충격량(Phase 24가 부재에 준 것). 그 밖에는 만들어지지 않습니다.
- 장면 수준: 파편 동체 질량 합 = bodies 계정, 장면 더미 질량 = 모델 더미 질량(테스트).

## 15. 잔해 충돌과 2차 피해 (`secondary.ts`)

- Rapier 접촉력 이벤트 → **타격 에피소드**(같은 파편·대상, 0.5 s 이내 간격) 단위로 평가, **한 번만 기록**(여러 스텝에 걸친 충돌의 중복 기록 없음; 기존 ForceLedger 중복 검사 0 유지).
- 전달 에너지 E = J²/(2m), J = Σ F·Δt(법선 운동을 멈추는 데 필요한 운동 에너지 — 상한).
- **모듈형 건물**: 접촉 부재가 W = P·δ_u(여유 용량 × 변형 용량; 외장은 설계 압력 × 면적 × 변위 용량 × 높이)로 저항. E ≥ W → 파괴(원인 `impact`, 주 해저드 유지, 타격 파편·출처 건물·부재 기록), 아니면 D += E/W.
- **가로등·표지·담장·나무**: 접촉력 × 높이 vs 설계 밑동 모멘트(Phase 23 분출물 검사와 같음) → 전도.
- **차량·사람**: 기존 접촉 피해 모델 유지, 파편이면 2차 귀속 추가. 모듈형 건물이 있는 실행에서는 접촉 피해를 에피소드당 피크로 평가(같은 충돌 여러 번 감산 방지).
- **도로**: 잔해 더미 아래 차로 표본이 ≥ 0.3 m 덮이면(Phase 21 통행 불가 단차) 구간 차단 — 토사 퇴적과 별도 상태, 도로망 자체는 바뀌지 않음.
- **매몰**: 더미 깊이 / 대상 높이 ≥ 사람 0.7, 차량 0.6, 소형 구조물 0.8(Phase 22 기준) → 매몰(원인 `burial`), 몸체 고정.
- 레거시(Phase 0–16) 건물은 부재 모델이 없어 파편 타격을 평가하지 않습니다(한계).

## 16. 잔해 정착

- 파편이 0.5 s(30 스텝) 정지하면 **고정 동체**(솔버 비용 0, 충돌은 유지), 부재 상태 SETTLED.
- 낙하 블록은 지면 도달 시 더미로 정착(질량·에너지 기록), 층 위 정지 시 RESTING.

## 17. 잔해 LOD (Physics LOD)

- 움직이는 파편 최대 160, 전체 동체 최대 600(시험·벤치마크용으로 조절 가능).
- 활성 상한 초과: 새 파편은 **탄도 착지점**에 집계 잔해로 놓임. 전체 상한 초과: 가장 오래된 정지 파편을 그 자리의 잔해 더미로 합침.
- 집계된 잔해도 질량·면적을 유지하므로 **도로 차단·매몰 계산에 그대로 포함**됩니다. 조용히 지우는 경로는 없습니다(기존 320개 상한의 "가장 오래된 잠든 조각 제거"는 레거시 파편에만 남고, 그 질량은 `legacyRecycled`로 집계).
- 집계 위치의 기존 더미는 4 m 격자 색인으로 찾고(더미 수와 무관한 비용), 건물·더미 번호로 같은 더미를 다시 찾는 조회는 맵, 높이 조회용 8 m 버킷은 더미가 바뀔 때 증분 갱신합니다 — 1000동 압력파에서 더미 약 3000개를 파편마다 훑던 비용이 사라짐(§33.4).

## 18. 지반·기초 연동 (`foundation.ts`)

- Phase 21은 발자국 아래 지반 변위에 맞춘 평면으로 건물을 강체 이동·기울이고 각변위를 평가합니다(유지). 강체 운동이 따라가지 못하는 **국부** 변화 — 맞춘 기초면보다 5 cm 넘게 내려간 곳, 명시적 지지 상실(싱크홀 천장·크레이터) — 은 그 위 **기초 부재**의 지지 상실입니다.
- 지면에 놓인 각 부재(독립 기초·매트·지면 슬래브·흙 위 부재)가 자기 발자국(중심 + 모서리 90 % 4점)을 표본화: 지지율 = (접촉 점/5) × 명시적 지지 배수 평균.
- 지지율 < 5 % → 지지 상실(그 부재와 그것만 받치던 것이 하중 경로를 잃음), 그 외 지지력 압력 1/f배(극한 지지력 검사). 슬래브 위 기둥은 뚫림 전단도 검사(기초를 잃은 기둥이 지면 슬래브 위에 계속 서 있던 오류 수정).
- 모든 부재가 완전 지지인 동안에는 아무 일도 없고 모델도 만들지 않습니다. 결과: 싱크홀 위 공장의 기초 4개만 파괴, 나머지는 서 있음(국부; 테스트·Chrome 18).

## 19. 지진 연동

층간변위 → 부재 변위 용량 → `drift` 파괴 → 엔진 재분배·낙하. 집약 모델 층 메커니즘 → 층 수직 부재 `story` 파괴(즉시 덩어리 제거가 아니라 엔진의 낙하·충돌). 정지한 잔해의 질량은 집약 모델 층 질량에 더해지고, 층이 무너진 곳에서 모델이 절단됩니다. 파편은 그 높이의 구조물 속도(1차 모드 형상)를 물려받습니다.
여진·반복 하중은 같은 경로(손상 지수 포락선 + 잔여 강도)로 누적됩니다.

## 20. 바람·압력파 연동

- **바람**: 외장 부품 피로(기존) → 탈락 결정 → `facade.ts`가 엔진에서 부재를 빼고(걸려 있던 보·벽에서 하중 제거) 정확한 질량의 파편으로 만듭니다(추가 밀기 없음, 이후 바람 항력이 파편에 작용). 구조 피로 → 가장 약한 층 메커니즘. 가장 약한 층은 **내력 부재가 파괴됐을 때만** 엔진의 현재 층 강도(집약 모델에 쓰는 것과 같은 부재별 기여)와 원래 층 질량으로 Phase 17 기준(역삼각형 층전단 대비 층 강도)을 다시 구합니다 — 외장만 떨어질 때는 다시 계산하지 않고, 전체 Phase 17 재해석도 하지 않습니다(원본 월드에서는 분석의 가장 약한 층과 같음 — 테스트). 지배 건전도가 지진·홍수·지반이면 그 해저드로 기록(Phase 22 원칙, 이번에 손상 끌어내림의 해저드도 지배 채널로 수정).
- **압력파**: Phase 24 압력파 모델은 다시 구현하지 않습니다. 외벽 면외 SDOF가 한계에 이르면 `overpressure` 파괴 → 엔진, 날아가는 벽은 **받은 충격량**의 운동량으로 떠남(테스트). 탈락한 외장 부품은 구조에서 빠지므로 압력파 하중을 **다시 받지 않습니다**(동체가 된 뒤에는 ForceLedger `blast`로 자유 물체로서만).

## 21. 홍수·토사 연동

- 홍수: 1층 수압(기존 손상 지수) → 층 메커니즘 `story`(해저드 flood) → 엔진 붕괴, 잔해 더미. **물 질량 보존은 바뀌지 않습니다**(테스트: 상대 오차 기준 유지). 무너진 건물의 발자국 장애물은 기존처럼 제거되며, 잔해 더미는 1 m 물 격자 장애물로 추가하지 않습니다(한계). 실내 침수 흐름은 계산하지 않습니다.
- 토사(Phase 22): 측방 토압·동압이 1층 수직 부재의 손상 지수를 올립니다(해저드 ground). 토사 퇴적과 잔해 더미는 별개 상태(도로 차단도 별도 집계).

## 22. 운석 연동

에너지 장부(Phase 23)는 그대로. 분출물 운동량 플럭스로 붕괴가 판정된 모듈형 건물은 엔진으로 무너지며(해저드 impact), 크레이터·분출물로 바뀐 지반과 운석 지반 충격이 지배하는 흔들림도 `impact`로 기록됩니다. 대기 압력파 몫(Phase 24)은 압력파 경로. 같은 에너지를 두 번 쓰지 않습니다.

## 23. 피해 원인 귀속

- 모든 엔진 입력은 `governingHazard(e, h, ctx)` 하나를 거칩니다: 운석 지반 충격·압력파가 지배하는 흔들림은 각각 impact/blast, 운석이 바꾼 지반은 impact.
- 기록: **직접 원인**(파괴 모드 — drift, axial, bending, shear, connection, support, impact, foundation, bearing, story, overpressure, facade) + **주 해저드**(연쇄 뿌리의 해저드) + **유발 부재·뿌리·깊이**. 2차 피해는 **타격 파편 → 출처 건물·부재 → 주 해저드**까지.
- 예: 지진으로 아파트 1층 기둥 drift 파괴 → 위층 support/impact 파괴 → 파편이 옆 차량 타격 → 차량 IMPACT 기록: hazard = earthquake, secondary = {striker, source = 아파트}.
- 쉬는 잔해가 나중에 층을 무너뜨리면 그 잔해 부재가 유발 부재, 원래 연쇄의 주 해저드 유지.
- 기록 수 제한: 건물당 손상 이벤트 60개(붕괴 순서 전체는 모델에 남아 CSV/JSON으로 내보냄). 층 메커니즘 부재·개구부는 FAILED 이벤트로 남기지 않고 순서에만 기록.

## 24. 시각적 파괴

- 부재는 **엔진 상태대로** 그립니다: 떨어진 부재는 정지한 곳으로 변위·압축(sy), 잔해 색조, 부서진 조각의 결정론적 기울기(시각 전용). 물리 엔진·잔해장·미세 입자가 가져간 것만 숨김.
- 잔해 더미: 계산된 발자국·질량·안식각 높이의 병합 메시(변화 시 재생성·해제).
- 먼지: 시각 전용, 양 선택(끔 / 1× / 2×). 섬광·과장 배율(운석 파편 크기 등 기존 옵션)은 렌더링만 바꾸며 **계산 결과를 바꾸지 않습니다**(시뮬레이션은 view store를 읽지 않음).

## 25. 건물 인스펙터

시뮬레이션 중 모듈형 건물 선택 시 "구조 상태" 섹션: 붕괴 분류, 서 있는 상부 비율, 파괴·손상 부재 수, 하중 경로·대체 경로, 연결(전체/파괴), 기초 지지, 잔여 용량, 지배 사용률, 원인별·주 해저드별 집계, **붕괴 순서**(시각·부재·원인·유발 부재), 질량/에너지/운동량 장부.
부재를 클릭하면(시뮬레이션 모드 부재 선택) 상태·손상·용량 계수·사용률 성분·용량·지지 경로·지반 지지·파괴 사슬·타격 파편·연결 목록.

## 26. 구조 시각화

부재 색: 기본 / **수요/용량** / 상태 / **붕괴 순서**. 선택 건물 오버레이: 하중 경로(연결별 전달량/용량 색), 파괴된 연결(×), 기초 지지 상실(주황→빨강), 낙하 블록(청록), 선택 부재(흰색). 잔해 상태색(움직임/정지), 잔해 더미, 먼지. 모두 `structureViz`(렌더 전용) 토글 — 오버레이 메뉴 "구조" 섹션.

## 28. GUI·창작 모드

- 편집기(건물 편집): 부재 선택 → 수요/용량, **하중 전달 연결 목록**(종류·지지 부재·전달 하중·용량), **부재 제거 미리보기**(시뮬레이션과 같은 붕괴 모델로 갑작스러운 제거의 대체 경로 검사 — 결과 분류·파괴 목록, 뷰포트 강조). 설계는 바뀌지 않습니다.

## 29. Blueprint 호환성

설계도(Phase 20 라이브러리)는 `BuildingDesign` 그대로이며 그래프는 거기서 유도됩니다. 공유 설계는 절대 변경되지 않고(그래프 캐시는 읽기 전용), 같은 설계의 여러 건물은 서로 독립(테스트). 놓인 곳의 지반·노출에 따라 결과가 달라지는 기존 원칙 유지.

## 30. 원본 월드 복원·결정론

- 시뮬레이션은 원본 문서를 복제해 실행하며, 종료 시 원본 월드 지문이 같습니다(테스트, Chrome 21).
- 결정론: 같은 조건 → 같은 붕괴 순서·잔해·파편 위치·이벤트(SHA-256 해시 비트 단위 일치, 초기화 후 재실행도 동일 — 테스트, Chrome 22). 엔진은 난수를 쓰지 않습니다(재료 산포는 기존 시드 기반).
- 결과는 객체 id에 의존하지 않습니다: id는 월드를 만들 때마다 무작위인데, Phase 24의 압력파 외벽 묶음 위상이 id에서 나와 같은 장면을 다시 만들면 벽이 다른 스텝에 파괴되고(원인 overpressure ↔ drift) 붕괴 결과가 달라졌습니다. 위상은 이제 seed·배치에서 나옵니다(테스트: 새 id로 두 번 만든 장면이 비트 동일, §33.5).
- 100동 이상: 1000동 장면의 초기화(원본 월드 복원)는 100 ms 미만(§33 `resetMs`), 같은 장면 6회 반복 실행에서 힙 평탄·Rapier 월드 0개 남음(§33).

## 31. 저장·불러오기

- 스키마 v7 유지(새 필드 없음). 구조 그래프는 설계에서 유도되는 값(저장 안 함), 붕괴 상태는 런타임 상태 → **설계와 런타임 상태 분리**. v1–v7 파일은 그대로 열리고 같은 결과(테스트: 저장 → 불러오기 → 같은 붕괴).
- **실행 중간 상태 저장은 지원하지 않습니다**(기존 Phase 21–24와 같음). 런타임 상태 목록(`runtimeStateManifest`)에 structuralGraph(유도)·collapse·fragments·rubble을 추가해 무엇이 저장되지 않는지 명시.

## 32. 렌더링 최적화

- 부재: 재료 외형별 InstancedMesh(장면 공유, 기존), 변위·색 덮어쓰기 행렬만 갱신(건물 rev 변화 시).
- 잔해 더미: 병합 메시 1개 — typed array로 직접 생성(평면 셰이딩, 법선 계산 없음), 더미별 색조 캐시, 변하는 동안 최대 100 ms마다 재생성(이전 것 dispose), 새 실행이면 초기화. 파편: 기존 InstancedMesh 경로.
- 상태 요약(HUD·인스펙터, 초당 10회): 해석기·붕괴 모델이 유지하는 파괴 카운터를 읽고 장부 계정을 직접 합산(매번 모든 기록·연결을 훑지 않음).
- 오버레이: 선택 건물만, 키(모델 rev·토글) 변화 시에만 지오메트리 재생성·해제.

## 37. 과학적 한계

- **축약된 부재·하중 경로 모델**입니다: 하중 분담은 Phase 17의 등분 근사, 부재 검사는 축·휨·전단·연결·지지력 성분. **비선형 FEA·강성 행렬 해석이 아닙니다**(처짐·모멘트 재분배·막 작용·현수 작용 없음).
- 상세 접합부(볼트 군·용접·철근 정착·패널 존), 철근 배근, 균열 전파, 비틀림, 국부 좌굴, 피로 균열은 계산하지 않습니다. 접합부 효율 η는 문서화된 판단값입니다.
- 낙하 블록은 회전하지 않고 연직으로만 떨어지며, 블록 자체의 압괴(crush-up)는 없습니다(아래층만 흡수). 수평 변위 탐색은 원래 박스 기준입니다.
- 잔해 더미의 형상은 근사(팽창 1.6, 안식각 37° 둔덕), 질량은 정확. 집계된 잔해는 개별 동체가 없습니다.
- 유리·창의 질량은 미세 입자(fines)로 외벽 발치에 놓이며, 보이는 유리 조각은 시각 전용입니다.
- 레거시(Phase 0–16) 건물은 부재 모델이 없어 기존 덩어리 붕괴를 쓰며, 파편 타격을 평가하지 않습니다.
- 잔해 더미는 1 m 물 격자 장애물이 아닙니다(홍수 흐름이 잔해를 돌아가지 않음). 실내 침수 흐름은 없습니다.
- 실행 중간 상태 저장은 지원하지 않습니다(설계·실험 설정만 저장).
- 화재·열에 의한 강도 저하, 열팽창은 없습니다(Phase 26–27, §38).
- **실제 건축물의 붕괴 위험도·안전성 판단·구조 설계·진단에 사용할 수 없습니다.** 결과는 근사 모델의 계산이며 실험·FEA 검증을 대신하지 않습니다.
- 물리 계산과 시각 효과를 구분합니다: 먼지·기울어진 조각·잔해 색조·과장 배율은 렌더링 전용이며 결과를 바꾸지 않습니다(§24).
