# Phase 21 — Dynamic Terrain Deformation Engine

시뮬레이션 중에 **지면이 움직이는** 엔진입니다. 사용자가 지정한 변위장(침하·융기·국부 함몰·분포 침하·능선형 융기·지정 변위장)이 시간에 따라 적용되고, 같은 스텝 안에서 물리 충돌체·물 바닥·오브젝트·건물 기초·도로·렌더링이 모두 새 지면을 봅니다. 월드 문서는 절대 바뀌지 않으며, 초기화하면 원래 지형이 정확히 돌아옵니다.

이 엔진은 **운동학적 입력(prescribed kinematic input)** 입니다. 지반이 *왜* 움직이는지(공동 붕괴, 사면 파괴, 액상화, 충돌)는 계산하지 않습니다. 그 원인 모델은 Phase 22(싱크홀·산사태)와 Phase 23(크레이터)이 같은 `DeformationSource` 계약으로 연결합니다(§28).

## 1. 기존 시스템 분석 (작업 전)

변형 엔진이 닿아야 하는 시스템과, 작업 전 각각이 지형을 어떻게 읽던지:

| 시스템 | 작업 전 상태 | 변형 엔진이 필요로 한 것 |
|---|---|---|
| 지형 데이터 (`TerrainData`, Phase 12) | 201×201 정점, 1 m 격자, `heights/ground/soil` 배열 + `revision`. 시뮬레이션은 문서 스냅샷의 배열을 **그대로 공유** | 시뮬레이션 전용 사본(문서와 분리) |
| `TerrainSampler` | 모든 시스템의 유일한 지형 읽기 경로, `sync()`는 `revision`이 바뀌면 전체 격자 4회 스캔(평탄·지표·지반·높이 범위) | 높이만 바뀐 경우의 싼 동기화 |
| 물리 (`RapierEngine`) | 시뮬레이션 시작 시 한 번 높이장 생성(평탄이면 무한 슬래브). Rapier 0.21에는 **부분 높이장 갱신 API가 없음** | 충돌체 교체 비용 측정, 접촉 안정성 |
| 물 (`WaterField`, Phase 14) | 셀 바닥 `bed`는 생성 시 한 번 계산, 이후 불변 | 바닥이 움직일 때 수심/질량 정책 |
| 오브젝트 | 고정 바디(건물·나무·가로등·표지판·담장)는 초기 자세에 고정, 동적 바디(차량·사람·잔해)는 Rapier가 접촉 처리 | 고정 바디의 지면 추종, 동적 바디의 깨우기·들어올리기 |
| 건물 기초 (Phase 17) | `foundationContact`: 원래 지형에서 접지율·정적 지지력 비 | 변위에 따른 접지·부등침하·지지력 변화 |
| 도로 (Phase 18) | `RoadRuntime`: 균열·침수·세굴 상태, 도로망 자체는 불변 | 단차·경사·통행 판정 |
| 자연 (Phase 19) | 레이어 합성 지형(기본 + 지형지물), 강·호수 초기 물 | 설계(지형지물) 보존, 물이 바닥과 함께 움직임 |
| 설계도·템플릿 (Phase 20) | 문서에서 캡처 | 런타임 변형이 절대 섞이지 않을 것 |
| 현상 엔진 (Phase 15) | 이벤트는 채널만 쓰고, 시스템이 반영. 시스템 파이프라인 순서 검증(`validatePipeline`) | 새 채널 `terrainDeformation`, 새 시스템의 순서 선언 |
| 피해 (Phase 13–16) | 해저드 `wind/earthquake/flood`, 잔존 강도 = 다른 해저드 피해의 **포락선(max)**, 상태 전이는 `MetricsSystem`이 한 번 기록 | 새 해저드 `ground`, 이중 계산 금지 |

### 설계: 데이터 흐름과 갱신 순서

```
월드 문서 (원본, 불변)             ── 시뮬레이션 시작 ──▶  스냅샷(불변, 초기화 대상)
                                                           │ runtimeTerrain(): 배열 복사
                                                           ▼
                               런타임 TerrainData (시뮬레이션 전용)  ─ 원본 사본 H₀ (엔진 생성 시)
TerrainDeformationEvent ──▶ env.deformation (DeformationChannel: 엔진 + 통계)
                                                           │ DeformationSystem (prePhysics, 첫 번째)
                                                           ▼
                                 변위장 W(t) = Σ wᵢ(x, z, t)   (선형 중첩)
                                 유효 지형 H(t) = H₀ + W(t)    (런타임 TerrainData에 제자리 기록)
                                                           │ 같은 스텝 안에서 원자적으로
   ┌──────────────────┬──────────────────┬─────────────────┼──────────────────┬────────────────┐
 sampler.syncHeights  Rapier 높이장 교체   물 바닥(bed) 갱신     고정 오브젝트·건물 기초   도로 상태       렌더(dirty 사각형)
 (모든 시스템 공통)    (전체 교체, 측정됨)  수심 보존 = 질량 정확   (지면 추종·기울기·β)     (단차·경사·통행)  (지형·도로·물 메시)
```

1. 변형 이벤트는 채널(`env.deformation`)만 씁니다(Phase 15 원칙). 오브젝트를 직접 건드리지 않습니다.
2. `DeformationSystem`은 prePhysics **맨 앞**에서 실행합니다(`reads: terrain`, `writes: terrain, water, poses, damage`; 파이프라인 검증 통과). 연속 변형은 6 스텝마다(10 Hz) — 물 솔버와 같은 스텝이고 그보다 먼저 — 적용하고, 새로 시작한 변형(즉시·첫 단계)은 시작 스텝에 바로 적용합니다(`engine.urgent`).
3. 적용은 원자적입니다: 높이 → 샘플러 → 충돌체 → 물 바닥 → 오브젝트·건물·도로. 그 스텝의 물리·물 솔버·피해 시스템은 모두 새 지형을 봅니다.
4. 스냅샷과 원본 사본은 절대 쓰지 않습니다 → 초기화 = 스냅샷에서 다시 빌드 = 원본 정확 복원(§19).

## 3. 런타임 변형 레이어

| 층 | 내용 | 쓰는 곳 |
|---|---|---|
| 원본 합성 지형 H₀ | `DeformationEngine.original` — 엔진 생성 시 런타임 높이의 Float32 사본 | 아무도 쓰지 않음 |
| 런타임 변형장 W | `engine.field` — 정점별 총 변위(m, + 위) | 엔진만 |
| 유효 지형 H | 런타임 `TerrainData.heights` = H₀ + W (변경 사각형에서만 기록) | 엔진만 |
| 이력 | `engine.history` — 갱신마다 (시각, max\|W\|, 순 체적 ΣW·A), 최대 4000개 | HUD·검증 |
| 원인(source) | `DeformationSource` 목록 — id, 현상(실험 인스턴스 id `p1`…), 종류, 모델 분류, 시작, 지속, 정점 사각형, `version()`, `sample()`, `support()`, `netVolume()` | 인스펙터·타임라인 |

- 엔진은 **첫 변형이 시작될 때** 만들어집니다. 변형이 없는 실행은 원본 사본도 만들지 않고 시스템도 비활성입니다(비용 0, §22 A/B).
- 시뮬레이션은 시작 시 `runtimeTerrain()`으로 스냅샷의 높이·지표·지반 배열을 복사해 자기 지형으로 씁니다. 문서·스냅샷과 배열을 공유하지 않습니다(테스트: `not.toBe(doc heights)`).
- 렌더러(`runtimeGround.ts`)는 시뮬레이션 모드에서 엔진이 있으면 런타임 지형을, 없으면 문서 지형을 그립니다. 초기화하면 엔진이 사라져 원래 지면이 그대로 그려집니다.

## 5. 변형 종류와 공간 형상

w(x, z, t) = A · S(x, z) · f(t − t₀) — 분리형 원천. S ∈ [0, 1], 반경 밖에서 **정확히 0**(컴팩트 지지).

| 종류 | A 부호 | S (t = 거리/반경) |
|---|---|---|
| 침하 subsidence | − | falloff: smooth ½(1 + cos πt) — 중심·가장자리 기울기 0(C¹) / linear 1 − t / steep 평탄 바닥(t ≤ ½) + cos 벽 |
| 융기 uplift | + | 위와 같음 |
| 국부 함몰 depression | − | 항상 steep(좁고 가파름) |
| 분포 침하 settlement | − | smooth × (1 + v·n(x, z)), n = 시드 값 노이즈 fBm(16 m 척도), ≥ 0으로 잘라 부호 역전 없음 |
| 능선형 융기 ridge | + | 축에 수직 방향 smooth(반폭 = radius) × 양 끝 smoothstep 테이퍼(길이의 15 %) |
| 지정 변위장 prescribed | 값 그대로 | 사용자 격자의 이선형 보간, 격자 밖 0 |

- **결정론**: 형상은 스펙과 시드만의 순수 함수. 같은 입력 → 비트 단위로 같은 장(테스트). 분포 침하는 시드가 다르면 다른 장.
- 싱크홀·산사태·운석 같은 이름의 가짜 모델은 만들지 않았습니다. 그 현상들은 계획 상태로 남고(`phenomena/definitions.ts`), 필요한 누락 모델(`missing.cavityCollapse`, `missing.craterFormation` …)과 재사용할 이 엔진(`reuse.deformationEngine`)이 명시됩니다.

## 6. 중첩 정책과 검증

- **선형 중첩**: 원천들의 기여를 더합니다(작은 변형률 가정에서 독립 원인의 연직 변위는 가산). 원천 사이 클램프 없음 — 대신 검증이 결과를 경고합니다. 순서 무관(테스트: A+B = B+A = A 단독 + B 단독).
- **검증**(`validateDeformation`, 실제 격자에서 계산):
  - 오류(실행 거부, 이유 표시, 값은 절대 몰래 고치지 않음): 최대 변위·반경·지속·단계·주기·능선 길이·지지력 감소 범위 밖, 지정 변위장 누락/크기/값 이상. zod 스키마도 같은 한계(`deformationSchema.ts`) → 저장 파일·명령의 잘못된 값은 불러올 때 버려지고 파일은 열립니다.
  - 경고(실행됨, 이유 표시): 45° 초과 경사(`steep`), 경사 3(71.6°) 초과(`verySteep` — 물 솔버 CFL 부분 스텝 증가·접촉 불안정), 10 m 초과(`large`), 월드 가장자리 걸침(`edge` — 월드 밖 지면은 y = 0 고정 경계라 잘림), 완전히 밖(`outside`).
  - 수치 요약: 예상 최대 |변위|, 최대 경사(°), 순 체적(m³)을 편집기에 표시.
- GUI 필드는 클램프하므로 범위 밖 값은 파일·명령으로만 들어오며, 그 경우 편집기에 `⚠` 이유가 뜨고 실행 목록에서 빠집니다(브라우저 검증 5번).

## 7. 시간 프로파일과 스케줄

| 프로파일 | f(τ), D = duration |
|---|---|
| instant | τ ≥ 0이면 1 (이벤트 길이 1/60 s) |
| linear | τ/D |
| smooth | smoothstep(τ/D) — 시작·끝에서 가속도 연속 |
| staged | ⌊n·τ/D⌋/n, τ ≥ D에서 1 (n 단계, 첫 단계는 τ = D/n) |
| cyclic | ½(1 − cos 2πτ/P), τ ≤ D; 이후 f(D) 유지 |

- 변형은 끝난 뒤 **유지**됩니다(반복 프로파일은 D 시점 값 유지).
- 시뮬레이션은 60 Hz 고정 스텝, 변형 갱신은 10 Hz(물 솔버와 같은 스텝). 원천은 `version()`(= 시간 계수)이 바뀐 경우에만 다시 샘플링 → 끝난 변형은 비용 0.
- **dt 독립성**: W는 시간의 함수이지 적분이 아니므로, 갱신 횟수가 달라도 같은 시각의 W는 같습니다(테스트: 2회 vs 100회 갱신, `advance(5)` vs `advance(0.1)`×50 — 높이·자세·피해 이벤트 동일).
- 실험 탭의 시작 방식(절대 시각 / 다른 현상 시작·종료 후)과 비교 실행(단독/함께)을 그대로 씁니다.

## 8. Rapier 충돌체 갱신

- Rapier 0.21에는 높이장 부분 갱신이 없어 **충돌체 전체 교체**(`physics.setTerrain(heightfieldDesc(H))`)를 합니다. 평탄 월드도 첫 변형부터 높이장을 씁니다.
- 측정(201×201): 갱신당 평균 **0.24–0.5 ms**(헤드리스), 0.45–1.1 ms(브라우저, 부하 25–33). 10 Hz에서 실시간 프레임 예산의 0.3 % 미만. 그래서 dirty 사각형 패치를 위해 높이장을 타일로 나누지 않았습니다(타일 경계에서 접촉 이음매가 생기는 위험이 더 큼).
- **충돌체 = 렌더 표면**: 같은 배열, 같은 대각선 분할. 테스트: 두 변형 후 약 420 지점(80 m × 80 m 격자)에서 하향 광선 거리와 샘플러 높이 차 < 1 mm, 렌더 메시 정점 = 런타임 높이(브라우저 검증 7번: 40,401 정점 최대 차 0).
- **접촉 안정성**: 융기 시 지면에 놓인(바닥이 지면 0.5 m 이내) 동적 바디는 같은 양만큼 함께 들어 올립니다 — 그렇지 않으면 새 지면이 바디 안에 생겨 튕겨 나갑니다(테스트: 1.5 m 융기 중 차량 최대 속도 < 3 m/s, 지면 위에 남음). 침하 시에는 아무것도 옮기지 않고 깨우기만 합니다 — 바디는 중력으로 떨어집니다(테스트: 1.5 m 침하 후 차량이 새 지면에 정지, 속도 < 0.2 m/s).
- 결정론: 갱신은 스텝 번호와 스펙에만 의존(테스트: 두 번 실행 동일).

## 9. 오브젝트–지면 상호작용 정책

| 오브젝트 | 정책 | 근거 |
|---|---|---|
| 차량·사람·잔해·쓰러진 나무 (동적) | **물리 접촉**: 깨우기, 융기 시 함께 들기 | Rapier가 접촉·마찰을 계산 |
| 건물 (고정) | **운동학적 지면 추종**(강체 기초 평면) + 부등침하 평가(§10) | 기초는 지면에 붙어 있음 |
| 가로등·표지판·담장·나무 (고정) | 3×3 평면 맞춤으로 침하 + 기울기 추종. 기울기가 한계를 넘으면 동적 바디로 전환 → 경사 따라 넘어짐 | 한계(판단값, 검증된 기준 아님): 가로등·표지판 15°, 담장 8°, 나무 30° |

## 10. 건물 기초 반응

강체 기초 근사입니다. 발자국(회전 반영) 아래 5×5 점에서 변위를 읽어 평면 w ≈ a + b·lx + c·lz를 맞춥니다(대칭 격자 → 닫힌 해).

| 양 | 정의 |
|---|---|
| 평균 침하 | a |
| 기울기 | atan \|∇평면\| — 강체 회전, 구조 손상 아님 |
| 각변위 β | 평면에서 벗어난 잔차의 인접 점 차 / 간격의 최대(Burland & Wroth 1974 정의) |
| 접지율 | 잔차 > −5 cm인 점의 비율(지면이 기초 아래로 5 cm 넘게 내려간 점은 지지 안 함) |
| 지지 계수 | 명시적 `supportLoss`의 발자국 평균(기본 1) |
| 지지력 이용률 | Phase 17 정적 지지력 비(원래 지면) / (접지율 × 지지 계수) |

- 손상 지수(β의 구간 선형): 1/500 → 0, 1/300 → 0.3, 1/150 → 0.6, 1/50 → 1. 한계는 Skempton & MacDonald(1956), Bjerrum(1963)의 경험값: 1/500 균열 없음 예상, 1/300 칸막이벽 첫 균열, 1/150 구조 손상. **1/50 이상 = 파괴는 외삽**이며 UI에 그렇게 표시됩니다.
- 상태: β ≥ 1/500 또는 접지 < 100 % → 응력, β ≥ 1/300 또는 최저 접지 < 75 % → 손상, β ≥ 1/150 또는 지지력 이용률 > 1 → 위험, β ≥ 1/50 → 파괴.
- 균일 침하와 강체 기울기만으로는 구조 손상을 주지 않습니다(설비·사용성은 모델 밖). 테스트: 넓은 평탄 침하 0.4 m 위 건물 → 침하 −0.4 m, β < 1/500, 접지 100 %, 손상 0.
- **지지력은 변위와 별개**입니다. 지면이 낮아졌다고 지지력을 줄이지 않습니다. 줄어드는 것은 접지율(형상)과 명시적 `supportLoss`뿐(테스트: 지지력 감소 50 % → 이용률 정확히 2배, 미지정 → 불변).
- 이벤트(건물당 한 번): 기울어짐(> 1/250, 정보), 균열(β ≥ 1/300), 로그(구조 손상·접지 상실·지지력 초과). 상태 전이(손상/위험/파괴)는 `MetricsSystem`이 `lastHazard = ground`, `lastCause = foundation`으로 한 번 기록합니다.
- **고친 버그 2개**: (1) 처음 구현은 위험·파괴를 직접도 기록해 상태 전이가 두 번 기록됐습니다(테스트가 발견, 직접 기록 제거). (2) 브라우저 검증 화면에서 발견: 바람이 0 m/s인데 지반 때문에 무너진 모듈형 건물이 "바람 피로"로 기록됐습니다. 구조 건강도는 채널별 최솟값인데, 모듈형 건물의 붕괴 경로가 항상 `hazard: 'wind'`를 썼기 때문입니다. 이제 건강도를 지배한 채널을 넘겨 지반이 지배하면 `ground / foundation`, 잔해는 기초 평면의 내리막 방향으로 떨어집니다. 회귀 테스트는 수정 전 코드에서 실패하고 수정 후 통과함을 확인했습니다.
- 정밀 지반공학 해석이 아닙니다(§26).

## 11. 도로 반응

- 도로 구간의 5 m 간격 표본에서: 인접 표본 상대 단차(최대값 유지), 현재/원래 최대 경사, 평균 침하.
- 균열 지수 = 단차 / 0.1 m (Phase 18 지반 파괴 훅과 같은 척도) → 균열 ≥ 0.05, 심각 ≥ 0.6.
- 경사 급변: 경사 ≥ 15 %(지방 도로 설계 최대 경사 수준)이고 원래보다 1 %p 이상 증가.
- **통행 불가**: 단차 ≥ 0.3 m 또는 (경사 ≥ 25 %이고 증가) — 판단값, 문서화. 한 번 끊기면 유지.
- **도로망은 절대 삭제·수정하지 않습니다.** 설계상 연결성은 그대로이고 통행 가능 여부만 런타임 상태입니다(테스트: 문서 도로 JSON 불변, 구간 수 동일). UI: 도로 패널 행(침하·단차 cm·경사 원래→현재·통행), 오버레이 색(끊김 보라, 경사 노랑), 타임라인 `roadCut`.

## 12. 홍수·물과의 결합

- **정책: 수심 보존**. 바닥 셀이 움직이면 그 셀의 물기둥이 함께 움직입니다(`h` 불변, `bed` = 새 모서리 높이의 가중 평균). 따라서 **물의 질량은 정확히 보존**되고(테스트: `applyBedChange` 단독 — 모든 수심 비트 동일, 총량 비트 동일), 수면은 바닥과 같이 오르내립니다. 그 뒤 물 솔버가 새 수면 기울기로 재분배합니다.
- 기록: 바닥과 함께 움직인 물 부피(`displacedVolume`), 물기둥이 받은 위치에너지 변화(`work` = ρ g h A Δz), 최대 상승/하강. HUD에 "물과 함께 이동한 체적" 표시.
- **에너지 한계(명시)**: 얕은 물 근사라 물의 연직 운동량·충격파가 없습니다. 바닥이 갑자기 움직이면(즉시 프로파일) 수면이 같이 계단식으로 움직이고 그 뒤 수평 흐름으로 풀립니다 — 실제의 충격·분출은 표현하지 못합니다.
- 결과(테스트·검증):
  - 호수(2.5 m 깊이) 아래 1 m 즉시 침하: 세이시(출렁임)가 생겨 진폭이 처음 40 s 0.86 m → 이후 80 s 0.18 m로 감쇠, 시간 평균 수면은 −0.41 m로 평평해짐(그릇 체적 / 호수 면적 예측 ≈ −0.40 m), 총량 상대 오차 < 1e-6.
  - 호수 아래 넓은 융기 0.5 m: 수면이 0.3 m 넘게 상승, 질량 보존.
  - 0.2 m 물이 덮인 월드에서 침하: 물이 새 그릇으로 모여 중심 수심 > 0.7 m, 외곽은 얕아짐, 수지 오차 < 1e-6.
  - 브라우저: 강·호수 월드에서 수지 상대 오차 4.3e-14.
- 시뮬레이션 중간의 물 상태 저장은 **변형된 지면에서는 지원하지 않음**(명시적 거부 + 이유 토스트, §20).

## 13. 강·호수

- 지형지물(강·호수 설계)은 문서에 그대로 남습니다. 변형은 런타임 지형에만 적용되므로 강의 경로·폭·깊이·호수 수면 설계는 바뀌지 않습니다(테스트·브라우저 검증 17번: `landscape` JSON 불변).
- 물은 §12 정책으로 바닥을 따라가고, 흐름은 물 솔버가 새 바닥에서 계산합니다(강을 가로지르는 융기 → 상류 수위 상승, 하류 감소는 솔버의 결과).

## 14. 지반 재료 확장 지점

`src/deformation/groundModel.ts` — `GroundResponseModel { id, soils, additionalSettlement(input), reference }`와 등록 함수. 건물 기초 반응이 발자국마다 이 모델을 조회해 평면 맞춤 침하에 더합니다. **이번 단계에는 등록된 모델이 없습니다**(테스트로 확인): 압밀·탄소성·액상화 침하에는 압축지수·선행압밀·탄성계수·지하수 같은 보정된 값이 필요한데 이 프로젝트의 일반 지반 등급(Phase 13)에는 그런 자료가 없고, 지어낸 계수는 정밀해 보이지만 근거 없는 수치를 만들기 때문입니다. 지반 종류는 기존 Phase 17 허용 지지력으로만 반영됩니다.

## 15. 다중 재해

- 새 해저드 `ground`가 `DamageEvent`·결과 패널(색 #ffd9a0)·비교 실행(`eventsByHazard.ground`)·타임라인에 들어갑니다.
- **이중 계산 금지**: 엔티티 상태는 채널별 수준의 최악값(`worst`), 구조 건강도는 채널별 최솟값, 잔존 강도는 다른 해저드 피해의 **포락선(max)** — 지반 피해가 포락선에 들어가지만 합산되지 않습니다(테스트). 상태 전이는 한 번만 기록(§10).
- 힘은 ForceLedger 경로를 그대로 씁니다: 지반 변형은 힘을 만들지 않고 자세·접촉을 바꾸며, 이후의 바람·지진·물 힘은 새 자세·새 지면에서 계산됩니다.
- 테스트: 지진 + 침하에서 지반 피해가 자기 해저드로 남음. 브라우저 검증 19번: 해저드 집합 = {ground, earthquake}(수정 전에는 잘못된 wind가 섞였음).

## 20. 저장 / 불러오기

- 저장 스키마는 **v7 그대로**입니다. 변형 설정은 실험 계획(인스턴스 spec)으로 저장되며, 스키마 검증으로 잘못된 인스턴스만 버리고 파일은 열립니다(테스트: 정상 1개 유지, 반경 1 m 인스턴스 제거, 시드·지지력 감소·능선 필드 보존). v1–v7 불러오기는 기존 마이그레이션 그대로(기존 테스트 통과).
- 파일에는 런타임 변형(변위장·변형된 높이)이 들어가지 않습니다 — 다시 실행하면 같은 설정·시드로 같은 변형이 재현됩니다(결정론).
- **실행 중간 상태**: 물 상태 파일(`*.water.json`)은 그 지형의 지문에만 맞습니다. 지면이 변형된 뒤에는 **명시적으로 지원하지 않음** — 저장을 거부하고 이유를 알립니다(검증 20번). 변형 자체의 중간 상태 저장도 지원하지 않습니다(재실행으로 재현).

## 21. 렌더링·성능 설계

- **dirty 사각형**: 엔진이 갱신마다 바뀐 정점 사각형을 돌려주고 최근 64개를 보관(`dirtySince(rev)`) — 지형 메시는 그 행들만 다시 쓰고 GPU에는 그 범위만 올립니다. 도로는 바뀐 높이에 닿는 청크만 다시 만들고(최대 5 Hz, 도로가 없으면 생략), 물 메시는 지형 `revision`이 바뀔 때 마른 정점 기준 높이를 다시 읽습니다.
- `TerrainSampler.syncHeights()`: 변형은 지표·지반을 바꾸지 않으므로 높이 범위만 한 번에 계산 — 0.95 → 0.08 ms.
- 엔진 갱신: 원천마다 두 버퍼 교대(할당 없음), 행 단위 루프 — 전 격자 원천 0.41 ms(정상 상태).
- **셰이더 예열**(`ShaderWarmup`): 평탄 월드는 평면을 그리므로 첫 변형 때 높이장 지형 재질·스커트·외곽선·주변 링·RGBA 오버레이 프로그램이 컴파일되며 ~100 ms 프레임 정지가 있었습니다. 시뮬레이션 장면이 뜰 때 4 프레임 동안 화면 밖 삼각형으로 미리 컴파일합니다. 효과: city-roads 최악 프레임 808 → 59 ms, multi-hazard 1081 → 54 ms(브라우저 벤치, 다른 수정 포함).

22. (Phase 20 잔여 B) 왼쪽 패널 6개 탭이 KO/EN 모두 잘리지 않음

검증 중 발견해 고친 것: 지반 붕괴의 바람 오귀속(§10), 프로브가 내부 이벤트 id를 원인으로 표시하던 것(→ 인스턴스 id), 지반 반응 섹션에 홍수 라벨이 잘못 쓰이던 것, 첫 변형의 셰이더 컴파일 정지(§21).

## 26. 과학적 한계

- 변위는 **입력**입니다. 지반이 왜·얼마나 움직이는지 예측하지 않습니다. 결과는 지정한 입력에 대한 반응이지 실제 사건의 예측이 아닙니다(모델 배지·가정 목록·경고에 명시).
- 높이장이므로 동굴·오버행·수직 벽 없음, 수평 변위 없음(연직만).
- 건물 기초는 강체 평면 근사 + 경험적 각변위 한계입니다. 기초 강성·지반-구조 상호작용·압밀 시간 효과·지하수가 없습니다. 1/50 이상의 파괴 판정은 외삽입니다.
- 쓰러짐·도로 통행 한계는 판단값입니다(문서화된 상수, 검증된 기준 아님).
- 물은 얕은 물 근사입니다 — 연직 운동량·충격·분출 없음, 갑작스런 바닥 이동은 수면의 계단 이동으로 나타납니다.
- 월드 밖 지면은 y = 0 고정 경계라 가장자리에 걸친 변형은 잘립니다(경고).

## 27. 알려진 제한사항

- 실행 중간 상태 저장(변형 진행 상태, 변형 지면 위의 물)은 지원하지 않습니다 — 설정 재실행으로 재현.
- 충돌체는 갱신마다 전체 교체(측정상 0.24–1.1 ms). 수십 개의 빠른 동시 변형이 매 스텝 바뀌는 경우는 10 Hz 제한으로 묶입니다.
- 첫 변형이 시작되는 프레임은 브라우저에서 한 번 길어질 수 있습니다(빈 월드 최악 291 ms, 부하 25–33). 두 번째부터는 없습니다.
- 1000동이 모두 움직이는 지면 위에 있으면 갱신당 반응 1.5 ms(헤드리스) / 6 ms(브라우저, 부하) — 실시간 FPS가 떨어질 수 있습니다.
- 모듈형 건물의 붕괴 귀속은 이번에 지반만 고쳤습니다. 홍수·지진 건강도가 지배할 때도 같은 "바람" 경로를 쓰던 기존 동작은 이번 범위 밖이라 그대로 두었습니다(관찰 사항, 보고서 참조).
- 지반 재료 응답 모델은 확장 지점만 있고 구현은 없습니다(§14).

## 28. Phase 22–23과의 연결

- `DeformationSource` 계약(`version`, `sample`, `support`, `netVolume`, `model`)이 연결 지점입니다. 싱크홀(Phase 22)은 공동 붕괴 모델이 시간에 따른 변위장과 지지력 감소를, 산사태(Phase 22)는 질량 보존 이동(`netVolume` = 0)을, 크레이터(Phase 23)는 충돌 역학이 만든 변위장을 같은 엔진에 넣으면 충돌체·물 바닥·건물·도로·렌더·인스펙터·저장 정책이 그대로 적용됩니다.
- 모델 분류(`physics` / `empirical`)와 근거(`reference`)를 원천마다 표시하도록 이미 데이터 모델에 들어 있습니다.
