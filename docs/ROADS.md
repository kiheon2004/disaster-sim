## 1. 기존 구조 분석 (작업 전)

| 부분 | Phase 17까지 |
|---|---|
| 도로 | `WorldObject`(`type: 'road'`): 비활성(바디·바람·손상 없음, 홍수만), `length × width` 직사각형, `lanes`, 지형에 드레이프한 React 메시(렌더링만), 배치 렌더링 대상 아님 |
| 홍수 | `floodFeatures`가 도로 직사각형을 1 m 물 격자에 포장 셀로 래스터화(아스팔트 침투·Manning·배수). **바닥 = 지형 높이 그대로** — 도로는 바닥을 바꾸지 않음 |
| 지형 | 201×201 정점 높이장 + 지표 종류 + 토질. Rapier 높이장·물 바닥·렌더러·배치·마찰(Phase 14 접촉 위치)의 **단일 원천** |
| 편집 | 원자적 `applyEdit`, 기록 = 오브젝트 + 지형 패치; Blueprint v1(오브젝트만); 스키마 v5 |
| 시설물 | 가로등·표지·벽(+울타리 프리셋) — 바람/지진/홍수 거동 있음 |

연결성·곡선·교차로·보도·포장 재료가 없고, 지형과 물 바닥에 아무 영향이 없었습니다.

### 결정

1. **도로망 = 새 문서 레이어** `doc.roads`(노드·구간·단면·블록 용도·underlay). 레거시 도로 오브젝트는 그대로 두고, **명시적 변환**만 제공(§20).
2. **도로를 지형 레이어에 굽기**(정지/고정 도로의 높이, 차도/보도의 지표 종류). 높이장이 계속 충돌체·물 바닥·렌더러·배치·마찰의 단일 원천이라, 도로가 “메시에서만 올라가는” 일이 구조적으로 불가능합니다. 도로가 덮은 정점의 원래 값은 `underlay`에 보관해 도로를 옮기거나 지우면 정확히 복원합니다.
3. **편집 1회 = 실행 취소 1단계**: 도로망 + 지형 패치 + 연결 오브젝트를 한 번에 커밋(기록 항목에 도로망 추가).
4. **형상은 파생값**(순수 함수, 구간/교차로별 캐시, 청크 단위 병합 메시, 바뀐 청크만 재생성).
5. **스키마 v6**(최상위 `roads`, 설계 테이블, 파생 `components` 미저장). v1–v5는 그대로 로드.

## 2. 데이터 모델

```ts
RoadNetwork { version: 1, nodes: Record<id, RoadNode>, segments: Record<id, RoadSegment>,
              zones: Record<blockId, ZoneType>, underlay: { idx, h, g }, next }
RoadNode    { id: 'n<k>', x, z, y: number | null }          // y = 고정 노면 높이(m) 또는 지형
RoadSegment { id: 's<k>', a, b, control: [x, z][], profile, condition? }   // condition = 원래 손상 0–1
RoadProfile { width, lanes, oneWay, material, sidewalk, sidewalkWidth, curbHeight,
              elevation: 'follow'|'graded'|'fixed', drainage: 'none'|'standard'|'enhanced', markings }
RoadLink    { segment, t (0–1), lateral (m, + = 진행 방향 오른쪽), yaw (도로 기준), policy }
```

* **교차로는 저장하지 않는 파생값**입니다(노드에 모인 구간에서 계산). 그래서 저장값과 형상이 어긋날 수 없습니다.
* **id는 결정론적**(`next` 카운터) — 같은 편집 순서는 같은 id를 만듭니다(테스트).
* **불변 값**: 모든 연산은 새 `RoadNetwork`를 돌려줍니다. 기록·시뮬레이션 스냅샷은 참조만 보관(복사 비용 0).
* **검증**(`structuralIssues`, 모든 편집 결과에 적용 — 실패하면 아무것도 바뀌지 않음): 없는 노드 참조, 자기 루프, 2 m 미만 구간. **경고**(`networkWarnings`, 허용·표시): 20° 미만 예각 교차, 차도 폭보다 작은 곡선 반경, 같은 두 노드를 잇는 중복 직선.
* **중복 노드 없음**: 끝점은 반경 3 m 안의 노드에 붙고(`SNAP_NODE`), 0.75 m 안의 새 노드는 기존 노드로 합칩니다(`MERGE_DIST`). 분할점이 끝에서 2 m보다 가까우면 그 끝 노드를 씁니다(짧은 조각 방지).
* 단면 값은 한계로 잘립니다(폭 2.5–30 m, 차로 1–8, 보도 0.8–6 m, 연석 0–0.3 m).

## 3. 그리기 도구 (도로 탭 = 도로 편집 모드)

| 모드 | 동작 |
|---|---|
| 그리기 | 클릭으로 점 추가(직선 구간 = 폴리라인), 더블클릭/Enter 완료, Backspace 마지막 점 취소, Esc 취소 |
| 곡선 | 클릭한 중간 점이 곡선 제어점(구간 하나) |
| 편집 | 도로 클릭 선택(Shift 추가/제외), 노드·제어점 핸들 드래그(놓을 때 1단계 커밋), 노드 클릭 선택, Delete 삭제 |
| 분할 / 삭제 | 클릭한 위치에서 분할 / 클릭한 도로 삭제 |
| 블록 | 블록 클릭 선택 → 용도 지정 → 채우기 |

* **연장**: 기존 도로 끝 노드에서 시작하면 그 노드에 이어집니다. **연결**: 도로 위에서 끝나면 그 도로를 나눠 T 교차로. **교차**: 기존 도로를 가로지르면 양쪽을 나눠 4갈래 교차로.
* **스냅 우선순위**: 노드(3 m) > 도로 위의 점(차도 폭 + 2 m) > 격자(선택) > 자유.
* **미리보기**(클릭 전): 새 도로의 양쪽 가장자리·중심선, 커서 표시(노드 노랑/도로 파랑), 생성될 교차로 위치(링), 라벨 — 길이, 경사(%), 양 끝 높이차, 연결 종류(노드/T 교차로), 생성될 교차로 수, 곡선 최소 반경. 만들 수 없는 입력은 빨간 선 + “만들 수 없음”.
* **입력 충돌 없음**: `editorStore.tool = 'road'` 하나가 뷰포트 입력을 소유(Phase 16 구조). 도로 모드에서는 V/P/B/L/A 도구 단축키가 동작하지 않고, Enter/Esc/Backspace/Delete는 도로 모드 처리기가 먼저 받습니다. 드래그 중 미리보기는 별도의 선 그룹이며 일괄 메시를 다시 만들지 않습니다.

## 4. 도로 형상

* **중심선**: 노드 a → 제어점 → 노드 b를 지나는 **centripetal Catmull–Rom**(α = 0.5)으로 보간 — 어떤 제어점 배치에서도 첨점·자기 교차가 생기지 않는 매개화(Yuksel, Schaefer & Keyser 2011). 양 끝은 대칭 가상점으로 접선을 맞춥니다. 1 m 간격 균일 재표본(지형·물 격자와 같은 해상도), 접선은 중앙 차분.
* **메시**(`mesh.ts`): 구간마다 트림(교차로) 사이의 횡단면 → 차도(좌·중·우 띠), 보도 윗면 + 연석 수직면, 차선(양방향: 노란 이중 중앙선, 차로 경계 점선 3 m/6 m, 가장자리 실선; 일방통행: 흰 점선), 교차로 면(부채꼴), 보도 모서리, 횡단보도 줄무늬.
* **뒤집힘·자기 교차 방지**: 곡선 안쪽 가장자리의 점이 진행 방향으로 뒤로 가면(반경 < 반폭) 이전 점에 고정 → 접힘 없음. 퇴화 삼각형(넓이 0)은 버리고, 아래를 향한 노면 삼각형은 감김 순서를 뒤집어 항상 위를 향하게 합니다.
* **검증(테스트)**: 위치·법선·UV가 모두 유한, 정점 수 = 3의 배수, 법선/색 개수 일치, 노면 법선 y > 0.2 — 직선·곡선·교차로·반경 6 m에 폭 12 m인 급곡선 포함.
* 높이: 정지/고정 도로는 고도 프로필 + 횡단 경사(§6), 지형 따라가기 도로는 굽힌 지형(연석 경사 램프를 피하려고 가장자리에서 35 % 안쪽을 표본). 지형 위 3 cm, 차선은 그 위 1.2 cm(+ polygonOffset).

## 5. 교차로

노드에 모인 도로를 각도순으로 정렬 → 이웃한 두 도로의 마주 보는 가장자리(차도, 보도 바깥선)의 교점이 모서리 → 각 도로를 모서리 너머까지 **트림**(교차로 +1 m, 굽은 길 +0.25 m) → 트림 끝 단면 + 모서리 점이 교차로 노면 다각형, 차도 모서리와 보도 바깥 모서리 사이가 보도 모서리. 횡단보도는 3갈래 이상 교차로의 트림 끝 바깥.

* 지원: T(3갈래), 4갈래, 다갈래(벤치에서 6갈래), 굽은 길(2갈래 각도 > ~10°; 거의 직선이면 생략).
* **경고만 하고 고치지 않음**: 20° 미만 예각(`acute`), 트림이 도로 길이의 절반을 넘음(`trimTooLong` — 트림을 L/2 − 0.5 m로 제한). 교차로 계산은 도로를 지우거나 옮기지 않습니다(테스트: 계산 전후 네트워크 동일).
* 정지/고정 도로가 모인 교차로는 노드 높이의 평면, 지형 따라가기 교차로는 지형을 따릅니다.

## 6. 높이 정책과 지형 정지

| 정책 | 노면 높이 |
|---|---|
| 지형 따라가기 | 지형 변경 없음(지표 종류만 도로로) |
| 정지 | 원래 지형 중심선의 **16 m 이동평균** + 양 끝 노드 높이로의 선형 보정 |
| 고정 | 양 끝 노드 높이(고정값 또는 지형) 사이 직선 |

* **횡단 경사(crown)**: 정지·고정 도로는 중심선에서 연석 쪽으로 포장별 경사(아스팔트 2 %, 콘크리트 1.5 %, 자갈 3 %, 흙 4 % — 통상 설계 범위 1.5–2.5 % 포장, 2–4 % 자갈, 3–5 % 흙)로 낮아집니다. 비가 거터(빗물받이가 있는 곳)로 흐릅니다.
* **보도**: 거터 높이 + 연석 높이(지형 따라가기 도로는 원래 지형 + 연석).
* **깎기/쌓기 비탈**: 도로 가장자리(보도 포함) 밖에서 원래 지형까지 **1:2**(수직 1 : 수평 2) 선형 연결, 최대 8 m 폭. 그 밖의 지형은 건드리지 않습니다.
* **굽기**(`bakeRegion`): 변경 사각형 안의 정점마다 도로 요구(차도 > 보도 > 비탈, 같은 순위는 가까운 쪽)를 계산 → 요구가 있으면 도로 값, 없으면 **원래 값**(underlay 또는 현재 지형). 높이는 1 cm로 양자화(float32 비교라 다시 굽기는 변화 0 — 테스트). 결과 지형 하나가 충돌체·물 바닥·렌더러·배치·마찰의 원천이라 **지형·충돌체·물 바닥이 항상 일치**합니다.
* **변경 사각형**(`dirtyRect`): 달라진 구간과 움직인 노드에 붙은 구간의 영향 범위 + 그 끝 노드의 교차로 영역(양쪽 버전). 이웃의 이웃은 포함하지 않습니다(이웃의 정지 프로필은 자기 노드에만 의존). 480구간 격자에서 노드 하나 이동 = 63×63 정점.
* **지형 편집과 동기화**(`sync.ts`): 브러시 획이 도로 아래를 바꾸면 그 변화량을 underlay(원래 지형)에 반영하고 영향받는 도로를 다시 굽습니다 — 언덕을 올리면 도로가 새 언덕에 맞춰 다시 정지됩니다. 지형 프리셋 적용 = 전체가 새 원래 지형 → 도로 전체 다시 굽기. 모두 실행 취소 1단계.
* 도로를 지우면 underlay가 원래 지형을 **비트 단위로 그대로** 복원합니다(테스트).

## 8. 보도와 시설물

* 보도·연석은 단면의 일부(양쪽/왼쪽/오른쪽/없음, 폭, 연석 높이) — 지형에 굽혀지고 메시로 그려집니다.
* 시설물은 **기존 오브젝트를 재사용**합니다: 가로등(`streetLight`), 교통 표지(`sign`), 신호등(`sign` 프리셋, 새 팔레트 항목), 가드레일(`wall` 프리셋, 새 팔레트 항목), 울타리(`wall` 울타리), 가로수(`tree`). 바람·지진·홍수 거동이 이미 있습니다.
* **자동 배치**(`infrastructureAlong`, Phase 16 배치 계획기 재사용 — 경사·충돌·월드 경계): 가로등·가로수는 보도의 연석 쪽(보도 없으면 도로 가장자리 0.8 m 밖), 양쪽은 반 간격 엇갈림, 가로등 팔은 도로 쪽. 가드레일은 차도/보도 가장자리, 울타리는 대지 경계(보도 바깥 + 0.5 m). 표지는 3갈래 이상 교차로로 들어오는 각 도로의 오른쪽에서 진입 차량을 향함, 신호등은 각 진입부 모서리.
* 배치된 시설물은 **일반 오브젝트**라 개별 선택·이동·삭제·속성 편집이 됩니다(도로 링크만 추가).
* **빗물받이**는 오브젝트가 아니라 도로 단면의 배수 등급에서 파생되는 시뮬레이션 요소입니다(§13). 등급은 도로마다 편집합니다.

## 9. 블록·용도·채우기

* **블록 검출**(`blocksOf`): 그리기가 모든 교차점에서 도로를 나누므로 도로망은 평면 그래프입니다. 각 방향 반변을 따라 노드에서 시계 방향 다음 도로로 돌면 모든 면을 한 번씩 돕니다. 양의 넓이(> 150 m²) 면 = 블록, 바깥 면(음의 넓이)과 좁은 틈은 제외 → **열린 도로망(나무 모양)은 블록이 없습니다**(테스트).
* 블록 id = 경계 구간 id들 → 무관한 도로 편집에는 용도가 유지되고, 경계 도로가 바뀌면 새 블록입니다(사라진 블록의 용도는 다음 지정 때 정리).
* 블록 모드: 모든 블록 윤곽을 용도 색으로 표시, 클릭 선택, 용도(주거·상업·공업·공원·혼합) 지정, 채우기(선택 / 용도 지정된 전체). 경제 시뮬레이션은 없습니다.
* **채우기**: 경계 도로마다 블록 안쪽 면을 따라 건물 행(§10); 공원은 지터 격자 나무(도로·블록 밖 제외).

## 10. 도로변 건물

`buildingsAlong` / `fillBlock`: 도로를 따라 걸어가며 용도별 프리셋을 가중 무작위로 고르고(시드), 층수를 범위에서 고른 뒤(높이 배율 0.5–2), **그 건물의 폭으로 다음 위치를 정합니다**(간격 = 폭 + 건물 간격).

* 방향: 정면(로컬 +z, 문이 있는 남측 외벽)이 도로를 향함.
* 후퇴: 보도 바깥선(보도 없으면 차도 가장자리)에서 정면까지 지정 거리.
* 충돌: 기존 오브젝트 + 같은 작업에서 이미 계획한 건물(Phase 16 `FootprintIndex`), 도로 차도·보도 위(`footprintOnRoad`), 교차로 원 영역 — 모두 건너뜀. 경사 한계(°) 초과 위치 건너뜀. 결과 토스트: 배치 수 · 건너뜀(경사 / 충돌·도로).
* 실제 Phase 17 **모듈형 건물**. 같은 프리셋·층수는 **설계 객체 하나를 공유**(메모리·저장 크기 — §20).
* 결정론: 같은 도로망·월드·시드 → 같은 결과(테스트), 다른 시드 → 다른 결과.

## 11. 동네 프리셋

주거 거리(2차로 120 m, 가로등·가로수·주택/아파트), 상업 거리(4차로 140 m, 가로등·오피스/아파트), 공업 블록(100×80 m 순환 도로 + 공장/창고 채우기), 공원 블록(80×80 m 순환 도로 + 나무 + 가로등). 위치 클릭, 방향(°)·시드 지정. 도로는 손으로 그린 것과 같이 기존 도로에 연결되고(스냅·교차), 결과는 모두 보통 도로·오브젝트라 이후 편집할 수 있습니다. 도로 + 오브젝트 전체가 실행 취소 1단계.

## 12. 도로 편집과 연결 오브젝트

편집: 노드/제어점 이동(드래그), 노드 고정 높이, 폭·재료·보도·높이 정책·배수 등 단면 변경(인스펙터/패널 — 여러 도로 동시), 분할, 합치기(노드에 같은 단면의 도로가 정확히 2개), 삭제(남는 노드 정리).

연결 정책(`links.ts`, 오브젝트별, 일괄 변경 가능):

| 정책 | 도로가 바뀌면 |
|---|---|
| 도로 따라 이동 | 링크(t, 횡거리, 상대 방향)로 새 도로 위치에 다시 놓고 새 지형에 재안착 |
| 월드 위치 유지 | 월드 변환 유지, 링크만 새 도로에서 다시 측정 |
| 연결 해제 | 첫 편집에서 링크를 버리고 그대로 둠 |

* 구간이 사라지면(분할·합치기) 이전 앵커에서 가장 가까운 새 도로(30 m 안)에 다시 붙고, 없으면 연결 해제 — **오브젝트를 지우거나 순간이동시키지 않습니다**(테스트: 분할·삭제 후 오브젝트 수 동일).
* 같은 원자적 편집 안에서: 도로망 검증 → 굽기 → 연결 오브젝트 정책 → 지면에 서 있던 오브젝트 재안착(변경 영역 근처만).

## 13. 홍수 연동

물 솔버는 바꾸지 않았습니다. 도로가 지형에 굽혀져 있으므로:

* **바닥 고도**: 셀 바닥 = 두 충돌체 삼각형 평균(Phase 14 정의) — 굽힌 도로·연석·비탈이 그대로 물 바닥입니다. **메시만 올리는 일이 없습니다.**
* **투수성·조도**: 셀 네 꼭짓점의 지표 종류 평균(포장 비율). 보도·차도는 포장, 흙·자갈길은 투수.
* **경사·연석**: 종단 경사와 횡단 경사(crown)가 물을 거터로 모으고, 15 cm 연석이 거터를 따라 물을 흐르게 합니다.
* **빗물받이(inlet)**: 배수 등급별 간격(표준 30 m, 강화 15 m)으로 양쪽 연석 0.3 m 안쪽에 배치, 각 0.015 m³/s(통상 연석 유입구 10–30 L/s). 1 m 격자에서 **하위 격자 흡수원**으로 근사: 유입구가 있는 셀의 배수율(m/s)에 `용량 / 셀 면적`을 더합니다. 솔버의 배수 단계가 셀에 있는 물로 제한하므로 **질량 보존**(예산 `drainage` 항에 포함, 예산 오차 = 반올림)이 유지됩니다(테스트: 오차 < 1e-6 상대, 배수량 ≤ 유입구 수 × 용량 × 시간).
* 전역 배수 설정(포장 셀 mm/h)은 Phase 14 그대로 — 유입구는 그 위에 더해집니다.
* **도로 상태**(`RoadSystem`, 20 Hz 순번 평가): 중심선(노면 중앙)과 양쪽 거터에서 5 m 간격 표본. 차도 어디든 ≥ 0.15 m = **침수**(연석이 거의 참), 노면 중앙 ≥ 0.3 m = **차량 통행 불가**(레거시 도로 오브젝트와 같은 기준), 유속 > 재료 세굴 임계 & 수심 > 5 cm = **세굴** 누적(Phase 14 식, 임계만 재료별). 로그·오버레이(연한/진한 파랑, 갈색)·실시간 인스펙터 섹션.

**1 m 격자 근사(명시)**: 연석(15 cm 단차)은 1 m 정점 사이의 경사로, 거터는 1 m 셀의 평균 높이로 표현됩니다 — 실제 거터 흐름 단면(수 cm 폭의 삼각 단면)은 해상하지 못하므로 거터 수심은 과소, 셀 평균 흐름은 정성적입니다. 유입구 용량은 셀 단위로 집중됩니다. 하수관망(관 용량·역류)은 없습니다.

## 14. 지진 연동

* **노면 균열 지표**: 구간 표본에서 국부 최대 지반 속도(PGV, 기존 `GroundMotionField` — 토질 증폭 포함)를 추적, 재료 임계값(원래 손상이 있으면 최대 50 % 낮춤)을 넘으면 균열 지수 = (PGV − 임계)/임계(0–1). ≥ 0.05 균열, ≥ 0.6 심한 손상(통행 불가). 임계값은 지진 후 포장 피해 관찰의 크기 정도(강성 슬래브가 연성 아스팔트보다 먼저, 비결합 자갈·흙은 거의 “균열”하지 않음)이며 검증된 취약도 곡선이 아닙니다.
* **시설물 전도**: 가로등·표지·벽·나무는 기존 오브젝트 거동(흔들림 전도·가속도 이탈) 그대로.
* **Phase 21 훅**: `RoadGroundFailure.offset(x, z, t)`(지반 변위 m) — 10 cm 차등 변위 = 균열 지수 1. 실제 심한 도로 피해의 주원인(액상화·측방 유동·단층 변위)이 들어올 자리이며, 지금은 비어 있습니다(Phase 13 `LiquefactionModel`과 같은 원칙).

## 15. 바람 연동

도로는 지형(정적 충돌체)의 일부라 바람에 움직이지 않습니다(테스트: 경사 정지 도로 위 차량이 바람 중 도로 위에 머묾). 시설물은 기존 `ForceLedger` → 손상 경로(가로등·표지판·벽·나무)를 그대로 씁니다.

## 16. 차량 배치

`vehiclesAlong`: 차로 중심(양방향은 오른쪽 통행: 진행 방향 오른쪽 차로는 a→b, 왼쪽은 b→a; 일방통행은 모두 a→b) 또는 갓길(연석 1.1 m 안쪽)에 도로 방향으로 정렬, 간격 ±20 % 지터(시드), 충돌 회피, 경사 한계 30°, 도로 링크. 테스트: 차로 중심 횡거리 ±1.75 m, 방향이 진행 방향과 일치.

## 17. 도로 인스펙터 (KO/EN)

길이, 폭·차로·일방통행, 포장, 높이 정책, 종단 경사, 횡단 경사, 최대 깎기/쌓기, 최소 곡선 반경, 연결(시작/끝 이웃 수), 배수, 빗물받이 수·용량, 마찰 계수, 투수성, 노면 상태, 연결 오브젝트 수, 경고 — 각 값에 **계산값 / 근사** 표시. 단면 편집 필드 + 삭제. 노드: 위치, 노면 높이(지형/고정 전환·입력), 연결 도로 수, 합치기. 시뮬레이션 중 오른쪽 패널: 도로망 요약(균열·심한 손상·침수·통행 불가·세굴)과 가장 심한 도로 목록.

## 18. 실행 취소 / 다시 실행

모든 도로 작업(그리기·이동·단면·분할·합치기·삭제·용도·채우기·시설물·차량·동네·붙여넣기·레거시 변환·지형 편집에 따른 다시 굽기)이 **원자적 1단계**입니다. 기록 항목 = { 오브젝트, 지형 패치(변경 사각형), 도로망 }. 도로망은 불변 값이라 참조 저장(비용 0), 지형은 사각형 패치만. 잘못된 결과는 적용 전에 예외 → 아무것도 바뀌지 않음(테스트). 브라우저: 8단계를 Ctrl+Z로 모두 되돌리면 지표가 원래 풀밭(합 0), Ctrl+Y로 모두 다시 하면 지문 동일.

## 19. Blueprint

* 도로 모드 Ctrl+C = 선택한 도로 + 그 도로에 연결된 오브젝트. 도로는 앵커 기준 상대 좌표·인덱스로 저장(id 없음), 오브젝트 링크는 Blueprint 안의 도로 인덱스로.
* 붙여넣기마다 **새 노드·구간 id**. **외부 연결 정책을 명시적으로 선택**: 연결(손으로 그린 것처럼 스냅·교차로 생성) / 분리(복사한 그대로, 기존 도로와 연결 안 함 — 교차하면 “연결하지 않은 교차 n곳” 경고). 붙여넣기 미리보기에 도로 윤곽 표시.
* 오브젝트 링크는 붙여넣은 도로에서 다시 측정(같은 위치). JSON 왕복 시 도로·링크 보존, 잘못된 구간(없는 노드 참조)은 제거.

## 20. 저장 / 불러오기 (스키마 v6)

```json
{ "schemaVersion": 6, ..., "roads": { "version": 1, "nodes": {...}, "segments": {...}, "zones": {...},
  "underlay": { "encoding": "b36-delta", "idx": "…", "h": "…", "g": "…" }, "next": 42 },
  "designs": { "d1": { ...BuildingDesign } },          // 2개 이상 오브젝트가 쓰는 모듈형 설계
  "objects": { "id": { ..., "building": { "$design": "d1" }, "roadLink": {...} } } }
```

* **underlay**: 정점 인덱스 차분·높이(cm)·지표 종류를 base-36 텍스트로.
* **설계 테이블 + 파생 `components` 미저장**(Phase 17 잔여 B): 로더는 Phase 8부터 항상 `components`를 다시 만들었으므로 저장본은 읽힌 적이 없습니다 → 빼도 무손실. 한 번만 쓰인 설계는 v5처럼 인라인.
* **마이그레이션**: v1–v5 → 빈 도로망, 지형·오브젝트 그대로(테스트). 레거시 도로 오브젝트는 **자동 변환하지 않습니다**.
* **레거시 변환**(도로 탭 버튼, 명시적): 안전한 변환만 — 같은 위치·폭·차로 수의 직선 구간(지형 따라가기, 보도 없음 → 모양과 지면이 그대로). 큰 도로부터 변환해 곁길이 T 교차로로 붙습니다. 월드 밖·너무 짧은 것은 오브젝트로 남김. 실행 취소 1단계.
* **참조 무결성**: 키와 id 일치, 노드 없는 구간·짧은/자기 루프 구간 제거, 구간 없는 노드 제거, 단면 값 클램프, 알 수 없는 용도 무시, `next` ≥ 최대 id + 1, 없는 구간을 가리키는 오브젝트 링크 제거. 구간이 제거된 파일은 underlay로 원래 지형을 복원한 뒤 남은 도로를 다시 굽습니다(지형과 도로망이 항상 일치). 보고: 제거된 노드/구간 수, underlay 손실 여부.
* **왕복 동일**: 저장 → 불러오기 → 저장 문자열이 같고, 도로망·지형 높이가 비트 단위로 같습니다(단위 테스트 + 브라우저 18번).

## 21. 원본 월드 보존

시뮬레이션은 문서 스냅샷에서 실행되고(도로망은 불변 값이라 참조), 도로 상태(균열·침수)는 `RoadRuntime`에만 있습니다. 실행 중 편집 잠금은 도로 작업에도 적용(“시뮬레이션 중에는 도로를 편집할 수 없습니다”). 테스트·브라우저(20번): 지진·홍수 실행 전후 도로망 JSON과 월드 지문 동일, 결정론(같은 입력 → 같은 도로 상태).

## 22. 렌더링 최적화

* **구간별 draw call 없음**: 50 m 청크(구간은 중점, 교차로는 노드 기준)마다 레이어 3개(노면·차선/횡단보도·보도/연석)를 병합한 메시. 정점 색, 재질 3개 공유. 60·220·480구간 모두 도로 draw call **48**(16청크 × 3).
* **캐시와 dirty 갱신**: 청크마다 조각 서명(노드 위치·제어점·단면·트림)과 조각 범위를 기억, 서명이 바뀌었거나 조각 범위 안의 지형 높이가 바뀐 청크만 다시 만듭니다(테스트: 노드 하나 이동 → 바뀐 청크만 새 지오메트리, 변화 없으면 0개). 중심선은 구간 객체 + 점 키로, 교차로·블록은 네트워크 객체로 캐시(WeakMap).
* **LOD**: 카메라에서 260 m 넘는 청크는 차선 레이어를 그리지 않음(서브픽셀 줄무늬).
* **편집 경로 분리**: 그리기·드래그 미리보기는 별도 선 그룹, 일괄 메시는 커밋 때만 갱신.
* 도로 메시는 레이캐스트 대상이 아님(객체 선택·지형 도구 방해 없음).

**A. 선택 반복 시 회당 ~3 KB 증가** — `scripts/probe-selection-heap.mjs`: 1,000오브젝트 장면에서 같은 오브젝트 선택/해제를 반복하며 GC 후 힙 스냅샷 두 장의 차이를 노드 종류별로 집계하고 새 노드의 유지 경로를 추적했습니다. 200회 동안 새로 남은 노드의 대부분이 **V8 JIT 코드**(InstructionStream·TrustedByteArray·Code·deopt 데이터, ~1.5 MB)와 **Blink 페인트/레이아웃 캐시**(PaintChunk·ClipCache 등)이고, 앱 JS 객체(Object/Array)는 회당 ~0.15 KB(인스펙터 DOM 요소의 최신 props 등 교체되는 값)입니다. 메시·지오메트리·리스너는 0. 1,200회까지 GC 후 힙: 회당 **6.45 → 1.02 → 1.00 → 0.23 KB**(0–200, 200–400, 400–800, 800–1,200회)로 수렴 → 엔진의 워밍업/캐시이며 누수가 아닙니다.

## 27. 과학적 한계

* **해상도**: 도로는 1 m 정점 격자에 굽혀집니다. 연석의 15 cm 단차는 1 m 경사로, 거터는 1 m 셀 평균으로 표현되어 거터 흐름 단면은 해상하지 못합니다(거터 수심 과소). 7 m 차도의 2 % crown은 정점마다 2 cm 단계입니다. 메시는 실제 단차를 그리지만 물리는 격자 값을 씁니다.
* **정지 모델**: 16 m 이동평균 + 선형 보정은 설계 종단(수직 곡선·최대 경사 규정)이 아니며 최대 경사를 강제하지 않습니다(인스펙터가 경사를 보여줌). 비탈은 1:2 고정(토질별 안정 경사 아님), 토공량 계산 없음. 교차로 면은 노드 높이의 평면(실제는 접속 경사면).
* **배수**: 빗물받이는 고정 용량 셀 흡수원이며 관로망(용량·역류·월류)·막힘이 없습니다. 노면 투수는 포장 재료의 대표 투수성.
* **포장 손상**: 균열은 PGV 대 재료 임계의 지표(크기 정도는 지진 후 포장 피해 관찰), 검증된 취약도 곡선이 아니고 노반·포장층·온도·교통 하중을 고려하지 않습니다. 실제 심한 피해의 주원인(액상화·측방 유동·단층·사면 붕괴)은 Phase 21 훅으로 남겨 두었습니다. 세굴은 Phase 14의 경험식(유속² 누적)에 재료 허용 유속만 바꾼 근사입니다.
* **교통**: 차량은 정적 배치이며 교통 흐름·대피 경로 계산은 없습니다(차량은 기존 물리·홍수 부유 거동).
* **도시 생성**: 용도는 건물 프리셋 선택 규칙일 뿐(경제·인구·용적률 없음), 대지 분할은 도로변 행 배치입니다.

## 28. 알려진 문제

* 서로 2 m 안에서 두 도로를 가로지르는 새 도로처럼 2 m 미만 조각이 생기는 그리기는 거부됩니다(토스트) — 교차점을 자동으로 합치지 않습니다.
* 도로 위 지형 브러시는 획 중에는 지형만 보이고, 획이 끝나면 도로가 새 지형에 다시 굽혀집니다.
* 정지 도로의 비탈은 이웃 도로의 비탈과 겹칠 때 가까운 도로가 이깁니다(순위·거리 규칙) — 매우 가까운 평행 도로 사이에 작은 턱이 생길 수 있습니다.
* 곡선 구간을 분할하면 제어점이 양쪽으로 나뉘어 곡선 모양이 조금 달라질 수 있습니다(위치는 유지).
* 시뮬레이션 FPS 측정은 같은 머신의 다른 작업 부하에 민감합니다(§23).
* 빗물받이는 오브젝트로 개별 이동할 수 없습니다(도로의 배수 등급으로 편집).

## 29. Phase 19+ 호환

* 도로망은 그래프(노드·구간·교차로·블록)라 경로 탐색(대피 경로, 차량 이동)과 교통 흐름 모델이 그대로 쓸 수 있습니다. 시뮬레이션의 `RoadRuntime`이 구간별 통행 가능 상태(균열·침수)를 제공합니다.
* Phase 20 Blueprint 라이브러리: 도로 포함 Blueprint 형식과 연결 정책이 준비되어 있습니다.
* Phase 21 지반 파괴: `RoadGroundFailure` 훅, 블록·건물의 `foundationContact`.
* 새 포장 재료 = `ROAD_MATERIAL_PROPS` 항목 + 지표 종류 하나.
